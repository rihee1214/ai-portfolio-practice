## 상세 계약과 변경 위치

소비: A의 원 항목/원 단위·배송묶음별 완료시각. 생산: 확정된 수량/시각/원인 이력, C~E가 사용하는 원 주문 수량의 점유·해제 공개 계약. 아직 없는 claim 모듈로 order가 역의존하지 않는다. order가 수량 보류를 소유하고 향후 claim이 공개 계약으로 호출하는 안을 착수 시 Astra가 순환/잠금 관점에서 확정한다. 이는 새 거래 경계 설계 게이트이며 미승인 중요 변경을 확정하지 않는다.

- 직접 확정은 현재 본인 회원 또는 별도 GuestAccessSession·CSRF·배송 완료 수량을 검사한다. 미배송/타인/이미 클레임 점유한 수량은 거부한다. 비회원에게 구매 승인 권한을 추가하지 않는다.
- 자동 확정은 대상 수량 배송 완료 시각+7일 이상. 신청은7일 미만이며 경계 동일시각에는 확정만 가능하다. 여러 배송 묶음을 부모 주문의 하나의 시간으로 처리하지 않는다. 시각 정밀도/Clock 경계도 저장 계약과 맞춘다.
- 같은 원인/키 재시도는 확정 효과1회. 클레임 보류/확정이 같은 수량을 잠그며 경합 한쪽만 성공한다. 반려/해제 후 자동 확정 재평가, 완료된 환불 수량은 확정 제외.
- 지속 job은 실제 producer→worker→Outbox로 수행한다. 재시작·lease 상실 후 중복 확정 금지. worker에 고객 세션을 요구하거나 브라우저 timer로 자동 확정을 대체하지 않는다.

B1은 A의 H02 배송 사실 계약을 사용하고 order→fulfillment/claim 역의존 없이 구현한다. 보류 상태를 A의 출고 판정과 같은 원단위/잠금 경계에 연결하는 작업도 B 범위다. B에서는 실제 공개 내부 보류 포트를 호출한 경합으로 검증하고, C/D/E에서는 실제 신청 API와 연결해 다시 검증한다. A의 원단위 선택 규칙을 B가 재정의하지 않는다.

H03의 기간 snapshot/버전과 기존 P08 주문 적용 정책을 B1에서 확정하기 전에는 과거 주문의7일 기준을 현재 전역 설정으로 대체하지 않는다. H06의 부모/하위 상태 집계 초안도 고정한다. 확정된 일부 수량만으로 부모 CLOSED를 만들지 않으며 CLOSED 이후 조회·허용된 재시도/대사의 경로와 기존 PAID 전용 포트의 영향을 명시한다. 교환은 E가 결정할 H05 완료/기한 기준을 전달받아 재평가하며 최초 배송 시각으로 무조건 즉시 확정하지 않는다.

## 독립 검토와 C 인계

독립 검토자는 아직 없는 claim을 무조건 false로 반환하는 방식으로 보류를 통과시키지 않았는지, 실제 공개 보류 포트로 경합했는지 확인한다. C/D에서 실제 신청과 연결하는 추가 검사는 별도 필수다. 모든 제약·동결 소스·보존/전체 결과가 없으면 C 진입 보류.

C에는 원 단위 점유/해제·확정 상태·기한·멱등키와 트랜잭션 경계를 인계한다. P10 리뷰 자격과 P11 정산 원장은 구현하지 않는다. 이 문장은 최초 계획 당시 변경/실행 증거가 없던 이력이다. 실제 변경·집중/전체 검증은 아래 기록을 따르며 독립 검토·사용자 학습 직접 확인은 별도 판정한다.

## 실제 구현 계약 — B1 및 승인된 §10

[지정 설계 계약](P09-B-design-review.md)의 §10이 앞의 승인 대기·LEGACY_UNSET 권고 이력보다 우선한다. 사용자 선택 원문은 “기존 배송 완료 시각부터 7일 적용. 이미 7일이 지난 주문은 즉시 자동 확정 대상이 됩니다.”다. decisionId는 `P09-B-H03-20261030-OPTION2`, 승인 날짜는 2026-10-30이다. 승인 시·분·초를 만들지 않았다. 실제 이행은 새 `d2_it_<32hex>`와 별도 미디어에서만 수행한다.

- `OrderConfirmations`의 `Unit(itemId,ordinal)`, `Command(key,expectedRevision,units)`, `Result(receiptId,units,confirmedAt,cause,revision)` 및 단위별 `View/Eligibility`가 공개 값 계약이다. `GET /api/orders/{number}/confirmations`, `POST /api/orders/{number}/confirm`은 후자의 세 필드만 받는다. 현재 회원 또는 별도 GAS의 소유권을 확인하고 CSRF를 요구하며 no-store로 반환한다. 새 HTTP 진입 두 경로를 기존 비회원 조회처럼 허용하되 실제 권한은 포트에서 다시 검사한다. GAS가 결제 승인 권한을 얻지 않는다.
- `OrderQueries.lockOwned`는 current account/session 또는 guestBuyer/GAS → 처음부터 order FOR UPDATE → 정렬 원단위 → 현재 권한/시각 재검사 순서다. SHARE→UPDATE 승격을 하지 않는다. 현재 권한을 검사한 다음 원 receipt를 먼저 반환하고, 새 요청에서만 revision/PAID/OPEN/배송 사실을 검사한다. 동일 원단위 집합과 revision은 배열순서에 무관하게 canonical hash를 사용한다.
- `OrderUnitHolds.acquire(orderId,holdId,causeId,kind,units)`, `release(orderId,holdId,causeId,outcome)`, `completeRefund(orderId,holdId,causeId,refundReference)`는 실제 저장하는 내부 포트다. caller 거래가 필수이며 C/D/E는 신청 권한을 먼저 확보해야 한다. REFUNDED는 확정에서 제외하는 단위 사실이며 실제 payment/재고/쿠폰 성공을 B가 구현했다고 하지 않는다.
