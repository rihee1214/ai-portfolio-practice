## 2026-11-09 정책 결정

기존 검토세션 `01a1a658-3fa7-7a70-aa14-96236ecf25eb`의 착수 설계 판단(턴 `01a1bd2e-b099-7992-b7bf-16ca37114b1f`)을 확인하고 사용자가 네 권장안을 모두 승인했다.

1. 현재 활성 회원이 열람 가능한 상품·후기·댓글·판매자 답글·상품 문의·답변을 신고한다. 비밀 문의·답변의 접수자는 작성자 또는 해당 판매자이다. 첨부는 부모 대상과 함께 지정한다. 후기 본문 세대가 바뀌면 새 대상이다. GAS·주문 문의·지원 사건은 제외한다.
2. 같은 회원·대상·세대의 열린 사건에는 근거를 추가한다. 다른 회원의 사건을 노출하지 않는다. 회원별 최근 24시간 신규 접수는 10건까지이며, 동일 요청 키·동일 내용은 원 결과를 반환하고 다른 내용은 충돌이다. 종결 후 새 근거는 같은 사건의 재개 요청으로 남긴다.
3. 조사에는 현재 CONTENT 권한과 해당 사건 배정이 모두 필요하다. 비밀 문의의 사유·원문·첨부에는 현재 SUPPORT 권한과 원 문의 배정도 필요하다. 미배정 큐는 최소 정보만 표시한다. 비밀 원문·바이너리는 복제하지 않는다.
4. 접수→조사 중→종결 전이를 감사한다. 담당자는 위반 확인·위반 미확인·확인 불가 중 하나와 사유를 남긴다. 담당자가 새 근거 또는 판단 오류를 확인하면 같은 사건을 재개하며 이전 판단은 보존한다. 신고자에게 본인 접수의 상태와 결과 요약을 제공한다. 실제 숨김 완료 표시는 D의 조치 ID·결과가 있어야 한다.

### 비밀 대상 설계 검토

기존 검토세션 `01a1a658-3fa7-7a70-aa14-96236ecf25eb`의 후속 설계 판단(턴 `01a1bd39-0bf9-7a83-a7e5-92e5b956a29a`)에서 다음 구현 방향을 수용했다. 설계 검토이며 제품 구현의 중간·최종 수용은 아직 진행 전이다.

- operations.api가 대상 확인 인터페이스를 소유하고 content가 구현한다. **신고를 접수할 자격**과 **조사자가 현재 원문을 열 자격**을 별도 연산으로 둔다. B에서 비밀 문의를 읽는 운영자가 그 권한만으로 신고를 접수할 수는 없다.

## C1/C2 연결

상품 접수의 신고자별 직렬화·24시간 한도·요청 영수증을 모든 대상이 공유한다. [ReportTargets](../../backend/src/main/java/com/example/marketplace/operations/api/ReportTargets.java)의 접수 판정과 현재 원문 조회를 [content 어댑터](../../backend/src/main/java/com/example/marketplace/content/infrastructure/ContentReportTargets.java)가 구현한다. 자식은 원 후기/문의 ID, 세대, 실제 자식 종류까지 일치해야 한다. 첨부는 각 근거가 접수 당시 지정한 불변 asset ID로 조회한다.

[조사 서비스](../../backend/src/main/java/com/example/marketplace/operations/infrastructure/ReportInvestigations.java)는 사건 행을 잠근 뒤 세션·권한을 다시 검사한다. 담당 배정/인수·조사 시작·종결·재개는 버전과 요청 키를 사용하며 상태 변경과 감사 행을 같은 트랜잭션에 저장한다. 신고자가 새 근거를 제출해도 종결 상태는 담당자가 재개할 때까지 유지된다. 신고자 요약에 내부 사유나 담당자 ID를 포함하지 않는다.

개발 선택 범위는 `reports`와 공통 Java/ArchUnit·프런트다. 새로운 공유 스키마 V112와 content·catalog·media·identity·B의 담당 계약을 소비하므로 최종 판정에는 무선택 Offline 전체와 기존 세션의 동일 소스 검토가 필요하다. 브라우저는 실제 신고→조사→종결→신고자 상태→재개, 키보드와 375/768/1440폭을 확인하는 데 사용한다.
