## 구현 진행 — 최신 사용자 승인

현재 요청은 E1~E4의 구현·새 격리 로컬 실행·별도 서브 에이전트 독립 검토·보완·미커밋 인계까지 승인했다. 아래 설계 당시의 구현 미승인·미착수 문장은 과거 기록이다. 제품 기능 확장·실제 외부 거래·공개 배포·커밋·다음 단계는 제외한다.

[진입 감사](../../.local-tools/p12-e-entry-1f822cf5-a70a-49e9-b5da-f9dc06931852/entry.json)에서 HEAD `dbaef2ddedfa7f2393e93bea6b648cf832c5cbf9`, 빈 index, P12-D 수용1063입력 불일치0을 확인했다. 기존 변경은 README/계획/P12-D의 커밋 후 기록, E 설계와 requirements의 승인된 AC16 변경이다. 해당 문서 원본 사본과 기존 증거34224파일 해시를 같은 경로에 보존했다. 첫 보존 해시 수집은 sandbox의 보호 파일 읽기 거부로 중단됐고, 읽기 전용 확장 실행으로 재수집했다. 준비 감사 오류1회이며 제품·업무 자동 검사 실패로 합산하지 않는다. 보호 파일을 변경하거나 접근 권한을 완화하지 않았다.

**완료 범위:** E1 실행 가능한 안내, E2 실제 흐름/안전한 화면·추적, E3 AC17/18의 사실에 근거한 사례, E4 위 최소 제약·근거 대조와 부족분 실행을 모두 갖추고 같은 최종 소스의 독립 영향/선택 적합성 검토·필수 잔여0이면 **P12-E 로컬·모의 범위**를 수용할 수 있다. AC16은 변경된 기준의 별도 현재 판정으로 기록한다. 이는 P12 전체 통합 마감, 실제 Toss/실송금, 공개 배포, 실기기·사용자 직접 학습 확인을 충족했다는 뜻이 아니다. 선택 실패/skip·필수 assertion/출처 누락은 해당 완료를 차단한다. 현재 이 보완은 문서/소스 독해에 따른 설계 판단만이며 실행 결과는 구현 담당과 부모의 후속 기록으로 연결한다. 커밋·푸시·외부 자원 생성·P13 이후는 승인 범위에 추가하지 않는다.

## 목적·범위·제외

독자가 프로젝트가 무엇을 하는지, 로컬에서 무엇을 준비하고 실행해야 하는지, 어떤 실제 사용자 결과와 자동 근거가 있는지, 어디까지 검증됐는지를 따라갈 수 있게 한다. 기존 증거를 재설명하되 기능을 추가하거나 새 시연 전용 제품을 만들지 않는다.

향후 구현 결과물은 다음 네 묶음이다. 구체적인 설명은 기존 문서를 우선 보완하고 README는 짧은 진입점으로 유지한다. 필요한 경우에만 `docs/portfolio/` 아래 가이드·사례·공개 가능한 이미지/manifest를 만든다. 이번 설계에서는 그 결과물을 작성하거나 이미지를 생성하지 않는다.

E1의 정보 구조는 README 상단의 현재 상태/현재 실행 진입점과 과거 진행 연표를 분리한다. 기존 P01/P02의 ‘로그인 없음’ 등 당시 설명은 역사로 표시하고 수용/실패 증거를 삭제하지 않는다. [로컬 개발 문서](../local-development.md)의 P01 기준 JAR/프로필·과거 검사 수·`-RunBrowser` 등 옵션은 향후 구현에서 현재 launcher와 인수 선언에 대조해 현행 안내 또는 역사로 구분한다. 과거 숫자를 일괄 최신화해 과거 실행 사실을 바꾸지 않는다. 현재 하네스의 Windows/PowerShell7·로컬 캐시 제약을 명시하며 Linux/macOS 지원을 추정하거나 OS 이식 작업을 추가하지 않는다.

최소 결과는 새 DB migration 완료, 화면/API/worker 준비 완료, 개별 로그인과 실제 구매자/판매자/운영자 핵심 명령의 UI→API→DB→후속 소비 확인이다. 정확한 시연과 assertion은 기존 등록된 업무 중 실행 모드가 허용하는 범위에서 선택하고 필요한 데이터 준비·모의 제공자를 구분한다. public-demo의 비회원503 등 가드는 유지하며 비회원 성공을 위해 완화하지 않는다. 다른 모드에서 검증한 기능은 해당 별도 근거로 표시한다. 기존 근거가 새 기준 전체를 충족하면 불필요한 재실행을 하지 않고 독립 검토에서 재사용 범위를 확인한다.

검사 등록과 소비 영향은 [하네스](../verification-harness.md)·`verification/required-tests.json` 및 브라우저 필수 목록을 따른다. 문서·서식/안전한 이미지 파생만 변경하면 정적 확인으로 해당 범위를 마감할 수 있다. runtime 예제의 실제 실행을 새로 주장하려면 명령/exit/result/보존 근거가 필요하다. 제품·테스트 실행 동작·설정·공통 fixture·하네스를 수정해야 한다면 문서 범위를 넘는 사실을 기록하고 영향표/승인 범위를 재판정한다. 인증·공통 금융·worker·공유 스키마·하네스 동작/영향 불명확 변경에는 새 무선택 전체가 필요하다.

P12의 여러 결과를 통합해 **마일스톤 전체 마감**을 주장하거나 배포 전에는 새 증거 경로의 무선택 `./verify.ps1 -Offline`과 외부 미검증 해소가 필요하다. 단순 E 문서 마감/로컬 커밋 때문에 전체를 관성적으로 재실행하지 않는다. 동일 유효 근거를 개발·독립에서 두 번 실행하지 않는다. `selected-passed/eligible=false`와 전체 통과를 구분하고, 실패/skip/필수 누락은 차단한다.

## 화면·포트폴리오 증거의 출처와 안전한 전달

각 화면은 원 source commit/manifest, 실행 ID·모드·도구/viewport, 실제 URL/행동, 업무 식별자 대응, 원 이미지 hash/경로, 연결 assertion, 촬영 시각과 제한을 가진다. 이전 스크린샷은 과거 소스로 표시하며 새 소스 화면으로 포장하지 않는다. 새 촬영은 향후 승인된 실행에서만 한다. 브라우저 가상 desktop/mobile은 실기기 검증이 아니다.

원 `.local-tools` raw는 비공개 보존 대상으로 두고 저장소·공개 포트폴리오에 통째로 올리지 않는다. 비밀·계정·연락처·주문 개인정보·내부 경로/토큰을 점검한 별도 파생물만 제공한다. 파생 manifest는 원 hash와 가림/자르기·가명 치환 범위를 기록한다. 원본을 덮어쓰거나 가림으로 상태/금액/assertion을 바꾸지 않는다. 공개 설명에서는 안전한 식별자 대응으로 UI→API→DB 연결을 유지하고 비공개 원결과를 외부 독자가 열 수 있다고 가정하지 않는다. 원자료 열람 가능자/로컬 경로와 공개 요약의 한계를 구분한다.

사례 서술은 문제→재현 조건→선택/대안→실제 변경→정상/거부/경계 assertion→실패/재검증→현재 한계 순서다. B/D의 수용 결과, 전체+선택 결합, 실제 시간 비용, 공지 원인 미확정 등 불리한 사실도 보존한다. 설계자의 설명 이해와 사용자 스스로 재현/설명했다는 학습 검증은 다르며 후자는 실제 관측 전까지 미확인이다.
