# P02-A1 회원 가입·이메일 확인 기반

2026-10-24 / 기준 0a7db1d / 상태: 구현·검증·독립 검토 반영 완료

## 승인·범위

검토 및 반영세션의 사용자 직접 메시지로 P02-A1 착수를 확인했다. 기존 P02 미착수 제한은 A1에 한해 갱신됐다. 공개 Java 계약과 가입·이메일 확인 서비스, SQL, 로컬 테스트 메일함을 구현한다. HTTP 가입/로그인·CSRF·세션·React 화면은 아직 제공하지 않으며 P02-A2/A3로 남긴다. 검토세션도 이 경계를 확인했다. 기존 서버·DB를 유지하고 신규 격리 DB에서만 SQL을 실행한다.

## 확정할 작은 계약

- identity.api의 register(email,password)는 userId만 반환한다. 비밀번호·토큰을 일반 응답/로그로 반환하지 않는다. verifyEmail(token)은 성공 또는 고정 오류 코드다.
- 이메일은 ASCII 주소의 앞뒤 공백 제거·Locale.ROOT 소문자화, 최대254자/로컬64자다. 잘못된 도메인·점·공백을 거부한다. provider별 점/plus 병합이나 국제 이메일은 이번 범위 밖이다. 정규화 주소는 DB UNIQUE로 경쟁을 막는다.
- 비밀번호는 Unicode 코드포인트12~128자, 공백·붙여넣기 허용, 전부 공백/잘못된 surrogate는 거부한다. 자르거나 정규화하지 않는다.
- Spring Security crypto의 Argon2id(메모리19MiB, iteration2, parallelism1, salt16/hash32)로 서비스 자체 거래 시작 전에 해시한다. 호출자가 이미 거래를 시작했다면 그 거래 밖까지 보장하지 않으며 무거운 해시는 호출 설계에서 고려한다. 로그인 starter/filter는 추가하지 않는다. 비용은 실제 호스트에서 측정하며 운영 부하 조정은 후속이다.
- 회원은 PENDING_EMAIL, BUYER 자격, auth_version0으로 생성한다. 확인 성공 시 ACTIVE로 변경한다. 자격은 상태를 우회하는 로그인 승인이 아니다.
- 토큰은 SecureRandom32바이트의 base64url, DB에는 SHA-256만 저장한다. 유효시간30분, expiresAt > now일 때만 사용 가능, 소비와 활성화를 같은 트랜잭션으로 수행한다. 만료·재사용·잘못된 토큰은 같은 오류다.
- 메일함은 명시적인 local-mailbox 프로필에서만 생성하는 메모리 테스트 어댑터다. HTTP·외부 SMTP 없음. 원문 토큰은 이 개발 도구에서만 읽는다. commit 전에 예약하고 commit 후 공개, rollback 시 제거한다. 최대1000개와 만료 제거를 둔다. 프로세스 재시작 시 메일은 사라지며 재발송·운영 전달 보장은 후속이다.
- 회원/자격/토큰은 하나의 트랜잭션이다. 메일 준비 실패는 전체 rollback, commit 후 공개는 실패 없는 메모리 상태 전환이다. 예외에는 입력/SQL 파라미터/원인 비밀값을 넣지 않는다.
- 전체 설계에 맞춰 REQUIRED로 호출자 거래에 참여한다. 바깥 거래가 있으면 반환된 userId도 아직 확정된 가입이 아니며 바깥 commit 이후 메일이 공개된다. 바깥 rollback은 가입 데이터와 메일 예약을 모두 취소한다.
- 생산 V1과 테스트 전용 V2는 변경하지 않는다. V3로 회원 테이블을 추가해 기존 C3/D2 이력 checksum을 유지한다. 초기 저장소는 marketplace schema를 사용한다.

## 실행 계획·파일 책임

1. domain 입력 규칙·application 해시/토큰 검사를 먼저 작성하고 실패를 확인한다. identity.api는 공개 계약/고정 오류, domain은 순수 규칙·저장소/메일 포트다.
2. infrastructure에 JDBC 저장소·Argon2 해시·로컬 메일함, application에 트랜잭션 유스케이스, V3에 제약을 구현한다. db + local-mailbox 구성에서만 서비스를 조립한다.
3. 기존 보호 초기화기와 동일 컨텍스트에 identity IT를 추가한다. 신규 UUID DB를 사용하며 기존8 JDBC·E4/E5 4검사도 회귀한다. 순차/동시 이메일 중복, 토큰 만료경계/동시 소비, 해시 비교/원문 미저장, 메일 실패 rollback·로그 미노출을 검증한다.
4. 검토 가능한 로컬 커밋·증거·잔여 DB·제한을 남기고 검토 및 반영세션에 인계한다. P02-A2·push는 하지 않는다.

## 코드 흐름과 작은 실습

`SignupOperations.register` → `SignupRules` 정규화/길이 검사 → `ArgonPasswordHasher` → `SignupService`의 REQUIRED 거래 → `JdbcIdentityStore`의 회원·자격·토큰 INSERT → `LocalTestMailbox.prepare` 예약 → commit 시 공개 순서다. `verifyEmail`은 원문을 해시해 조건부 UPDATE로 소비하며 계정 활성화와 함께 commit한다. 소비 UPDATE의 행 잠금과 조건 재평가 덕분에 동시 요청2개 중 하나만 성공한다. 메일함은 실제 메일 발송을 흉내 낸 로컬 도구이며 전달 보장 시스템이 아니다.

작은 실습: SignupRulesTest에서 비밀번호11/12자 경계와 한글·이모지 코드포인트를 비교한다. 서비스 실행 예시는 PostgresJdbcIT의 signupPersistsOnlyHashesAndBuyerThenVerificationActivates를 읽는다. 일반 로그에 토큰을 출력하지 말고 테스트 디버거에서 mailbox.messages()를 확인한다. 전체 통합 명령은 새 DB를 생성하므로 반복 때마다 잔여 DB가 추가된다. 사용자 직접 실습·이해는 미확인이다.

## 제한·검토 인계

현재 실행 차단 항목은 없다. HTTP 가입/메일함 endpoint·React·로그인·세션·CSRF·비밀번호 재설정·재발송·이메일 발송 rate limit은 미구현이다. 가입 서비스 성공을 사이트 가입 전체 완료로 표시하지 않는다. API 어댑터와 보안 정책은 P02-A2/A3에서 연결하며 이번에는 진행하지 않는다. local-mailbox 프로필 없이는 로컬 서비스 구성을 생성하지 않는다. 메모리 메일은 재시작 시 사라지고 재시도/내구성을 제공하지 않는다. 원문을 DB 토큰 테이블에 저장하는 대체 구현은 하지 않았다. production 메일 어댑터에는 별도 outbox/재처리 설계가 필요하다.

신규 SQL은 V3이며 marketplace schema를 전제로 한다. 타 schema·새 PC·다른 OS·실제 외부 메일·공개 배포·성능 부하와 프런트 재검증은 하지 않았다. 기존 P01 health/API 회귀는124개에 포함된다. 대상 커밋과 이 기록을 검토 및 반영세션에 전달하고 최종 검토를 기다린다. 원격 push는 하지 않는다.

## 최종 검토 반영·완료 기록

구현 커밋은 `f288f8d`다. [지정 세션의 최종 검토](P02-A1-review.md)와 [독립 집계/보존 요약](evidence/P02-A1-independent-summary.json)을 확인했다. R1 REQUIRED/R2 ASCII 수정 후 독립124+21이 통과했고 남은 필수 수정 결함은 없다. 제품 코드를 더 변경하지 않고 최종 문서 상태와 검토 링크를 반영한다.

검토가 명시한 한계도 유지한다. 메모리 메일은 commit 직후 프로세스 종료나 재시작에 대한 내구성이 없으며 미확인 계정의 재발송 경로는 아직 없다. 토큰 시간은 애플리케이션 Clock 기준이고 장시간 lock 대기·시간 변경을 시험하지 않았다. 일반 로그 검사는 현재 기본 로깅과 합성 입력의 실행 범위이며 임의 DEBUG 설정의 모든 비밀값 노출을 막는 보장은 아니다. 후속 HTTP/운영 연결 전에 해당 계약을 다시 검토해야 한다. 현재 A1 로컬 서비스 범위의 차단 항목은 없다.

최종 문서 커밋에는 이 완료 기록·현행 상태·검토 문서/요약만 포함한다. 기존 서버·DB·신규 검증 DB5개를 보존하며 P02-A2·원격 push는 수행하지 않는다.
