# P04-B 독립 검토

2026-10-24 / 기준 eaba02d / 계약 사전 검토. 구현 완료 및 실행 검증 판정 전.

## 승인과 범위

개발세션의 최신 실제 사용자 메시지에서 P04-B 진행·새 격리 DB 검증·기존 검토세션 독립 검토 요청을 직접 확인했다. 이전 P04-A 마감 시점의 P04-B 보류 이후 내려진 요청이다. 옵션 조합·기본 SKU·원 단위 가격·SKU 판매 상태를 검토하며 P04-C 이후는 진행하지 않는다. 기존 서버와 기존·신규 검증 DB를 보존한다. 이 검토는 검토 문서와 독립 증거만 변경하며 제품 코드와 개발 검사 파일은 개발세션이 소유한다.

## 계약 사전 검토

설계의 SKU 코드 고유·상품 내 옵션 조합 고유·음수 금액 금지 및 작업 계획 P04-B 범위와 일치한다. 기본 SKU 자동 생성, 기존 상품 보충, 옵션 정규화, SKU별 낙관 버전, 공개 상품 자격 필터를 명시했다. 다음 항목은 구현과 검증에서 확인할 조건이며 현재 발견된 구현 결함을 뜻하지 않는다.

1. 정수 가격 계약은 HTTP JSON의 소수·숫자 문자열·null·boolean·범위 초과도 엄격히 거부해야 한다. 기본 역직렬화의 소수 절삭이나 타입 강제 변환으로 잘못된 가격을 저장하지 않는지 확인한다.
2. 빈 옵션 POST와 최초 옵션 생성/기본 SKU 활성화의 경합에서도 기본 SKU 정확히 1개 및 옵션 존재 시 기본 SKU 비활성을 유지한다. 정규화 후 이름 중복, 순서/NFC/공백이 다른 동일 조합, SKU 100개 한계의 동시 생성과 실패 롤백을 확인한다.
3. 수정 요청의 productId/skuId 소속을 함께 확인한다. 읽기·쓰기 타인404, CSRF, 계정 상태 변경 중 잠금 대기, 보관과 SKU 수정 경합을 확인한다. 상품 잠금을 모든 SKU 쓰기가 공유해 기본 SKU 정책과 개수 제한을 직렬화하는지 확인한다.
4. 공개 목록의 상품 자격과 SKU active 판정은 같은 스냅샷이어야 한다. 비공개404와 공개 상품의 빈 SKU 목록을 구별하고 안정된 페이지 정렬·hasMore를 확인한다.
5. 기존 상품 보충은 새 격리 DB를 V14까지 구성하고 상품을 넣은 후 V15로 올리는 검사로 검증해야 한다. 빈 DB 전체 마이그레이션 성공만으로 기존 상품 보충을 검증했다고 표시하지 않는다. 상품 생성과 기본 SKU 저장의 원자성도 확인한다.
6. 옵션 SKU를 전부 중지해도 기본 SKU를 다시 활성화할 수 없고 조합 수정/삭제도 제공하지 않는다는 제한을 화면에 안내한다. 영구적인 옵션 모드 전환이므로 최초 생성 시 영향을 알려야 한다.

## 문서 정합성 및 남은 확인

작업 계획에는 아직 P04-A 마감 당시의 “P04-B 이후는 진행하지 않는다” 문장이 남아 있다. 개발세션은 P04-B 작업 상태와 최종 결과를 갱신할 때 이 문장을 최신 범위인 P04-C 이후 미진행과 구분해 정리해야 한다. 본 검토는 해당 개발 소유 문서를 수정하지 않는다.

현재는 계약 사전 검토이며 구현 통과·전체 완료 판정은 하지 않는다. 개발세션 최종 실행 종료 후 독립 정적 검토 및 새 격리 DB/브라우저 검증을 수행하고 결과·차단 항목을 갱신한다. 아직 독립 실행하지 않았다.

## 구현 중간 정적 검토

Skus/JdbcSkus/SkuController, V15, JdbcProducts의 기본 SKU 생성, CatalogStore/Skus/SkuPanel과 관련 HTTP·동시성·브라우저 검사 소스를 직접 대조했다. 현재 읽은 구현에서 확정된 필수 수정 결함은 발견하지 않았다. 최종 실행 전 판정이며 독립 통과를 의미하지 않는다.

- HTTP 입력은 JsonNode의 정수·long 변환 가능 여부와 boolean 형식을 명시적으로 검사한다. 서비스 가격 범위 검사와 DB CHECK도 존재한다.
- 회원→매대→상품 잠금 이후 보관 상태를 재검사하며, SKU 조회에서 product_id와 id를 함께 제한한다. 상품 잠금 아래 버전 비교·개수 확인·기본 SKU 비활성·옵션 삽입을 수행한다. 예외 시 동일 트랜잭션을 롤백한다.
- 공개 SKU는 기존 PUBLIC 조건과 LATERAL SKU 조회를 한 SQL로 수행한다. 공개 상품의 활성 SKU가 없는 경우와 상품 자체가 공개 불가인 경우를 구분한다.
- V14 데이터 구성 후 V15 보충 및 재실행, 생성 실패의 상품 롤백, 첫 옵션 생성 실패의 기본 SKU 롤백, 실제 잠금 대기 뒤 상태 변화 검사 소스가 존재한다. 검사 결과는 아직 독립 실행하지 않았다.
- 화면에는 기본 SKU 복귀 불가·조합 변경 불가 안내와 등록 확인이 추가돼 있다. 상품별 컴포넌트 교체와 CatalogStore의 중단/세대 확인으로 늦은 요청 결과를 폐기한다.

추가 확인 요청: NFC 동등 조합과 옵션 문자열 길이/제어문자 경계는 정규화 코드가 있지만 현재 읽은 신규 검사에는 직접적인 단언이 보이지 않는다. 실행 증거에서 검증했다고 주장하려면 해당 검사를 보충하거나 미검증으로 구분한다. 공개 SKU의 페이지 선택은 내부 ORDER BY로 정해지지만 최종 응답 순서도 계약으로 고정하려면 바깥 SELECT에 ORDER BY k.id를 명시하는 것이 좋다. 현재 실행 재현 결함으로 분류하지 않는다.
