조사일: 2026-10-21 (Asia/Seoul). 기존 조사 기록을 보존하고 같은 날짜의 재조사 결과를 9절, Docker 방침 반영과 현재 준비 기준을 10절에 추가했다.  
기준: [P01-A](P01-A.md), [전체 설계](../shop-design.md), [ADR-001](../decisions/ADR-001-java-spring-react.md), [ADR-002](../decisions/ADR-002-docker-postgresql.md), [구현 계획](../implementation-plan.md)

**상태: 완료 — 설치 전 조사·기록 범위. 이후 B1~B3 구현·검증 완료, Docker DB 구성은 미착수.**

설치 전 조사에서 Java·JAVA_HOME은 일치했고 JDK의 메이저 버전은 Boot의 요구 범위에 들어갔다. Maven 명령은 PATH에서 발견되지 않았으며, 당시 기본 Node 20.12.1은 선택한 프런트 도구의 조건에 미달했다. Docker·WSL·서비스 조회·로컬 DB 포트 접근은 제한된 세션에서 거부됐고, 확인한 다운로드 호스트 모두 DNS 조회에 실패했다. 공식 웹 문서·일부 릴리스 소스는 별도 웹 조회 도구로 확인할 수 있었다.

2~9절의 버전은 **당시 설치 목표 또는 검증 후보**이며 다운로드·접근 실패는 실제 조사 이력이다. 이후 [P01-B1](P01-B1.md)·[P01-B2](P01-B2.md)·[P01-B3](P01-B3.md)에서 도구와 앱을 준비·검증했다. 현재 다음 구현은 P01-B4다. 다운로드 출처·프로젝트 경로·DB 이미지와 볼륨은 10절을 따르며, 과거 Windows PostgreSQL 설치 안내를 현재 준비 지시로 사용하지 않는다.

## 1. 범위와 완료 판단

설치 전 재조사에서 직접 확인한 범위는 9절이다. 2~8절은 그 작업 시작 시 이미 존재하던 조사 이력이며, 10절은 이후 Docker 방침에 맞춘 문서 검토다. 각 절의 명령을 이번에 모두 다시 실행했다는 뜻은 아니다.

G01·G07·G10 및 AC16의 실행 준비에 연결된다. Java·React·PostgreSQL 기술 선택과 F01~F18·AC01~AC20, MSA 목표는 유지한다.

수행 범위는 문서·파일 확인, 도구 버전·경로와 제한된 환경 변수 조회, 읽기 전용 Docker/WSL 상태 확인, localhost 기본 DB 포트 연결 가능성 검사, 공식 지원 조건·릴리스·소스 메타데이터 조회다. 설치·생성기 실행·패키지 캐시 준비·서비스 시작·컨테이너 실행·시스템/PATH 변경·Git 초기화·앱/설정/SQL/테스트 작성은 하지 않았다.

조사 완료는 확인 가능한 사실과 실패·미검증 항목을 기록하고 후속 검증에 배정했다는 뜻이다. 환경이 준비됐거나 서비스 완료 기준을 통과했다는 뜻이 아니다.

## 5. 최초 다운로드와 DB 접근 조사 이력

최초 조사 당시 셸에서 다음 URL을 **HEAD 요청·8초 제한·최대 4회 리다이렉트**로 확인했다. 파일을 저장하지 않았다. 일곱 호스트 모두 HTTP 응답 전에 이름 조회가 실패했으므로 해당 파일의 존재·체크섬·최종 CDN 접근까지 확인한 것으로 볼 수 없다. 이 표는 요청한 주소를 보존하며 현재 다운로드 안내는 10절과 B1·B2 기록을 따른다.

## 9. 롤백 범위 확인 후 재조사

2026-10-21 사용자는 롤백 대상을 프로젝트 설정으로 명확히 했다. 재조사 시작 시 숨김 파일을 포함한 프로젝트 목록에는 Markdown 문서 9개만 있었고 앱·빌드·DB·Git 설정은 없었다. 되돌릴 프로젝트 설정은 없으며 시스템에 설치된 Java·Node·Docker는 제거하거나 변경하지 않았다.

이 재조사에서는 P01-A의 최초 조사·문서 개정 기록을 보존 대상으로 삼았다. 당시 비교에 사용한 P01-A SHA-256은 `E2DF9970E7668855B603567FE70EEAA93B7CA4A7CBF59DDD7BB26D5756144C5C`였고 변경 범위는 P01-A2·구현 계획·요구사항·README 네 문서였다. 이 값과 범위는 해당 재조사의 이력이며 이후 문서 개정에도 같은 해시를 유지해야 한다는 규칙은 아니다.

공식 웹 자료도 재조회했다. [Boot 4.1.1 요구 조건](https://docs.spring.io/spring-boot/system-requirements.html)은 Java 17~26·Maven 3.6.3 이상이며 현재 Java의 메이저 버전은 범위 안이다. [Vite 안내](https://vite.dev/guide/)의 Node 하한과 현재 Node는 맞지 않는다. 이 대화의 앞선 읽기 전용 조사에서 Flyway 공식 PostgreSQL 문서 접근에 성공했다. [공식 문서](https://documentation.red-gate.com/flyway/reference/database-driver-reference/postgresql-database)는 검증 버전에 18을 명시하고 별도 `flyway-database-postgresql` 모듈이 필요하다고 안내한다. 3절의 접근 실패는 기존 조사 이력으로 남기며, 문서 접근 성공과 실제 마이그레이션 성공을 구분한다.

### 해당 재조사에서 미검증한 항목과 당시 다음 작업

설치, 의존성 다운로드·해석, Java 컴파일·테스트·기동, 프런트 타입·린트·빌드·브라우저 검사, PostgreSQL 연결·Flyway 이행은 모두 미실행이다. 이번 조사로 통과한 앱 테스트는 없다. WSL·서비스·브라우저 파일 정보 등 이번에 재실행하지 않은 값은 기존 이력이다. 사용자 직접 이해·수정·확인 결과도 미확인이다.

### DB 이미지와 경로를 기록하는 기준

2026-10-21 [PostgreSQL 공식 이미지 안내](https://hub.docker.com/_/postgres)에서 `18.6` 태그를 확인했다. 이는 웹의 태그 안내 확인이며 이 PC의 다운로드 성공을 뜻하지 않는다. P01-C1에서 실제 레지스트리 접근·플랫폼·pull 결과와 digest를 기록한다. `latest` 대신 버전 태그를 명시하고, 태그가 가리키는 이미지가 바뀔 수 있으므로 받은 이미지의 digest도 구분한다. [Docker 이미지 다운로드와 digest](https://docs.docker.com/reference/cli/docker/image/pull/)

- **원격 이미지 식별자:** `docker.io/library/postgres:18.6`. 웹 안내 주소·Windows 설치 파일·PC 폴더 경로와 구분한다.
- **로컬 이미지 저장:** Docker 엔진이 관리한다. `C:\Program Files\PostgreSQL`이나 `.local-tools`를 DB 서버 설치 경로로 지정하지 않는다. Docker Desktop 내부의 실제 저장 위치는 이 문서에서 추정·고정하지 않는다.
- **DB 데이터 볼륨:** 이미지와 별개로 관리한다. PostgreSQL 18 공식 이미지의 기본 `PGDATA`는 `/var/lib/postgresql/18/docker`, 볼륨 마운트 대상은 `/var/lib/postgresql`이다. 이는 컨테이너 내부 경로이며 Windows 다운로드 경로가 아니다. [공식 이미지의 PGDATA 안내](https://hub.docker.com/_/postgres)
- **접속 경로:** 호스트에서 실행하는 Spring Boot는 로컬에 공개한 DB 포트로 연결한다. 정확한 포트·DB명·계정은 P01-C1에서 정하고 P01-C2에서 JDBC 연결을 검증한다. 컨테이너 내부 psql 확인만으로 호스트 API의 연결까지 통과 처리하지 않는다.

볼륨명과 컨테이너 내부 마운트 위치를 Compose에 명시하고 재생성 후 데이터 보존을 확인한다. 호스트의 psql·Windows PostgreSQL 서비스·기본 설치 폴더는 필수 준비 조건이 아니다. CLI는 컨테이너의 psql을 사용할 수 있으며, 서버 실행·SQL 버전·계정·개발/테스트 DB는 실제로 확인해야 한다. [Docker 볼륨](https://docs.docker.com/engine/storage/volumes/), [공식 이미지의 psql 사용](https://hub.docker.com/_/postgres)

### 이번 문서 검토의 확인 범위

프로젝트 JDK의 java/javac 21.0.12.1, Maven 3.9.16과 해당 JDK 경로, Node 24.22.0·npm 11.19.1을 실행해 재확인했다. Maven 버전 출력 앞에는 기존 기록과 같은 `Access is denied.` 한 줄이 있었으며 원인은 확정하지 않았다. 다운로드 ZIP·도구 폴더·B2 보관 결과·B3의 HomePage 경로가 실제로 존재하고 Wrapper·npm 도우미가 이 경로를 사용함을 확인했다.

이번에는 배포본 재다운로드·체크섬 재검증·앱 빌드·브라우저/HTTP 검사·Docker 엔진 재조회·이미지 pull·DB 생성을 하지 않았다. 기존 B1~B3의 검증 결과는 각 작업 당시 증거다. 문서 검토로 새 테스트 통과나 Docker 준비 완료를 선언하지 않는다.

현재 다음 작업은 P01-B4이며 B5도 미착수다. B5는 Java/React 설정 예제·비밀값 제외·실행 안내를 정리하고, 실제 Compose·DB 연결 설정은 P01-C1에서 추가한다. P01-C1~C3에는 이미지·볼륨·DB 계정·호스트 접속·Flyway·트랜잭션 검증이 남아 있다.

이후 같은 날 사용자의 요청으로 B1의 상태 확인을 Actuator `/actuator/health`로 교체하고 빌드·HTTP 27건을 검증했다. 이는 위 Docker 문서 점검과 별도 작업이며 최신 결과는 [B1](P01-B1.md), health 프록시·화면 연결의 미착수 계획은 [B4](P01-B4.md)를 따른다.
