# P01-B2 React TypeScript Vite 첫 화면 구현과 검증

작성일: 2026-10-21 (Asia/Seoul)  
상태: **완료 — 첫 화면·도구 준비·타입·린트·빌드·브라우저 조작 확인. 사용자 직접 확인은 미확인**

2026-10-21 저녁에 B2 첫 화면을 재검증했다. 아래 초기 구현 설명과 P01-B2 재검증 절의 결과를 구분한다. 재검증 중 작업 폴더에 별도로 추가된 라우팅·레이아웃 변경은 이번 B2 검증의 완료 범위가 아니다.

현재는 [P01-B3](P01-B3.md)까지 완료됐다. 아래 App.tsx 중심 설명은 B2 당시 구현이며, 현재 샘플 상품·매대 입력은 `frontend/src/pages/HomePage.tsx`에 있다. 현재 전체 앱의 실행·라우팅은 B3 기록, 다음 구현은 B4를 따른다.

## 범위와 결과

G01·G10의 작은 화면 학습과 AC16의 실행 재현성 준비에 해당한다. 임시 이름 ‘모아마켓’의 첫 화면, 생활소품 샘플 3개, 입력값에 따라 바뀌는 매대 이름 미리보기를 구현했다. 매대 생성·상품 조회 API·장바구니·회원·구매 기능을 구현한 것은 아니다. 샘플임과 입력이 저장되지 않는다는 사실을 화면에 표시한다.

B2 최초 완료 당시에는 P01-B3의 라우팅·역할별 화면도 미착수였다. 이후 B3가 완료됐으며 P01-B4의 실제 Java API 연결과 P01-D3·D4의 자동 화면 테스트 체계는 여전히 미착수다. B2 구현 작업에서는 P01-A·P01-A2 및 백엔드 코드를 변경하지 않았다.

## Node 준비와 기술 판단

P01-A2에서 조사한 기본 Node 20.12.1은 Vite 목표 조건에 미달했다. 공식 Node 24.22.0 Windows x64 ZIP을 `.local-tools/node-v24.22.0-win-x64.zip`에 저장하고 프로젝트 `.local-tools/node-v24.22.0-win-x64`에 풀어 준비했다. 시스템 PATH나 기존 Node 설치는 변경하지 않았다.

[ADR-002](../decisions/ADR-002-docker-postgresql.md)는 PostgreSQL 서버의 Docker 실행 결정이다. React 개발·빌드 도구는 호스트의 Node·npm을 계속 사용하므로 Node 배포 URL·ZIP·실행 경로를 Docker 이미지 주소로 바꾸지 않는다. 프런트 패키지는 npm과 잠금 파일로 관리한다.

공식 SHASUMS256.txt와 다운로드 ZIP의 SHA-256 `f9683a19877e12a9b167305c8db71040d812876359de21f0d2e97c3f321f80c3`가 일치했다. [배포 파일과 체크섬](https://nodejs.org/dist/v24.22.0/)

새 배포본의 node.exe는 24.22.0이었다. 그러나 npm.cmd는 기존 prefix에서 npm을 찾는 로직 때문에 10.5.0을 반환했다. 새 배포본의 `node_modules/npm/package.json`은 11.19.1이었다. 시스템 prefix를 바꾸는 대신 새 node.exe로 동봉 `npm-cli.js`를 직접 실행해 11.19.1을 확인하고 설치·검증했다.

이 경로를 재현하는 `frontend/npm.ps1`을 추가했다. 실행 동안만 PATH·npm 캐시를 프로젝트 경로로 지정하고 종료 시 복원한다. 이 도우미는 Windows PowerShell 7용이다. 다른 OS에서는 지원되는 Node·npm을 별도로 준비하고 package.json의 명령을 사용한다.

| 구성 | 실제 고정 버전 |
| --- | --- |
| Node / npm | 24.22.0 / 11.19.1 |
| React / React DOM | 19.3.1 / 19.3.1 |
| TypeScript | 6.0.3 |
| Vite / React 플러그인 | 8.3.4 / 6.1.2 |
| ESLint / @eslint/js | 10.13.0 / 10.0.1 |
| typescript-eslint | 8.72.0 |
| React Hooks / Refresh 린트 플러그인 | 7.1.1 / 0.5.7 |
| React / React DOM 타입 | 19.3.0 / 19.3.0 |

설치 전 공식 npm 레지스트리 메타데이터로 린트·타입 도구의 engines/peer를 확인했다. typescript-eslint의 TypeScript 범위 >=4.8.4 <6.1.0에 6.0.3이 포함된다. Hooks·Refresh의 ESLint 10 지원도 확인했다. 전체 해석 결과는 package-lock.json에 기록했다. `--force`나 `--legacy-peer-deps`로 충돌을 숨기지 않았다. Node API를 코드에서 사용하지 않으므로 @types/node를 직접 추가하지 않았고 Router는 B3에 남겼다.

브라우저가 index.html을 읽으면 main.tsx가 App을 렌더링한다. App의 products 배열을 map으로 돌며 ProductCard에 product를 전달한다. 이것이 **props**이며, 자식 컴포넌트가 받는 입력값이다. SampleProduct 타입은 이름·가격 등 데이터 모양을 개발 중 검사한다. 서버 입력 검증이나 실제 데이터 저장을 대신하지 않는다.

B3 이후에는 App이 라우트를 구성하고 홈 경로에서 HomePage를 표시한다. products·ProductCard·SampleProduct·shopName은 HomePage.tsx로 이동했으며 아래 상태 갱신 원리는 같다.

매대 이름 입력 → onChange → setShopName → React 상태 갱신 → App 재렌더링 → previewName 표시 순서다. **state**는 화면이 기억하는 값이다. 일반 지역 변수에 대입하는 대신 setter를 호출해야 React가 변경을 반영한다. 빈 값과 공백은 안내 문구로 처리하고 JSX의 텍스트 보간을 사용해 HTML처럼 실행하지 않는다.

지금 흐름에는 HTTP 요청·Java·SQL이 없다. Node는 Vite·TypeScript·ESLint를 실행하는 개발 도구 환경이고, 배포할 화면 결과는 dist의 정적 파일이다. 개발 서버는 운영 서버로 사용하지 않는다.

## 실행과 검증 명령

프로젝트 루트의 PowerShell 7에서:

```powershell
.\frontend\npm.ps1 ci
.\frontend\npm.ps1 run typecheck
.\frontend\npm.ps1 run lint
.\frontend\npm.ps1 run build
.\frontend\npm.ps1 run dev '--' --port 5173 --strictPort
```

마지막 명령 후 http://127.0.0.1:5173을 연다. 터미널에서 실행한 서버는 Ctrl+C로 종료한다. `.local-tools`는 공유 대상이 아니므로 다른 PC에서 Node ZIP을 준비할 때 공식 체크섬을 검증한다. npm 도우미가 예상하는 폴더명은 위 Node 경로다. node_modules와 dist는 재생성하며 Git 제외 규칙에 추가했다.

PowerShell 스크립트를 통해 npm을 실행하므로 구분자 `'--'`를 따옴표로 감싼다. 따옴표 없는 `--`는 PowerShell이 먼저 소비해 `--port` 같은 Vite 옵션을 npm이 해석할 수 있다. npm이 스크립트에 넘길 옵션과 PowerShell의 인수 처리를 구분한다.

## 직접 수정해 볼 예시

현재 소스의 `frontend/src/pages/HomePage.tsx`에서 products 배열의 첫 상품 name을 ‘내가 고른 머그’로 바꾸고 홈 화면을 확인한다. B2 당시에는 App.tsx에 있던 코드다. 저장하면 Vite가 변경을 반영한다. 다음으로 price를 21000으로 바꾸면 21,000원이 표시된다. 숫자 대신 문자열을 넣으면 TypeScript 검사가 실패하는 것도 비교해 볼 수 있다. 실습 후 올바른 타입으로 복구하고 typecheck·lint·build를 실행한다.

컴포넌트 수정·타입 오류 이해·실제 조작에 대한 **사용자 직접 확인은 미확인**이다. 자동 검사와 에이전트의 UI 확인 결과를 사용자 학습 완료로 대신하지 않는다.

B2 당시 다음 작업은 P01-B3의 경로·공통 레이아웃이었다. 이후 별도 B3 작업에서 완료됐으며 현재 다음 구현은 B4다.

### 수정한 안내와 막혔던 항목

1. 따옴표 없는 `--`로 preview 옵션을 전달하면 npm이 `--outDir`·`--port`를 자신의 옵션으로 해석하고 Vite가 `Unused args: 4173`으로 종료했다. `'--'`를 문자열로 전달하자 옵션이 온전히 전달되고 기동에 성공했다. README와 위 개발 서버 명령을 수정했다.
2. 제한된 실행 환경에서는 서버가 시작돼도 로컬 HTTP 요청이 소켓 접근 거부로 실패했고 브라우저는 시간 초과됐다. 해당 서버를 종료하고 접근이 허용된 실행 환경에서 다시 기동해 HTTP·UI 검증을 마쳤다. 시스템 방화벽·네트워크 설정은 변경하지 않았다.
3. 처음 실패한 브라우저 탭은 오류 화면 재사용이 막혀 새 탭에서 같은 허용된 localhost 주소를 열어 검증했다. 브라우저 보안 설정을 변경하지 않았다.
4. 동시 소스 변경 때문에 최신 전체 작업 폴더의 최종 통합 검증은 이번 결과에 포함하지 않는다. 모바일·여러 브라우저·화면 전체 키보드 접근성·복합 이모지의 길이 기준도 미검증이다.
