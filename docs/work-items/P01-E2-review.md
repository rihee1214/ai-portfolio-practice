# P01-E2 개발 검토

2026-10-23 / 대상: `cc98717..35e0fd4`

판정: 문서에 명시된 Servlet ERROR 디스패치의 API 오류 표현 범위에서 검토 통과. 필수 수정 결함은 발견하지 않았다. 이 세션은 제품·테스트 코드와 작업 상태 문서를 수정하지 않고 검토 문서와 실행 요약만 추가했다. 최종 완료 기록·로컬 커밋은 개발세션에서 처리한다.

## 독립 실행

기존 로컬 JDK/Maven 캐시로 별도 `.local-tools/e2-review-build`에 DB 프로필 없는 verify를 실행했다. [검토 요약](evidence/P01-E2-review-summary.json): **69개 통과**, 실패·오류·skip 0, Checkstyle·컴파일·패키징 성공. 기존 44개와 신규 HTTP 25개를 포함한다. RED 22개 중 18개 실패와 배포 JAR의 probe 제외는 개발세션 증거를 검토했으며 해당 RED 실행은 반복하지 않았다.

| 검토 항목 | 판단과 증거 |
| --- | --- |
| ERROR 필터 선택 | 현재 범위에서는 원래 요청 경로로 적용 범위를 제한하고 기본 비업무 오류 처리를 유지한다. ControllerAdvice 또는 전체 ErrorController 교체를 지금 추가할 필요는 없다. 직접 반환한 ResponseEntity 오류까지 통일하지 않는다는 제한이 문서에 명시돼 있다. |
| 경로 경계 | 정확한 /api 또는 /api/ 접두사만 허용한다. /apiary·/API/missing·/actuator/env·직접 /error는 기본 형태를 유지하는 실제 HTTP 검사가 통과했다. context path 제거 로직은 정적으로 확인했고 실제 별도 context path 배포는 미검증이다. |
| 상태·헤더 | 오류 속성의 400~599 상태를 유지하며 고정 표현으로 변환한다. 실제 405 Allow와 429 Retry-After 단언이 통과했다. no-store 설정을 코드로 확인했으며 모든 헤더 조합 보존을 시험한 것은 아니다. |
| HEAD·콘텐츠 협상 | HEAD는 404와 빈 본문·ID 헤더를 검사한다. JSON/HTML/XML/wildcard Accept에도 API 오류는 JSON이라는 명시적 계약이다. 실제 406도 검사한다. HEAD의 Content-Type·Cache-Control 전체 계약을 테스트가 단언하지는 않는다. |
| 요청 ID·정리 | E1보다 뒤에서 실행되므로 응답 body와 헤더가 같은 서버 ID를 쓴다. 동기·비동기 500도 같은 body/header 계약을 검사한다. E1의 finally 정리와 기존 디스패치 검사가 통과했다. |
| 정보 노출 | 고정 record의 세 필드만 직렬화한다. URL·쿼리·예외·거절 입력을 response에 복사하지 않는다. 가상 private-e2 문자열과 Exception 미노출을 확인한다. 서버 로그의 개인정보 정제까지 보장하는 검사는 아니다. |
| 기존 계약 | health 정상·장애 status-only 및 health405 검사는 유지된다. 성공 API는 감싸지 않는다. 기존 /api404 기대값 수정은 이번 오류 계약 변경에 부합하며 비업무 기본 오류 기대값은 유지했다. |

시험의 의도적 500 예외 로그와 장애 health 경고는 테스트 실패가 아니다. 401/403/409/429는 sendError로 이미 결정된 상태의 표현 검사이며 실제 인증·인가·충돌·요청 제한 기능 검증으로 계산하지 않는다.

## 설계상 주의점과 한계

API ERROR를 처리할 때 chain.doFilter를 호출하지 않는 종결 필터다. 따라서 순서가 뒤인 ERROR 전용 필터나 기본 오류 컨트롤러는 이 경로에서 실행되지 않는다. 현재 E1은 앞에서 실행되어 영향을 받지 않고, 현재 범위에 필수 후속 필터도 없어 결함으로 분류하지 않는다. 향후 보안 헤더·관측·오류 감사 필터를 추가하면 이 순서와 ERROR 디스패치 적용 여부를 다시 검토해야 한다.

이미 커밋된 응답·직접 작성한 오류 응답·필터 이전 오류는 정규화하지 않는다. 모든 미래 업무 오류가 자동 통일됐다는 의미가 아니다. fieldErrors·업무 예외 handler·React 표시·DB 거래·브라우저는 미구현 또는 이번 미검증 범위다. 사용자 직접 실습과 이해도 미확인이다.

## 보존

검토 종료 후 기존 dev/test DB를 읽기 전용 pg_dump로 조회한 정규화 해시는 개발세션 종료 증거와 동일하다. 무작위 restrict/unrestrict 토큰을 제외했으며 덤프 원문은 저장하지 않았다. DB 컨테이너 ID·healthy와 15432/15433 PID 57168이 유지된다. DB 쓰기·생성·초기화·재시작은 하지 않았다.

8080/4174/5174 앱 리스너는 기존 기록과 마찬가지로 없다. 기존 앱을 실행하거나 종료하지 않았고 소유 RANDOM_PORT 테스트 서버만 사용했다. 다음 E 작업·프런트 단순화·push·로컬 커밋은 수행하지 않았다.
