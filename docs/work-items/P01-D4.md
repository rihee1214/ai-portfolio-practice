# P01-D4 Playwright 실제 브라우저 검사

2026-10-23 / 상태: 구현·검증·독립 검토 완료

## 범위와 계획

기준 커밋 `22f9f55`의 설계·작업 계획에 따라 현재 React 화면과 실제 Java health 연결을 검사한다. 기존 서버·DB는 보존하고 D4 이후는 진행하지 않는다. 실행 계획 및 완료 전 검증 스킬을 적용한다. 개발 검토는 사용자가 지정한 검토 및 반영세션에 요청한다.

1. 기존 서버·DB 기준 상태 기록 및 고정 버전 Playwright/Chromium 준비.
2. 현재 Java 소스를 별도 경로로 빌드하고 테스트 전용 React/Java 포트를 사용.
3. mock 없는 health 연결, 경로/새로고침/없는 경로, 키보드·화면 폭·문맥 격리 검사.
4. 기존 포트 점유 시 거부, 타입·린트·빌드·기존 검사 회귀 및 보존 확인.
5. 결과와 한계를 기록하고 독립 검토 후 최종 문서 커밋.

## 구성과 보존

- @playwright/test **1.64.1**을 개발 의존성으로 정확히 고정했다. Node >=20 조건을 확인했으며 기존 Node24.22.0을 사용한다. Chromium **156.0.8078.4 / revision1248**, headless shell, FFmpeg, Winldd를 `.local-tools/playwright`에 설치했다. 전역 브라우저나 사용자 프로필은 사용하지 않는다.
- `playwright.config.ts`의 webServer는 현재 Java JAR를 **127.0.0.1:18080**, 기존 React 앱과 동일 apiProxy 구현을 **127.0.0.1:24174**에서 실행한다. 제품의 기본 프록시8080 설정은 변경하지 않았다. Java는 기본 classpath 설정과 D4 프로필·명시적인 DataSource/Flyway 제외로 DB를 연결하지 않는다.
- 두 서버 모두 `reuseExistingServer:false`, Vite strictPort로 기존 서버를 채택하지 않는다. 직접 시작한 테스트 프로세스만 Playwright가 종료한다. [포트 충돌 검사](evidence/P01-D4-occupied-port.txt)는 직접 만든 임시 HTTP 리스너를 대상으로 실행했다. 실행 코드1로 거부한 뒤 기존 리스너의200 응답을 재확인했다.
- 시작 기준으로8080·4174·5174 앱 리스너는 없었다. 브라우저 UI에 URL이 표시되는 것과 서버 실행은 구분한다. 기존 DB 컨테이너와 포트는 유지했다. 시작·종료 읽기 전용 덤프의 restrict/unrestrict 무작위 토큰만 제외하고 해시를 비교하며 원문은 저장하지 않는다. DB 생성·쓰기·초기화·재시작은 없다.
- Playwright 산출물·실패 trace·실패 스크린샷은 ignored `.local-tools/d4-playwright`에 둔다. 성공 실행 요약·로그와 두 화면 이미지만 문서 증거로 남긴다. 실제 사용자의 로그인 상태·쿠키는 접근하지 않는다.

## 실제 브라우저 검사

Chromium desktop 1440×900, Chromium 모바일 에뮬레이션 390×844에서 동일한6개 시나리오를 실행한다. `workers:1`, `retries:0`, `forbidOnly:true`로 실행하며 테스트마다 새 문맥을 사용한다. route.fulfill 등 API 모의는 없다.

| 시나리오 | 확인 내용 |
| --- | --- |
| 실제 API 연결 | Java 직접 health200/UP 및 React 버튼 → Vite 프록시 → Java 응답200/UP → 화면 성공 안내, 다시 시도 |
| 직접 URL·새로고침 | 구매자·판매자·운영자 및 하위 화면 총15개 경로의 heading·title |
| 없는 경로 | 안내 화면·새로고침·홈 복귀 |
| 키보드 | Tab/Enter 본문 건너뛰기, 입력·초기화, 판매자 이동 후 main 포커스와 뒤로 가기 |
| 화면 폭 | 홈·구매자·상품 관리·콘텐츠 조치의 가로 넘침 없음, 주요 메뉴 viewport 진입과 판매자 이동 |
| 문맥 격리 | 첫 문맥 입력/테스트 localStorage 표식이 새 문맥과 공유되지 않음, 새로고침으로 입력 초기화 |

결과: [최종 브라우저 실행](evidence/P01-D4-browser-final.txt) **12개 통과**, 실패·skip·flaky0. [집계](evidence/P01-D4-browser-summary.json), [데스크톱 화면](evidence/P01-D4-chromium-desktop.png), [모바일 화면](evidence/P01-D4-chromium-mobile.png). 모바일 캡처에서 메뉴와 카드의 줄바꿈을 확인했다. 이 이미지는 회귀 기준 이미지와 픽셀 비교한 결과는 아니다.

Java verify는 DB 없는 기존33개·Checkstyle·패키징을 통과했다. [타입](evidence/P01-D4-typecheck.txt)·[린트](evidence/P01-D4-lint.txt)·[React 빌드](evidence/P01-D4-build.txt), [Vitest14개](evidence/P01-D4-unit.txt), [기존 Node68개](evidence/P01-D4-node.txt)도 통과했다. 제품 코드 수정 없이 테스트·설정·의존성만 추가했다.

## 실패 이력과 남은 범위

- 앞선 시도에서 다른 세션의 오래된 ‘D4 미진행’ 메시지 때문에 자동 승인 검토가 설치를 두 번 거부했다. 직접 사용자가 제한 해제와 D4 진행을 재승인한 뒤 설치가 성공했다. 우회 설치는 하지 않았다.
- 첫 실행은 **14174가 Windows 예약 포트14117~14216에 포함**되어 Vite EACCES로 기동 실패했다. [실패 로그](evidence/P01-D4-browser-first.txt). 예약 목록 및 bind 검사로 원인을 확인하고 사용 가능한24174로 변경했다. Windows 예약/방화벽 설정은 변경하지 않았다. API와 프런트 중 일부만 기동한 경우도 Playwright 정리 이후18080 포트를 다시 bind할 수 있었다.
- 색상 환경변수 경고(NO_COLOR/FORCE_COLOR)는 실패가 아니다. Vite import 확장자 경고는 테스트 설정에서 `.ts`를 명시해 해결했다.
- 실제 모바일 기기·Firefox·WebKit·스크린리더 발화·운영 배포 서버는 미검증이다. 모바일은 Chromium 에뮬레이션이며 새 문맥 테스트는 현재 입력/저장소의 격리만 증명한다. 로그인·권한·비회원 주문 조회는 아직 구현되지 않았다.
- 현재 health는 DB를 검사하지 않는다. 이번 결과는 **React→Java 실제 연결**이며 React→Java→DB 구매 거래나 AC01~AC16 전체 완료가 아니다. 오류·늦은 응답·스트림 단절은 기존 D3/Node 검사 범위이며 이번 브라우저 검사에서 서버 중단을 새로 재현하지 않았다.
- 사용자 직접 실습·이해 확인은 미확인이다. D4 이후·프런트 단순화·원격 push는 진행하지 않는다.

## 다시 실행하기

Windows PowerShell7 프로젝트 루트에서 실행한다. 로컬 JDK/Node는 기존 준비 경로를 사용하고 현재 소스를 전용 경로에 다시 빌드한다. Maven verify는 DB 통합 프로필을 켜지 않는다. 테스트 포트가 점유돼 있으면 기존 프로세스를 종료하지 말고 원인을 확인한다.

```powershell
$previousJava = $env:JAVA_HOME
$previousMaven = $env:MAVEN_USER_HOME
try {
  $env:JAVA_HOME = Join-Path $PWD '.local-tools/jdk-21.0.12.1+1'
  $env:MAVEN_USER_HOME = Join-Path $PWD '.local-tools/m2'
  ./backend/mvnw.cmd -f backend/pom.xml "-Dmarketplace.build.directory=$PWD/.local-tools/d4-build" verify
  if ($LASTEXITCODE -ne 0) { throw 'Java build failed' }
} finally {
  $env:JAVA_HOME = $previousJava
  $env:MAVEN_USER_HOME = $previousMaven
}
./frontend/npm.ps1 run test:e2e
```

새 환경에서는 먼저 `./frontend/npm.ps1 ci`를 실행한다. Chromium 설치 시 `PLAYWRIGHT_BROWSERS_PATH`를 프로젝트 `.local-tools/playwright`로 일시 지정하고 `./frontend/npm.ps1 exec -- playwright install chromium`을 실행한 뒤 환경변수를 복원한다. 패키지와 브라우저 다운로드가 필요하며 오프라인 새 설치는 검증하지 않았다.

학습 흐름: `test`가 실제 브라우저 문맥을 만들고 `page.goto`로 앱에 접속한다. role 기반 locator가 사용자 조작을 수행하고 `expect`가 화면 갱신을 기다린다. health 검사는 서버 응답과 화면 안내를 함께 확인한다. 작은 직접 실습으로 경로 검사의 기대 heading을 잠시 틀리게 바꿔 실패를 확인한 후 원복할 수 있다. 자동 통과와 사용자 직접 실습 완료는 구분한다.

공식 근거: [Playwright webServer](https://playwright.dev/docs/test-webserver), [브라우저 설치](https://playwright.dev/docs/browsers). 서버 소유권·브라우저 버전별 설치 방식은 이 문서를 기준으로 했다.

## 보존 확인

[시작](evidence/P01-D4-before.json)과 [종료](evidence/P01-D4-after.json)의 개발/테스트 DB 해시는 동일하다. 컨테이너 ID·healthy와 DB 리스너 PID57168도 유지했다. 종료 시18080·24174가 남지 않았으며 기존8080·4174·5174도 시작과 같이 리스너가 없다. 기존 서버를 끄거나 새로 켜지 않았다. 로그는 행 끝 공백과 마지막 빈 줄만 정리했다.

## 독립 검토 및 완료

구현 커밋 `3d74bc2`를 [검토 및 반영세션](P01-D4-review.md)에서 검토해 필수 수정 결함 없이 통과했다. [독립 요약](evidence/P01-D4-review-summary.json)에서 브라우저12개·타입·린트와 종료 포트·DB 해시 보존을 재확인했다. 제품 코드 추가 수정은 없다. 현재 차단 항목은 없다.

비차단 관찰을 완료 범위에 반영한다. 키보드 검사는 일부 지점에 포커스를 직접 지정하므로 전체 Tab 탐색을 검증한 것은 아니다. 새 문맥은 기본 Chromium 옵션이어서 모바일 프로젝트에서 두 문맥 모두 모바일 설정이라고 볼 수 없다. viewport·가로 넘침 단언은 전체 요소의 터치 영역·잘림·겹침이나 스크린리더 검증이 아니다. 없는 경로는 SPA 안내 검사이며 HTTP404 상태 계약을 단언하지 않는다. 브라우저 검사는 Vite 개발 서버를 대상으로 했고 production build 브라우저 실행은 미검증이다. 이 한계를 현재 단계에서 새 기능 구현으로 확장하지 않는다.

Java 소스가 바뀌면 위 실행 안내대로 D4 JAR를 다시 빌드해야 한다. test:e2e는 JAR 존재만 확인하므로 빌드 최신성을 자동 보장하지 않는다. 사용자 직접 실습은 미확인으로 유지한다. 검토 문서와 완료 기록을 포함해 최종 로컬 커밋하고 D4 이후에는 착수하지 않는다.
