# P08-B DB Job·Outbox와 worker — 구현 작업 계획

> **For agentic workers:** 구현 요청 시 `superpowers:executing-plans`로 작은 작업을 순서대로 수행한다. 개발 전체 통과 후 지정 검토세션에서 독립 검토한다. 이번 문서 작성은 구현/커밋 승인이 아니다.

**Goal:** 업무 거래와 함께 저장한 이벤트를 중단·중복 실행에도 재개할 수 있게 한다.

**Architecture:** platform에는 업무를 모르는 일반 작업 포트/저장/실행권만 둔다. 업무 핸들러는 해당 모듈이 구현·등록하고 별도 worker 실행 모드가 폴링한다.

**Tech Stack:** Java/Spring Boot·Spring JDBC·PostgreSQL·JUnit/ArchUnit·React/TypeScript·Vitest/Playwright.

**Spec:** [설계](../shop-design.md) §4·7~11·13~16, [요구사항](../requirements.md) F05/F09/F10/F11·AC01~04/07/08/13, [구현 계획](../implementation-plan.md) §10, [P08 전체 계약](P08.md).

상태: R-B07 보완·개발 전체2 통과 / 독립 전체2 검토 대기. 선행: **A 완료**.

## Interfaces와 세부 계약

생산: `Outbox.append(event)`는 호출자 거래 참여, `Jobs.enqueue(command)`는 dedupeKey 고유, `JobHandler`는 타입별 처리와 결과 계약. Job은 status/nextRunAt/leaseUntil/attempts/ownerToken을 저장한다. 경쟁 claim은 DB행 잠금/조건부 갱신으로 한 owner만 획득하고 완료/연장은 해당 token 조건으로만 갱신한다. 오래된 owner의 완료를 거부한다. 외부 부작용은 lease만으로 exactly-once가 되지 않으므로 원인 키를 업무 명령/제공자에도 전파한다.

제안 초기 운영값: lease30초·heartbeat10초·최대5회·재시도5/15/60/300초 후 terminal 실패. 테스트는 조절 Clock으로 수행하며 값/오류 분류는 B 착수 계약에 확정한다. 결제 UNKNOWN의 별도 조회/운영 대사 기한은 D가 정하고 일반 재시도 소진을 주문 실패/예약 해제로 번역하지 않는다. 같은 이벤트를 여러 번 전달해도 소비자의 업무 효과는1회. 메모리 이벤트는 깨우기 용도로만 허용한다.

### C/D/F1 공개 인계 계약

`platform.api.Outbox.append(Event(UUID,Jobs.Command))`는 호출자 거래에 REQUIRED 참여하며 event와 job을 동시에 저장한다. Command(type,dedupeKey,causeKey,payload,nextRunAt)의 최초 실행시각은 microsecond로 정규화한다. 같은 dedupeKey의 type/cause/payload/최초시각이 바뀌면 JOB_KEY_CONFLICT, 같은 event ID가 다른 job이면 EVENT_ID_CONFLICT로 거래를 실패시킨다. 임의의 요청마다 실행시각을 다시 계산하지 말고 저장된 기한/안정 키를 재사용한다.

`Jobs`의 enqueue/claim/heartbeat/complete/fail/find/failed는 신뢰된 내부 포트다. claim은 지원 type 집합만 선택하고 별도 짧은 거래를 commit한 뒤 Job(id,command,status,attempts,nextRunAt,ownerToken,leaseUntil,lastError)을 넘긴다. heartbeat/complete/fail은 RUNNING+현재token+미만료 lease에서만 성공한다. Clock 판정은 행잠금 획득 뒤 한다. Job.command.nextRunAt은 최초 요청값이고 Job.nextRunAt은 현재 재시도 시각이다. terminal 조회는 failed(1..1000)이며 운영 HTTP/재처리 화면은 B 범위가 아니다.

업무 모듈의 application/infrastructure가 `JobHandler` bean을 등록한다. type은 유일해야 하고 Result는 COMPLETE/RETRY/TERMINAL이다. 예외 원문 대신 HANDLER_EXCEPTION을 저장하고 재시도한다. 각 handler는 causeKey로 업무효과를 동일 업무거래에서 dedupe하고 외부 제공자에도 같은 원인키를 전달해야 한다. lease만으로 외부 exactly-once를 보장하지 않는다. 일반 FAILED는 주문 실패/예약 해제 명령이 아니며 D의 UNKNOWN 대사 정책과 분리한다.
