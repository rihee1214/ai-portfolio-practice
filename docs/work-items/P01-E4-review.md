# P01-E4 개발 검토

2026-10-24 / 대상: `15d9a19..6b70d0f`

판정: db 프로필의 필수 datasource 설정 존재 검증 범위에서 독립 검토 통과. 필수 수정 결함은 발견하지 않았다. 이 세션에서는 제품·테스트·작업 상태 문서를 수정하지 않고 검토 문서와 요약만 추가했다. 완료 기록·최종 로컬 커밋은 개발세션에서 처리한다.

## 독립 실행

기존 로컬 JDK/Maven 캐시로 별도 `.local-tools/e4-review-build`에 DB 통합 프로필 없는 verify를 실행했다. [검토 요약](evidence/P01-E4-review-summary.json): **83개 통과**, 실패·오류·skip 0, Checkstyle·컴파일·패키징 성공. 기존 69개와 신규 설정 14개가 포함된다. 이번 실행에는 개발세션의 Mockito 초기화 대기 현상이 재발하지 않았다. 그 최초 대기의 내부 원인이 규명된 것은 아니다.

개발세션의 RED 및 패키징 앱 비웹 시작 실패 기록은 검토했으며 직접 재실행하지 않았다. 프런트·브라우저·실제 DB 연결 검사도 반복하지 않았다.

## 구현과 검사 의미

| 항목 | 결과 |
| --- | --- |
| 적용 범위 | @Profile("db")로 한정된다. default/local 컨텍스트에 설정을 요구하지 않는 검사와 기존 DB 없는 health/오류 HTTP 회귀가 통과했다. |
| 검증 대상 | 최종 Environment의 spring.datasource.url/username/password를 읽는다. 환경 이름만 강제하지 않아 명시적 datasource 설정으로 대체할 수 있다. 유효 합성 값·누락·빈 값·공백·미해결 placeholder 검사가 통과했다. |
| 시작 순서 | static BeanFactoryPostProcessor가 일반 singleton 생성 단계보다 먼저 검증한다. 잘못된 설정에서 일반 bean 생성 표식이 실행되지 않는 단언이 통과했다. 현재 제품 코드에 이보다 앞서 DB를 생성하는 별도 후처리기는 없다. |
| 진단 메시지 | 누락 항목을 고정된 설정 이름과 환경 변수 안내로 모은다. placeholder 해석 예외를 원인으로 연결하지 않는다. 합성 비밀값이 최종 원인 메시지와 캡처 출력에 없는 검사도 통과했다. |
| 기존 동작 | datasource/Flyway 설정 파일·DB_SCHEMA·health·React 구현에는 diff가 없다. 값 자체를 수정하거나 trim하여 저장하지 않는다. |
| DB 격리 | 새 컨텍스트 검사는 실제 앱/ConfigData를 로딩하면서 DataSource/Flyway 자동 구성을 제외한다. 정상 설정으로 컨텍스트가 시작했다는 결과는 실제 연결 자격 검증이 아니다. |

## 비차단 주의점·미검증

- '${'가 남은 모든 값을 거부하므로 이 문자열을 실제 비밀번호 일부로 사용하는 경우도 거부한다. 작업 문서가 이미 이 제약을 명시했다. 이번 검토에서 임의로 허용 범위를 확대하지 않았다.
- 일반 singleton보다 앞선 검증이지 모든 확장 코드보다 앞선다는 보장은 아니다. 향후 BeanFactoryPostProcessor/BeanDefinitionRegistryPostProcessor 등에서 DB bean을 조기 생성하거나 Environment를 뒤늦게 바꾸면 시작 순서를 다시 확인해야 한다.
- 테스트의 DB_URL 등은 합성 프로퍼티 소스로 주입한다. 실제 OS 환경 변수와 운영 배포 파일의 모든 바인딩 조합을 확인한 것은 아니다. default 검사는 명시적 default 프로필이며, 기존 전체 회귀가 기본 실행도 보완한다.
- 빈 값/placeholder 오류를 안전하게 안내하는 범위다. 잘못된 URL 문법·잘못된 접속 자격·DB 장애·다른 구성 요소가 출력하는 민감정보까지 검증하거나 정제하지 않는다.
- 일반 bean 생성 표식 하나와 자동 구성 제외 컨텍스트로 시작 순서를 검사했다. 실제 DataSource/Flyway 객체를 생성해 접속하지 않음을 별도 계측한 검사는 아니다. 패키징 실패 증거와 현재 코드의 실행 순서를 함께 검토했다.
- 사용자 직접 실습·이해는 미확인이다. Actuator 정책·ArchUnit·다음 단계는 이번 검토 범위가 아니다.

## 보존

검토 후 기존 dev/test DB의 읽기 전용 pg_dump에서 무작위 restrict/unrestrict 토큰을 제외한 해시가 개발세션 기록과 동일했다. 덤프 원문은 저장하지 않았다. 두 컨테이너 ID·healthy 및 15432/15433 PID 57168이 유지된다. 앱에서 실제 DB 접속 검증을 실행하지 않았고 DB 쓰기·생성·초기화·재시작은 하지 않았다.

기존 8080/4174/5174 앱 리스너는 이전처럼 없었다. 임의 실행·종료·재시작 없이 소유 RANDOM_PORT 테스트 서버만 사용했다. 제품 수정·다음 단계·프런트 단순화·push·커밋은 하지 않았다.
