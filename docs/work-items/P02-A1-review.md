# P02-A1 개발 검토

2026-10-24 / 기준: `0a7db1d` 이후 A1 변경 / 대상: identity 모듈, V3 SQL, 해시 의존성, 입력·보안·실제 DB 검사

판정: **진행 중 발견한 R1/R2를 개발세션에서 수정했고 수정 후 독립 검증 통과. 남은 필수 수정 결함 없음.** 완료 범위는 공개 Java 가입·이메일 확인 서비스/SQL/로컬 메모리 메일함이다. HTTP 가입·로그인·세션·CSRF·React 화면은 미구현이며 사용자 가입 화면 전체 완료를 뜻하지 않는다.

## 검토 중 발견과 반영

### R1 — 가입만 별도로 커밋되는 트랜잭션 전파

초기 SignupService는 REQUIRES_NEW를 사용해 바깥 작업이 rollback돼도 가입과 메일이 남을 수 있었다. 설계의 기본 REQUIRED 계약에 맞추도록 요청했고 개발세션이 외부 rollback 사례에서 가입 행이 남는 실패를 재현했다. 최종 코드는 REQUIRED이며, 외부 rollback 시 가입 행 부재와 메일 미공개를 확인하는 회귀 검사가 독립 실행에서도 통과했다.

가입 서비스가 반환한 userId는 외부 트랜잭션이 있을 때 아직 commit 확정값이 아니다. 해시는 서비스 자체 트랜잭션 전 계산하지만 이미 열린 호출자 트랜잭션 밖까지 보장하지 않는다. 문서가 이 차이를 명시한다.

### R2 — ASCII 입력 검증 전에 소문자화

초기 이메일 처리는 Locale.ROOT 소문자화 후 정규식만 확인했다. Kelvin sign K처럼 소문자화하면 ASCII k가 되는 입력이 ASCII 전용 계약을 통과할 수 있어 수정 요청했다. 최종 코드는 strip 후 비ASCII를 거부한 다음 소문자화한다. 해당 경계 사례가 입력 규칙 검사에 포함됐고 독립 검사도 통과했다.

`./backend/verify-db.ps1 -EvidenceDirectory .local-tools/p02-a1-review -Offline`을 실행했다. [독립 요약](evidence/P02-A1-independent-summary.json): 기본 **124개**, 실제 PostgreSQL 통합 **21개**, 실패·오류·skip 0, Checkstyle·컴파일·패키징 성공. 기본은 기존117+신규7, 통합은 기존12+가입/확인9다. 반복 입력값이나 스레드 수를 별도 테스트 수로 더하지 않는다.

새 DB **d2_it_0529e5bf6e164030b7d47d960c2acfbe**를 생성해 사용했으며 삭제하지 않았다. 기존 보호 초기화기·DB/역할 검사를 유지한다. 정제 로그·summary·target은 `.local-tools/p02-a1-review`에 보존했다. XML 원문이나 실제 비밀값은 공개 문서로 복사하지 않았다.

독립 실행의 Argon2 비용은 encode138ms·verify22ms였다. 단일 실행·JIT/초기화 비용이 포함된 관찰값이며 운영 처리량·목표 지연 보장이 아니다.

## 남은 범위와 주의점

- 메모리 메일함은 프로세스 재시작과 commit 직후 프로세스 종료를 견디는 전달 시스템이 아니다. 재발송도 아직 없어 토큰을 잃은 미확인 계정의 복구 경로는 후속 기능이 필요하다. 현재 로컬 테스트 도구의 한계로 유지한다.
- 메일 공개의 실패 없음은 현재 메모리 필드 전환 구현에 한정된다. 향후 SMTP 등 외부 I/O로 교체할 때 afterCommit 전달의 실패·재시도 설계를 새로 해야 한다.
- 동시성 검사는 두 요청 사례이며 부하·모든 스케줄링을 보증하지 않는다. 토큰 만료는 애플리케이션 Clock 기준이고 실제 시간 변경·장시간 lock 대기는 이번 시험 범위가 아니다.
- repository는 현재 marketplace 스키마를 명시한다. 다른 DB_SCHEMA로 서비스를 구성하는 것은 지원·검증한 범위가 아니다. V3를 기존 사용자 DB에 적용하지 않았다.
- 일반 가입/확인 HTTP 오류 매핑, 재발송·반복 실패 제한, 로그인·CSRF·화면은 다음 단계다. 프런트는 변경하지 않았고 브라우저 검사를 이번에 반복하지 않았다. 사용자 직접 실습·이해는 미확인이다.
