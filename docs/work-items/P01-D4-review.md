# P01-D4 개발 검토

2026-10-23 / 대상: `22f9f55..3d74bc23fc8c807158611c0facbfd51a595c29e7`

판정: D4 현재 범위 검토 통과. 필수 코드 수정 결함은 발견하지 않았다. 비차단 관찰과 증거 한계를 아래에 기록한다. 이 세션은 제품/테스트 코드와 상태 문서를 수정하거나 커밋하지 않았으며 검토 문서와 요약만 추가했다. D4 이후·프런트 단순화·push는 수행하지 않았다.

## 직접 실행과 보존

프로젝트 npm.ps1로 test:e2e, typecheck, lint를 실행했다. [독립 검토 요약](evidence/P01-D4-review-summary.json): Chromium desktop 6개 + mobile 에뮬레이션 6개, 총 **12개 통과**, 실패/skip/flaky 0, 약22.8초. 타입·린트 종료 코드도0이다. 기존 준비된 D4 JAR를 사용했으며 Java 빌드·Node68개·Vitest14개·React 빌드는 여기서 반복하지 않고 개발세션 증거를 검토했다. test:e2e는 JAR 존재만 확인하므로 Java 소스가 바뀌면 실행 안내대로 별도 재빌드해야 한다.

시작 시 8080/4174/5174/18080/24174에는 리스너가 없었다. Playwright가 시작한18080/24174는 실행 종료 후에도 리스너가 없음을 직접 확인했다. 기존8080/4174/5174는 계속 미실행이며 이를 기존 사이트의 가동 성공으로 계산하지 않는다.

검토 후 기존 marketplace_dev/test를 읽기 전용 pg_dump로 조회해 무작위 restrict/unrestrict 토큰을 제외한 해시를 비교했다. 개발세션 시작 기록과 동일하다. 덤프 원문은 저장하지 않았다. db-dev6a9f494624c9/db-test68d17431a4b1은 healthy이고 DB 리스너 PID57168도 유지한다. DB 생성·쓰기·초기화·컨테이너 재시작은 하지 않았다.

## 구현과 테스트 의미

| 항목 | 검토 결과 |
| --- | --- |
| 서버 분리 | Java18080과 Vite24174만 사용한다. Java는 명시적 DB/Flyway 제외를 적용하고 Vite는 기존 apiProxy 구현의 target만 변경한다. frontend/src 및 backend/src/main의 최종 diff는 없다. |
| 서버 소유권 | reuseExistingServer:false와 Vite strictPort를 사용한다. 기존 서버 채택을 허용하지 않는다. 개발세션의 임시200 리스너 충돌 거부 및 보존 증거를 확인했다. 해당 충돌 실험 자체는 재실행하지 않았다. 고정 포트는 병렬 별도 실행 시 충돌로 실패할 수 있으며 임의 서버 종료로 해소해서는 안 된다. |
| 실제 health | Java 직접 응답과 브라우저 버튼→프록시 응답→화면 안내를 함께 확인한다. route.fulfill 같은 응답 모의는 없다. DB 없는 health 연결의 증거이며 구매/결제·권한·DB 거래 정상 증거가 아니다. |
| 라우팅 | 역할별15개 경로에 직접 진입·새로고침하고 heading/title을 확인한다. 없는 경로는 앱의 안내 화면과 홈 복귀를 검사한다. 이 테스트는 HTTP404 상태를 단언하지 않으며 SPA 안내를 서버404 계약으로 해석하지 않는다. |
| 입력·키보드 | 본문 건너뛰기의 Tab/Enter, 입력 후 초기화 버튼 Tab/Enter, 링크 Enter와 main 포커스를 확인한다. 실제 브라우저에서 사용자 이벤트와 React 결과를 연결한다. |

## 비차단 관찰과 미검증

1. 키보드 테스트는 input.focus()와 seller.focus()를 사용한다. 해당 지점 이후의 키보드 조작은 검사하지만, 페이지 처음부터 모든 컨트롤을 순서대로 Tab으로 찾아가는 경로 전체나 실제 모바일 키보드 조작을 입증하지 않는다.
2. browser.newContext()에 프로젝트 장치 옵션을 전달하지 않았다. mobile 프로젝트에서도 두 번째 문맥은 기본 옵션의 새 Chromium 문맥이다. 서로 다른 두 문맥의 저장소 분리는 검증하지만 두 모바일 문맥의 동일 기기 설정까지 검증한 것은 아니다. 현재 격리 검사 목적에는 지장이 없다.
3. 가로 넘침 검사는 scrollWidth 한 번 조회이고 메뉴 viewport 단언은 일부 가시성도 허용한다. 모든 링크의 전체 노출·터치 영역·화면 안정화 이후 레이아웃·스크린리더는 별도 범위다. 실제 Pixel7 기기 검증이라고 표현하면 안 된다.
4. 브라우저는 Vite 개발 서버에서 실행한다. React production build 검사가 따로 통과해도 빌드 결과물을 브라우저로 시연한 것과는 구분한다. 운영 프록시·TLS·배포 서버도 미검증이다.

이 관찰들을 해결하기 위해 현재 코드를 변경하거나 검사를 불필요하게 늘릴 필요는 없다. 완료 문서에는 현재 증거의 범위를 유지한다. 사용자 직접 실습·이해는 미확인이다. 개발세션에서 이 검토와 요약을 확인해 작업 상태 갱신 및 최종 로컬 커밋을 처리할 수 있다.
