## 범위와 결정

F05, AC05·AC07의 재고 모듈 계약을 구현한다. Java 공개 계약으로 예약·확정·해제·기한 도래 해제를 제공한다. HTTP/화면, 주문·결제·쿠폰, 만료 스케줄러, P05는 포함하지 않는다. 호출자는 신뢰된 서버 애플리케이션이며 향후 P08이 구매 자격·상품 판매 가능·주문/결제 상태를 확인해야 한다. 결제 PROCESSING/UNKNOWN이면 해제를 호출하지 않는다. 기본 15분 정책과 주문 잠금은 P08 호출자 책임이며 여기서는 전달받은 기한을 강제한다.

예약은 전역 reservationId, 주문항목당 유일 orderItemId, checkoutId, skuId, 수량1..999999999, expiresAt을 받는다. 기한은 PostgreSQL 정밀도에 맞춰 마이크로초로 정규화한다. 묶음1..100개, 같은 묶음의 예약/주문항목 중복은400이다. 같은 reservationId/같은 정규화 본문은 현재 저장 결과를 반환하고 재예약하지 않는다. 다른 본문/주문항목 충돌은409, 다른 checkoutId의 확정/해제는404다. 조회와 모든 전이는 checkoutId로 한정한다.

묶음 전체를 REQUIRED 트랜잭션으로 처리하고 SKU UUID 문자열 오름차순으로 잔액 잠금 후 예약 ID 문자열순으로 예약 행을 잠근다. 반환 순서는 입력 순서다. 호출자는 한 거래의 SKU/예약을 한 묶음으로 전달해야 하며 여러 호출을 다른 순서로 끼워 넣으면 전체 거래의 잠금 순서를 보장할 수 없다. 잠금 취득 뒤 DB clock_timestamp로 기한을 판단한다. RESERVED만 한 번 COMMITTED 또는 RELEASED가 된다. 같은 종착 상태 재시도는 무효과, 반대 종착 상태 요청은409다. 기한이 지난 확정은409, 만료 호출은 기한 도래 RESERVED만 해제하며 그 외는 무효과다. 명시적 해제는 기한 전후 모두 가능하다. 묶음 일부 실패 시 전체 rollback이다. expiresAt 허용 범위는 1970-01-01~9999-12-31T23:59:59Z이며 신규 예약의 기한은 잠금 후 현재 시각보다 미래여야 한다.

수동 조정 stock_movement의 의미/제약은 유지한다. 예약 변경은 별도 inventory_reservation_event에 원인(RESERVE/COMMIT/RELEASE/EXPIRE), 전후 잔액과 버전을 저장한다. 잔액·예약·이력은 하나의 거래다. 모든 실제 변경이 잔액 version을 증가시키므로 수동 조정 이력 사이 버전 간격은 정상이다. 외부 I/O와 자동 재시도는 수행하지 않는다.

E-R1 보완 결정: 신규 예약 묶음은 잔액 잠금 전에 두 전역 유일 키(reservationId/orderItemId)를 이름공간별 문자열로 만들고 PostgreSQL hashtextextended의 실제 bigint 값순으로 거래 advisory 잠금을 취득한다. 해시가 충돌하면 추가 직렬화만 발생하며 고유 제약과 본문 비교를 대체하지 않는다. 키→SKU 잔액→예약 행의 순서를 지키고 거래 종료 시 잠금을 자동 해제한다. 반환 순서는 입력 순서 그대로다. 호출자는 같은 거래에서 수동 조정이나 다른 예약 묶음을 선행 호출해 잠금 순서를 뒤집지 않아야 한다.

## 변경과 학습

- V18은 새 예약/예약 이력 테이블과 인덱스만 만든다. V17 잔액과 수동 이력을 수정하지 않으며 새 DB의 별도 schema에서 이행 전후 값·재실행0건을 검사한다.
- `Reservations` 공개 Java 계약과 `JdbcReservations` 구현을 추가했다. 외부 주문항목 UUID에는 아직 주문 테이블 FK가 없으며 향후 P08에서 실제 주문과 같은 거래로 연결한다.
- 상태 전이·가용 수량·version 조건부 UPDATE의 영향 행 수를 확인한다. 성공한 거래에만 감사 이력이 남는다. 신규 예약의 가용량 부족 또는 감사 저장 실패는 전체 거래를 복원한다.
- 학습 포인트: Java 메서드 호출이 성공했어도 바깥 REQUIRED 거래가 실패하면 잔액/예약/이력이 모두 되돌아간다. `reservationBatchesAndOuterTransactionRollBack`의 수량을 바꾸고 예상 잔액을 먼저 계산하는 실습을 제안한다. 사용자 직접 실습은 미확인이다.

## 남은 항목

필수 잔여 차단은 없다. 최초 독립 검토의 E-R1(역순 전역키 교착)·E-R2(고정 sleep 후 기한 조건 미충족)는 RED→보완→개발/독립 전체 하네스로 해결했다. E04는 실제 잠금 대기를 관측한 뒤 DB 현재 시각으로 검사 전용 기한을 도래시켜, 고정 sleep 가정 없이 잠금 이후 시각/예약 재조회와 확정409·잔액 유지·해제1효과를 검사한다. 최초 실패의 DB 시계 변동 등 세부 원인은 확정하지 않았으며 제품 만료 오류로 단정하지 않는다.
