## 확정 범위

이름·전화 입력, 현재 브라우저의 구매 세션, PURCHASE 용도의 전화 인증 시도와 일회성 결과를 구현한다. P06-A의 로컬 Firebase 제공자를 사용한다. 이름은 자기 입력이며 실명 확인이 아니다. 비밀번호·GuestBuyer·조회 자격(P06-C), 주문 저장·결제·실제 주문 트랜잭션(P08-C), 공개 배포는 제외한다.

구매 세션은 기존 HttpOnly/SameSite 세션 쿠키에 결합한다. 프로세스마다 무작위 256비트 키를 만들고 HMAC-SHA256(sessionId)로 서버 전용 자격을 유도한다. DB에는 자격과 브라우저 세션의 해시만 저장하며 자격은 JSON·쿠키·Spring Session 속성에 쓰지 않는다. 동일 브라우저의 동시 시작 요청은 동일 자격을 사용하고 DB 잠금 안에서 checkout을 초기화하여 응답/세션 저장 순서 역전으로 폐기된 자격이 남지 않는다. 프로세스 재시작은 제공자의 메모리 상태와 함께 기존 자격을 무효화하며 새 인증이 필요하다. 다중 인스턴스는 이 로컬 범위에서 지원하지 않는다. 구매 세션 30분, 업무 인증 시도 3분(제공자 5분보다 엄격), 번호별 재발송 60초/15분 3회/실패 5회, 출처별 15분 20회 제한. 원격 주소를 출처로 사용하며 X-Forwarded-For를 신뢰하지 않는다. 새 시작은 현재 checkout의 이전 시도 연결·인증 상태를 폐기한다. 이전 시도와 소비 시각은 이력으로 유지한다. 외부 제공자 호출은 DB 트랜잭션 밖에서 수행하고 전후 잠금·상태·시간을 확인한다. OTP와 제공자 토큰은 DB/로그/URL/영구 브라우저 저장소에 남기지 않는다.

## 실패 복구 계약

발급 후 새로고침은 같은 SENT 시도를 재개한다. 교환 응답 유실·SDK 중단·확인 중 서버/DB 실패는 중간 상태에서 자동 재전송하지 않고 새 인증을 요구한다(번호·출처 제한 유지). 확인 응답만 유실됐고 DB 저장이 끝났다면 GET으로 VERIFIED를 복구하되 확인 재전송은 거부한다. 외부 제공자 성공 후 DB 실패는 CONFIRMING 상태로 남고 소비할 수 없다. 내부 consume은 호출자 트랜잭션에 참여하여 rollback 시 소비 상태도 돌아오며 실제 주문 결합은 P08-C에서 구현한다.
