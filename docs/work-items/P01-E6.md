# P01-E6 ArchUnit 모듈 경계

2026-10-24 / 상태: 구현·자동 검증 완료 / 독립 검토 대기

## 범위와 결정

설계의 `<module>/api` 공개 계약과 web/application/domain/infrastructure 내부 경계를 검사한다. 현재 main 클래스는 앱 진입점과 platform뿐이며 업무 모듈은 없다. 업무 모듈을 만들거나 빈 계층을 추가하지 않는다.

- 다른 업무 모듈에는 api 패키지를 통해서만 의존한다. 모듈 이름 목록을 고정하지 않고 루트 바로 아래 패키지를 모듈로 인식한다.
- platform은 업무 모듈에 의존하지 않는다. 업무 모듈의 api는 자기 내부 구현·platform 타입을 계약에 노출하지 않는다.
- api/domain은 Servlet·Spring Web/JDBC/Security/트랜잭션·JDBC 타입에 의존하지 않는다. domain은 자신의 web/infrastructure에도 의존하지 않는다.
- 루트 바로 아래 패키지 간 순환 의존을 검사한다. platform도 포함한다. 앱 진입점처럼 루트에 있는 클래스는 모듈 slice 밖이다.
- 실제 main 출력 경로를 직접 import하며 빈 import·진입점 누락·테스트 클래스 포함을 검사한다. 별도 출력 경로에서도 작동해야 한다.

현재 업무 모듈이 없으므로 가상 Java 소스를 임시 디렉터리에 컴파일하여 허용/위반·api 경유 순환 의존을 검증한다. 제품 검사가 통과했다는 사실을 미구현 업무 모듈의 검증 완료로 해석하지 않는다.

ArchUnit core1.5.1을 test scope로 고정하고 기존 JUnit Jupiter에서 직접 호출한다. 별도 JUnit 엔진·제품 의존성·런타임 설정을 추가하지 않는다. [공식 릴리스](https://github.com/TNG/ArchUnit/releases/tag/v1.5.1)와 [공식 사용 안내](https://www.archunit.org/userguide/html/000_Index.html)를 참고하고 실제 JDK21/Boot4.1.1 조합에서 확인한다.

## 진행 순서

경계 규칙 없는 baseline에서 위반 fixture가 탐지되지 않아 실패하는 RED 확인 → 규칙 구현 → 실제 main/fixture 및 전체 Java verify → 검토 및 반영세션 독립 검토 → 결과·차단 항목·로컬 완료 기록. 공유 체크아웃과 기존 지정 검토 흐름을 유지하며 이 문서에 결정을 기록한다.

리플렉션·문자열 기반 호출·Spring 런타임 배선·SQL 테이블 소유권·분산 서비스 경계·프런트 경계는 검사하지 않는다. 기존 health·서버·DB 데이터는 변경하지 않으며 다음 단계는 진행하지 않는다.

## 구현과 검증 결과

제품 Java와 설정·health는 변경하지 않았다. pom.xml의 test scope ArchUnit core1.5.1과 테스트 코드3개를 추가했다. ModuleArchitectureTest는 MarketplaceApplication의 실제 CodeSource 디렉터리를 import한다. ModuleRules는 ArchUnit direct dependency를 이용한 경계 조건과 slices 순환 검사를 제공한다. ModuleRulesTest는 JDK 컴파일러로 @TempDir에 가상 클래스를 만들고 동일 규칙으로 허용·거부를 검증한다. 임시 클래스는 main/test 패키지에 추가하지 않는다.

## 시행착오와 미검증

첫 명령은 PowerShell의 쉼표 인용 오류로 실행되지 않았다. 테스트 선택 인자를 인용해 해결했다. [최초 fixture 실행](evidence/P01-E6-fixture-first.txt)은 public 클래스 파일명을 패키지명 전체로 만들어11개가 컴파일 실패했다. 디렉터리/단순 클래스명으로 바로잡은 뒤 위 RED를 별도로 확보했다. 최초 실패는 경계 탐지 성공으로 집계하지 않는다.

라이브러리 준비와 최종 검증은 허용된 실행 환경에서 성공했고 다운로드 차단은 남지 않았다. 로그의 Mockito 에이전트·의도된 health DOWN 경고는 실패가 아니다. 증거 로그는 행 끝 공백과 탭 들여쓰기만 정리했다.

기술 타입 금지는 명시한 Java/Jakarta/Spring 패키지와 Principal에 한정하며 모든 외부 프레임워크 타입을 탐지하는 것은 아니다. 바이트코드가 표현하는 의존을 검사하며 리플렉션·문자열·런타임 배선·SQL 소유권을 증명하지 않는다. 루트 클래스는 모듈 slice 밖이고 api 하위 패키지는 공개 범위로 간주한다. 다른 모듈 api를 통한 순환도 금지하므로 향후 업무 설계 시 계약 방향을 정해야 한다. frontend/Node/브라우저/실제 DB 연결 검사는 이번에 재실행하지 않았다.

## 보존·실행·학습

[보존 확인](evidence/P01-E6-preservation.json)에서 dev/test DB 정규화 덤프 해시가 E5와 동일했다. 무작위 restrict/unrestrict 토큰만 제외해 해시를 계산했고 원문은 저장하지 않았다. 컨테이너 ID·healthy·DB 포트 PID57168 유지, DB 쓰기·초기화·재시작 없음. 기존8080/4174/5174 리스너는 없었으며 임의 실행/종료하지 않았다. Java 회귀는 소유 RANDOM_PORT만 사용했다. 현재 차단 항목 없음.

프로젝트 JDK21을 JAVA_HOME, .local-tools/m2를 MAVEN_USER_HOME으로 해당 실행 프로세스에만 지정한다.

```powershell
./backend/mvnw.cmd -f backend/pom.xml "-Dmarketplace.build.directory=$PWD/.local-tools/e6-build" verify
```

Java가 컴파일되더라도 다른 모듈의 저장소를 직접 가져오는 설계 위반은 컴파일러가 막지 않는다. ArchUnit은 컴파일된 클래스의 의존을 읽어 이런 규칙을 테스트로 만든다. api는 HTTP URL이 아니라 모듈 사이에서 사용할 Java 계약 패키지다. 작은 실습: 허용 fixture의 catalog.api.Product를 catalog.domain.Product 참조로 함께 바꾸면 허용 사례 검사가 실패해야 한다. 실습 후 원복한다. 사용자 직접 실습·이해는 미확인이다.

E6 다음 단계·실제 업무 기능·push는 진행하지 않았다. P01 전체 최종 인수 여부는 별도이며 이번 결과로 자동 완료 처리하지 않는다.
