# P02-D — 회원 정지·복구·탈퇴

상태: 구현·검증·독립 검토 완료(2026-10-24). 기준 커밋 781cccc. 다음 단계는 진행하지 않았다.

## 범위와 결정

- 운영자 ADMIN + ACCOUNTS 권한으로 ACTIVE → SUSPENDED, SUSPENDED → ACTIVE. 사유(1~300자), 처리자, 대상, 전후 상태, 시각을 감사 기록한다. 같은 상태 중복 요청은 409다.
- 본인은 ACTIVE 상태에서 현재 비밀번호와 `WITHDRAW` 확인값으로 탈퇴한다. 대상 ID를 요청에서 받지 않는다. WITHDRAWN은 복구하지 않는다.
- 운영자 계정의 정지·탈퇴는 이번 API에서 409로 차단한다. 운영 권한 인계·최종 운영자 보호 절차는 별도 설계가 필요하므로 운영자끼리 잠그는 기능을 열지 않는다.
- 상태 변경, 인증 버전 증가, 전체 세션·복구/확인 토큰 폐기는 하나의 트랜잭션이다. 복구 후에도 다시 로그인해야 한다.
- 탈퇴 시 사용자 UUID와 생성 시각은 보존하고 이메일을 무작위 비식별 값으로 대체한다. 표시 이름·전화·배송지·로그인 자격·역할·권한을 제거한다. 같은 이메일로 새 가입은 가능하나 새 UUID이며 과거 거래를 연결하지 않는다.
- 실제 주문은 아직 없으므로 거래 보존은 사용자 참조 fixture로 검증한다. 향후 주문의 구매 당시 정보와 보관 기간은 거래 단계에서 별도 설계한다. 운영 적용용 법적 보관 정책을 확정한 것은 아니다.
- 정지 계정은 로그인 및 회원 API 전체가 막힌다. 판매 정지는 P03, 운영자 목록·통합 조치 화면은 P10 범위다. 이번 UI는 본인 탈퇴 화면만 추가한다.
- 기존 서버와 DB는 그대로 두고 매 실행 새 격리 DB에서만 상태 변경·이행을 검증한다.

## 작업 순서

1. 상태 변경 HTTP 계약 실패 테스트 → 서비스·감사 이력·세션 폐기 구현.
2. 잘못된 상태/권한/CSRF/비밀번호, 중간 실패 롤백, 참조 데이터 보존 검증.
3. 본인 탈퇴 화면과 세션 정리·오류·늦은 응답 검증.
4. 새 격리 DB·실제 브라우저 검증, 검토 및 반영세션의 독립 검토, 결과 기록.

## API

- POST `/api/admin/accounts/{id}/suspend`, `/restore`: `{reason}` → `{status: SUSPENDED | ACTIVE}`.
- POST `/api/account/withdraw`: `{password, confirmation: WITHDRAW}` → `{status: WITHDRAWN}`.
- 공통 JSON 오류·요청 ID 및 CSRF 유지. 성공 응답은 no-store. 자동 재전송하지 않는다.
- 탈퇴 비밀번호 시도는 IP+세션 주체별 1분 5회로 제한한다. 기존 인메모리 제한의 재시작·다중 인스턴스 한계는 유지한다.

## 재현

저장소 루트에서 기존 서버를 종료하지 않고 실행한다. 매번 새로운 evidence 경로를 지정한다.

```powershell
./backend/verify-db.ps1 -EvidenceDirectory .local-tools/p02-d-new-run -Offline -RunBrowser
./frontend/npm.ps1 run test:unit
./frontend/npm.ps1 run typecheck
./frontend/npm.ps1 run lint
./frontend/npm.ps1 run build
```

새 DB는 삭제하지 않는다. `-Offline`은 프로젝트 도구·의존성 캐시가 준비된 현재 환경 기준이다. 실제 외부 메일, Windows 이외 재현, 실거래 주문과 법적 보관 정책은 검증하지 않았다. 운영자 계정 인계와 판매 정지, 통합 관리 화면은 이번 범위 밖이다.

## 학습 포인트

상태 플래그만 바꾸면 이미 발급된 세션이 남는다. 회원 행을 잠근 트랜잭션 안에서 상태·인증 버전·세션·토큰·감사 기록을 함께 변경한다. 탈퇴도 사용자 행을 삭제하지 않아 미래 거래의 UUID 참조를 유지한다. React 화면 제한은 편의 기능이며 실제 권한과 본인 확인은 서버가 다시 검사한다.
