## 확정 범위의 세부 설계

### 공지·FAQ·배너와 권한

- 기존 CONTENT를 관리 권한으로 사용한다. `/api/admin/content/site-*` 계열은 현재 회원→세션→CONTENT 권한과 대상 version을 잠금 후 확인한다. ADMIN 역할만으로 허용하지 않는다. SYSTEM 사이트 설정/작업 관리와 분리한다. 관리 응답과 미리보기는 no-store다.
- 공개 화면은 `/notices`, 공지 상세, `/faq`, 홈의 현재 배너를 제안한다. 공지 제목/본문, FAQ 질문/답변은 plain text로 출력한다. 초기 길이는 제목/질문 120자, 본문/답변 10,000자 이내의 Unicode code point 기준으로 구현자가 일관되게 정한다. 배너는 이미지 1개·대체 텍스트·선택적 내부 이동 주소·정렬 우선순위를 갖는다. HTML/script 실행과 외부 추적 주소는 허용하지 않는다.
- 배너 이동 주소는 앱 내부 허용 경로로 제한한다. `//`, 스킴, 역슬래시, 제어문자, 인코딩 우회와 운영/인증 처리 URL을 거부한다. 공개 상품/행사 등 목적지가 나중에 비공개돼도 목적지의 현재 접근 검사를 우회하지 않는다.
- 게시 상태는 DRAFT/PUBLISHED/ARCHIVED를 제안한다. PUBLISHED라도 예약 시작 전/종료 이후에는 공개되지 않는다. 공개 일시 중단은 DRAFT 전환, 종료 보관은 ARCHIVED로 표현하고 물리 삭제하지 않는다. FAQ/배너의 정렬은 우선순위와 안정적인 ID 순서로 결정한다. 페이지 크기·필드 길이 등 기존 계약 안의 기술값은 Sol이 확정해 기록한다.
- 작성/편집/게시/중단 명령은 요청키·예상 version·정규화 본문·사유를 결합한다. 동일 재전달은 동일 영수증, 다른 내용/오래된 version은 409, 실패 시 변경/감사/명령 기록이 함께 rollback된다. 변경 이력은 작성자·시각·이전/새 version과 내용을 append-only로 보존한다.

### 예약 시각과 미디어

- UTC 저장·한국 시각 입력/표시, 시작 포함·종료 제외다. 종료는 시작보다 뒤여야 한다. 시작 없는 즉시 게시는 서버의 현재 시각으로 정하며 요청 재시도에서 같은 명령 결과를 보존한다. 종료 없음은 무기한 공개다.
- 공개 목록·상세·이미지 접근이 **현재 DB 시각+상태+현재 연결 버전**을 직접 검사한다. 예약 공개를 위해 worker 실행 성공에 의존하지 않는다. 따라서 별도 예약 job은 필수 구현이 아니다. 추가하는 경우 대상 version·현재 기간을 검사해 옛 예약 작업이 수정/중단 내용을 다시 공개하지 못해야 한다.
- 기존 `Media`는 products/stores에 결합돼 있다. 배너를 기존 판매자 이미지로 위장하지 않는다. operations가 대상/권한/공개 기간을 소유하고 media는 새 공개 `SiteImages` 계약(이름 제안)으로 파일 정규화·저장/읽기를 제공한다. 다른 모듈 infrastructure에 직접 의존하지 않는다. 기존 `MessageImages`의 호출자 대상 잠금 유지 방식은 참고 가능한 패턴이다.
- 기존 `ImageNormalizer`의 JPEG/PNG/WebP, 5MiB, 가로/세로 4096 이하·16M 픽셀 제한 및 PNG 재인코딩을 재사용한다. 확장자/MIME 주장만 믿지 않는다. 비정상 파일·과대 픽셀·경로 입력·빈 alt를 거부한다.
- DRAFT/미래 예약/종료/ARCHIVED/교체된 이미지의 직접 asset URL은 공개되지 않는다. CONTENT 미리보기는 현재 권한으로 별도 검사한다. 공개 이미지는 정확히 현재 게시물과 연결된 asset만 반환한다. 업로드/DB rollback·교체 경합에서 원 asset을 삭제하지 않고 새 고아 파일도 즉시 정리하지 않는다. 과거 파일 보존과 공개 접근 차단을 구분한다.

승인된 A 적용 계약: 새 정책 버전의 commit 이후 새 견적에 적용하고 예약 정책 변경은 추가하지 않는다. `QuoteCalculator.shipping`과 `JdbcQuotes`의 현재 고정값을 소유 모듈의 typed 공개 정책 소비로 연결한다. 신규 정책 버전·값을 견적 fingerprint에 포함하며 checkout 최종 재계산과 정책 변경의 잠금/직렬화 순서를 명시한다. 옛 견적은 변경 내용 표시와 409/재확인을 거쳐 새 주문을 생성한다. 이미 생성된 주문의 policyVersion·상품/배송비·할인 배분·회수비·확정/환불/정산 원인은 불변이다. 과거 정책 버전은 수정하지 않는다. 허용 정수 범위와 0원 의미는 A 선택 취지 안에서 입력/금액 안전성 기준으로 기록하며 새로운 금융 규칙을 임의 추가하지 않는다.

미선택 B는 비교 이력으로만 유지하며 이번 구현 범위를 대신하지 않는다. 사이트 이름/지원 안내 같은 비금전 설정은 실제 소비 화면에 연결하고 입력 제한·append-only 이력을 검증한다.

### 안전한 작업 관리

- SYSTEM은 실패/진행 상태의 작업 ID·타입·시도 횟수·예약/다음 실행 시각·안전한 오류 코드·관련 업무 동작을 본다. principal/세션/현재 SYSTEM을 재검사한다. 임의 payload·토큰·연락처·비밀 본문·결제 비밀값은 응답/로그에 넣지 않는다. 유형별 설명과 현재 가능한 조치를 표시한다.
- platform은 안전 메타 조회 공개 포트를 제공하고 각 업무 소유 모듈이 재처리 가능 여부와 명령을 제공한다. `Jobs.failed(limit)`를 그대로 외부 직렬화하면 Command.payload가 포함되므로 금지한다. 페이지/필터 조회는 읽기 전용이다.
- 알림은 C의 `NotificationRetries`와 같은 사건·실패 job 결합, 대시보드는 D의 새 refresh 요청, 환불은 기존 SYSTEM 조회/대사 화면으로 연결한다. UI 연결만으로 완료하지 않고 실제 원 명령의 성공·중복·권한·보존까지 검사한다. 필요한 공개 포트 보완은 기존 infrastructure 직접 호출 대신 소유 api로 한다.
- 범용 FAILED→READY/attempts=0, 임의 type/payload 복제와 원 cause 분리는 금지한다. 미지원 타입은 읽기 전용과 이유를 표시한다. UNKNOWN 환불은 조회 전용·예약 유지, 실제 Toss 차단을 유지한다. 지원 재처리도 기존 효과 멱등성·lease·요청키·현재 상태·원인 이력 검사를 통과해야 한다.
- 새 재처리 요청은 operator·사유·요청키·원 실패와 새 작업을 기록한다. 기존 실패 행·시도 이력은 보존하며 금융/알림 원 효과를 중복 생성하지 않는다. C/D의 기존 명령 의미를 E가 재정의하지 않는다.

## UI → API → 데이터와 제공·소비 영향

첫 연결은 CONTENT 공지 작성→공개 GET→공개 페이지→중단 후 직접 URL 차단이다. 같은 업무 묶음에서 권한·예약·이력·복구를 완성하고 FAQ/배너·정책·작업까지 전체 완료표로 관리한다.

operations 소유에 게시물 현재 상태/버전, 내용 revision, 명령 영수증·변경 감사, typed 정책 버전을 제안한다. media는 asset과 정확한 게시 버전의 연결을 소유 계약에 맞춰 보관한다. 물리 삭제 endpoint와 원주문 일괄 UPDATE는 없다. 실제 테이블/마이그레이션 번호는 D 커밋 트리 확인 후 Sol이 정한다. DB 제약을 도입하면 직접 위반 assertion까지 포함한다.

## Sol 진입 계약과 검토·인계

1. 부모의 D 커밋 마감 완료 및 현재 트리·범위 밖 `.codex/` 확인 후 기존 Sol이 **공지·FAQ·배너·미디어·작업 관리**부터 착수할 수 있다. 이 문서 작성은 제품 구현 사실이 아니다. A가 승인됐으므로 typed 배송 정책 버전·견적/checkout 소비도 같은 E 범위에서 착수할 수 있다. SYSTEM 외 편집이나 두 항목 이외 금전 정책 확장은 금지한다.
2. 승인 범위의 DTO/필드 길이·테이블 이름·순서·공개 포트·오류 표현은 Sol이 자율 구체화한다. 새 금전 규칙·소급 변경·권한 확대·보존 삭제가 발견되면 그 결정만 부모에게 올린다. 구현 내부 helper마다 승인/검토 게이트를 만들지 않는다.
3. 최소 실제 UI/API/DB 연결과 필수 권한·기간·미디어 또는 정책 경합 위험의 assertion이 준비된 때 지정 세션에 필요한 중간 판단을 요청한다. 전체 완료표를 축소하지 않는다.
4. 최종 소스 고정·영향표·무선택 및 필요한 후속 결과·실패/보존 감사가 준비되면 기존 독립세션이 같은 소스와 원보고서를 대조한다. 필수 누락/skip/결함/근거 부재는 수용을 차단한다. 과거 결과를 현재 정책으로 소급 변경하지 않는다.
5. 인계에는 게시/미디어 공개시각·정책 적용/기존 주문 보존·업무별 재처리 허용범위·읽기전용 타입·현재 권한·소스 및 실행 경로·미검증·실패 이력을 남긴다. E 수용 이후에도 E 커밋·푸시·배포·P12는 진행하지 않는다.

## 이번 설계 확인

지정 세션이 요구 F16·계획 §13, 선행 D 인계, 현재 AccessArea/Media/ImageNormalizer/Jobs/NotificationRetries/환불 대사·견적 코드를 읽기 전용 대조했다. 기존 brainstorming의 요구/대안 비교 원칙을 기존 단일 작업 문서에 적용하며 새 계획 트리나 세션을 만들지 않았다. 이 문서 외 파일은 수정하지 않았고 기능 검사·DB/서버 명령·커밋은 실행하지 않았다. 사용자 A 승인으로 중요한 미결은 해소됐다. Sol에 기존 권한·신규견적/주문 전향 적용·기존 거래 불변을 구현 계약으로 인계한다.

## 구현 진행 · 첫 집중 검증 준비

이하 각 실행 절의 대기·예정 표기는 그 실행 당시 상태다. 현재 판정은 상단과 전체 완료표에 기록한다.

Sol이 entry HEAD ecca418에서 설계를 인수했다. 배송정책과 SYSTEM 관리 API를 promotion이 소유한다. 일반 견적은 RR에서 잠금 없이 정책을 읽고 checkout은 기존 쓰기 거래에서 정책 head 공유 잠금 후 해당 버전을 계산한다. 최초 버전은 기존 P07-C-1 지문을 유지한다. 공개 사이트 게시·시각·asset 귀속은 operations, 파일 정규화와 저장은 media, 작업 메타 조회는 platform 공개 포트가 소유한다.

V130 배송 정책, V131 게시 revision·사이트 안내, CONTENT 작성/공개 조회/중단과 SYSTEM 설정·작업 화면을 연결했다. 이행 계획 현재 버전은 131이다. site-management 첫 두 검사는 실제 HTTP 게시와 이전 버전 재전달, 실제 주문·환불 후 정책 변경과 원행 보존을 확인하도록 등록했다. 현재 이 두 DB 본문과 브라우저는 실행 전이다. 배너·시각 경계/권한 경합/DB 불변·rollback/정책 checkout 경합/업무별 후속 처리/화면 수명·브라우저 필수 근거는 진행 중이다.
