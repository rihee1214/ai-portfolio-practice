## 범위와 정적 확인

개발세션의 사용자 직접 승인 `01a16d8a-8914-73d0-bc74-e81fe118635f`와 [작업 문서](P03-C.md)를 확인했다. 기존 매대의 정지·복구·폐점과 기능별 제한을 검토한다. 제품·테스트는 개발세션이 담당하고 이 세션은 검토 문서를 담당한다. 기존 서버 및 모든 DB 보존, 다음 단계·커밋·푸시 금지 조건을 유지한다.

- 운영 조치는 ADMIN+ACCOUNTS, 폐점은 본인 ACTIVE SELLER로 구분한다. 자기 매대 운영 조치는 거부한다. 경로의 action도 허용 목록을 검사한다.
- 회원→매대 잠금 순서로 읽은 version과 현재 상태를 확인한다. OPEN→SUSPENDED, SUSPENDED→OPEN 및 OPEN/SUSPENDED→CLOSED만 허용하며 CLOSED는 종결이다.
- 상태·visible=false·version 증가와 사유/처리자/전후 상태 이력 INSERT는 같은 트랜잭션이다. V10은 제한 상태의 공개를 DB 제약으로도 차단한다. 복구 후 공개를 자동 복원하지 않는다.
- 매대 변경은 회원 상태·역할·세션을 갱신하지 않는다. 공개 조회는 OPEN과 visible 및 ACTIVE SELLER 조건을 요구한다. 기존 본인 조회는 유지하고 편집은 OPEN으로 제한한다.
- 미래 업무 변경용 requireCapability는 호출자 트랜잭션을 요구하고 회원·매대를 잠근다. NEW_SALES는 OPEN+visible, MANAGE_CATALOG는 OPEN, EXISTING_TRADES는 매대 존재 조건이다. 현재 실제 상품·거래 API를 구현한 것은 아니다.
- React 운영 변경/폐점은 CSRF와 읽은 version을 전송하며 자동 재전송하지 않는다. 폐점은 사유와 복구 불가 확인을 받는다. 인증 변경 시 보호 화면이 사라지고 store의 세대 검사로 늦은 응답을 무시한다.
