## 착수 당시 기존 계약과 이후 사용자 확정 사항

[설계 §12](../shop-design.md#12-정산알림대시보드)에는 주문 확정·발송·문의 답변·운영 조치가 열거돼 있으나 각 사건의 수신자와 발생 시점까지 확정돼 있지 않다. [P10-E 인계](P10-E.md)는 안정 원인·대상·세대와 현재 공개 권한을 제공하며, 비밀 원문·이미지를 알림에 복제하지 않는다. 이 보안 계약은 재승인 대상이 아니다.

| 정책 항목 | 실제 계약 차이 | 사용자 승인안 |
| --- | --- | --- |
| 주문 확정의 의미·수신자 | `ORDER_CONFIRMATION_RECORDED`는 결제 완료가 아니라 직접/자동 구매확정 사건 | 결제 완료는 구매자와 해당 매대 판매자, 구매확정은 해당 매대 판매자에게 구별해 통지 |
| 발송 범위·비회원 | `SHIPMENT_CREATED`는 발송 준비에서도 발생하므로 실제 발송 통지 근거가 아님 | 일반·분할·교환 재출고의 실제 발송 완료를 회원 구매자에게 통지. 비회원 알림함은 제외하고 기존 주문 조회 유지 |
| 문의 답변 | 상품 문의와 거래지원 대화는 당사자·담당·접근 계약이 다름. LOST_ACCESS는 확정 소유자 없을 수 있음 | 상품 답변은 작성자, 거래지원 새 답변은 열람 가능한 상대 당사자에게 통지. 자기 답변/내부 기록/수신자 불명 접수 제외 |
| 운영 조치와 복원 | 신고자와 대상 소유자의 공개 범위가 다름 | 조치·복원 결과는 대상 소유자, 신고 종결은 신고자에게 일반 문구만 통지. 비밀 사유·증거 제외 |

## 착수 당시 변경·전달 계약과 예정 assertion

아래 예정표의 상태는 첫 제품 수정 전 기록이다. 현재 판정은 위 전체 완료표와 아래 full1 원근거를 따른다.

기존 `JdbcOutbox`는 사건 하나를 작업 하나와 연결하며, `WorkerEngine`은 유형당 한 핸들러를 등록한다. 기존 구매확정 등 소비자를 교체하거나 원 업무를 재실행하는 방식은 사용하지 않는다. 승인 후 알림 전용 안정 사건과 수신자 키를 같은 업무 트랜잭션에 연결하고 기존 임대·재시도 계약을 재사용하는 상세 설계를 확정한다.

| 제약 | 예정 자동 assertion·기대 결과 | 실행 근거 |
| --- | --- | --- |
| 실제 생산자와 원자성 | PostgreSQL: 실제 업무 커밋 후 알림 1건, 업무 롤백 후 0건 | 미구현/미실행 |
| 중복·동시·ACK 유실·재시작 | JUnit 및 PostgreSQL: 사건/수신자 유일성, 저장 후 재전달에도 1건·읽음 시각 유지 | 미구현/미실행 |
| 모듈 경계 | ArchUnit: 공개 API 소비, 타 모듈 저장소 직접 접근 없음 | 미구현/미실행 |
| 본인 알림·현재 대상 권한 | PostgreSQL/API: 타인 목록·읽음 거부, 자격 상실 후 대상 정보 노출 0 | 미구현/미실행 |
| 화면 수명·실제 통합 | 프런트 단위/브라우저: 로그아웃·권한 회수·늦은 응답 폐기, 좁은 화면에서 실제 생산자 알림 조회·읽음 | 미구현/미실행 |

정확한 검사명·필수 목록·등록 소비 영향은 정책 확정 후 구현과 함께 연결한다. 현재 문서와 소스 대조만 수행했으므로 JUnit·ArchUnit·DB·프런트·브라우저는 실행하지 않았다. 공유 스키마 등 전체 조건에 해당하는 제품 변경 후에는 새 경로에서 선택 옵션 없는 `./verify.ps1 -Offline`을 실행한다. 실패 수정은 실패 검사와 영향 범위만 재검증하고 유효 근거를 재사용한다.

기존 서버·DB·미디어를 변경하지 않았다. 기존 증거와 실패 기록, F07/G08 실제 Toss 차단을 유지한다. 이번 착수의 해시 대조는 자원 보존 하네스나 기능 검증을 대신하지 않는다. 이메일·문자·외부 푸시, P11-D 이후, 커밋·푸시·배포는 제외한다. 제품 변경과 최종 수용·인계는 아직 없다.

## 첫 집중 실행 이후의 구현·검증 기록

시행 후 실제 업무에서 생성한 사건부터 처리한다. 접근 권한이 사라진 대상은 목록·건수·링크에 포함하지 않으며 기존 읽음 시각을 보존한다. SYSTEM은 실패한 알림의 전달만 사유와 함께 재요청할 수 있다. 수신자와 원래 사건은 고정하고 성공한 작업과 원 업무는 다시 실행하지 않는다.

운영자가 입력한 내부 감사 사유와 대상자용 공개 안내를 분리한다. 공개 안내가 없는 과거 조치는 NULL을 유지한다. 공개 안내를 생략한 기존 명령도 수용하고, 같은 명령 키로 안내 내용을 바꾸면 충돌로 처리한다. 대상 상세에서 현재 소유자와 대상 판본을 검증하고 고객지원 이의제기 경로를 제공한다. V127 기준 계획 버전은 LegacyIT와 공통 이행 helper 양쪽에서 127로 맞췄다.
