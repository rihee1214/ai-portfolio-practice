# P13-D 반품 환불 실행 경계 결정

**결정은 모듈형 모놀리스 유지다.** 구매자 동의와 금융 예약을 한 트랜잭션에서 처리하고, 제공자 제출·조회는 기존 worker가 맡는다. 실험처럼 짧게 실행하는 worker의 JVM 기동 옵션을 내부 개선 후보로 남긴다. 운영 기본값 변경이나 독립 서비스 구축은 별도 판단이 필요하다. 결정 시점 HEAD는 `027bf6245d39a486ecafb6b5f07783e58307b75a`다. [구현 계획 §15~16](../implementation-plan.md#15-p13-문제-재현과-기준-측정) · [MSA 전환 설계](../msa-evolution.md)

## 실측이 뒷받침하는 범위

P13-A에서는 구매자가 반품 견적에 동의한 뒤 첫 worker가 준비 상태를 커밋하고 제공자에 제출하기 전에 종료됐다. 다른 프로세스가 같은 작업을 두 번째로 선점했다. 자동 조회·환불 결과 기록·반품 재개 작업이 각각 성공했어도 모의 제공자 제출과 효과는 0건이었다. 결제 43,000원 중 견적·시도·환불 예약은 각각 7,000원, 회수비 예약은 3,000원, 확정 환불은 0원이었다. 같은 환불 시도 한 건이 `UNKNOWN`, 반품이 `REVIEW_REQUIRED`, 상품 보류가 `ACTIVE`로 남았다. 이 상태가 재현한 장애의 올바른 업무 결과다. [P13-A의 독립 재현과 DB 대사](P13-A.md)

| 같은 업무·장애에서 측정한 중앙값 | 기본 JVM (B) | 짧게 실행하는 두 자식 JVM에만 단계 1 적용 (C) |
|---|---:|---:|
| 재시작 요청부터 재인수 worker 종료 | 4.245초 | 2.967초 |

| 견적 시작부터 동의와 작업 등록 확인 | 370.586ms | 364.765ms |
| 복구 worker 종료부터 후속 결과 관측 | 154.132ms | 156.466ms |

각 조건에서 새 DB·미디어·JVM으로 워밍업 1회와 직렬 측정 3회를 실행했다. C는 재시작 구간을 30.11% 줄였고 매회 위 금액·상태를 지켜 사전에 정한 내부 후보 기준(중앙값 10% 이상 단축)을 충족했다. 복구 worker가 종료된 뒤 결과를 관측하기까지는 2.334ms 더 걸렸다. 부모 JVM에서 잰 구매자 명령 시간 차이는 자식 옵션의 효과로 돌릴 수 없다. DB 표본에서 잠금 대기는 관측되지 않았다. 동시 업무는 한 건이었고 lease 만료 시각은 실험 시계로 넘겼다. 운영 장애 감지 시간, 브라우저 왕복, 상주 처리량·CPU, 실제 Toss·송금, 독립 배포에 따른 격리 효과는 미측정이다. 서로 다른 시점에 측정한 세 표본으로 운영 p95·p99 또는 서비스 분리 효과를 추정하지 않는다. ## 유지할 책임과 조건부 분리 후보

현재 구매자 동의는 권한·견적 지문·기대 버전·요청 키를 검사한다. 반품·비용 평가, 결제 환불 예산 예약, 시도 생성, 비용과 시도의 연결, 동의 영수증 및 제출 작업 등록을 같은 DB 트랜잭션에 묶는다. 작업을 선점한 worker는 제공자 호출 전에 준비 상태를 저장하고, 호출 뒤 소유 토큰을 확인해 결과를 반영한다. 반품 소비자는 환불 시도와 결과 버전, 견적·비용 평가를 대조한 뒤 반품 상태를 갱신한다. [동의 트랜잭션](../../backend/src/main/java/com/example/marketplace/claim/infrastructure/JdbcReturnFinances.java) · [환불 예약·실행](../../backend/src/main/java/com/example/marketplace/payment/infrastructure/JdbcRefunds.java) · [반품 결과 소비](../../backend/src/main/java/com/example/marketplace/claim/infrastructure/ReturnFinancialWorker.java)

향후 독립 배포가 필요한 증거가 생기면 **제공자 제출·조회와 그 실행 기록**만 먼저 검토한다. 다음 표는 그 경우의 쓰기 권한 제안이다.

| 단일 쓰기 주체 | 소유 데이터와 계약 |
|---|---|
| 모놀리스의 반품 모듈 | 견적·동의 영수증·회수비·반품 상태를 소유한다. 금융 결과를 소비할 때 주문 모듈을 통해 원 주문 단위와 보류 상태를 조회·대사하고 반품 전이를 판단한다. 기존 React API와 구매자 권한 검사를 유지한다. |

## 재검토·중단·복귀 기준

1. **재검토 조건.** 운영과 유사한 부하에서 복구·처리 지연 목표를 내부 대안으로 충족하지 못하거나, 공동 배포 때문에 구매 업무까지 중단된 변경 사례가 반복되면 해당 지연 분포·건수·영향 시간과 자원 비용을 기록한다. 독립 자원 제한이나 독립 릴리스가 그 원인을 줄일 수 있는지, 같은 복제 수·감지 주기·부하의 모놀리스 대안과 비교한다. 서비스 분리는 배포·부하 격리 효과를 기대할 수 있지만 전용 DB, 인증, 재전달, 대사, 관측·복구 운영 비용도 함께 발생한다.
2. **성공 기준.** P14 착수 전 사용자와 목표 지표·허용 지연·비용을 정한다. 같은 장애에서 개선된 모놀리스와 비교해 해당 목표를 달성하고, 반복·중복·지연·역순·재기동 때 시도와 제공자 효과의 중복 0건, 예약·확정·원장 대사 차액 0원, 미확정 보류 해제 0건이어야 한다. 위 제출 직전 장애 입력에서는 제출·효과 0건과 동일한 검토 대기 상태까지 재현해야 한다. 기존 구매자 API 회귀, 전환 후 생성된 건을 포함한 복귀 검증도 통과해야 한다.
3. **실패와 중단.** 금액·귀속 불일치, 두 호출 주체의 동시 제출, 미확정 결과의 성공 처리, 복구되지 않은 이벤트 누락이 한 건이라도 있으면 전환을 중지한다. 정합성이 맞아도 합의된 성능·격리 목표 미달이나 운영 비용 초과이면 확대하지 않는다. C에서 충족한 10%는 내부 후보의 실험 기준이며 P14의 목표는 별도로 정한다.
4. **복귀.** 지금의 실험 옵션은 다음 격리 실행에서 옵션을 제거해 기본 JVM 조건으로 돌아갈 수 있다. 향후 읽기 비교 단계에서는 원본 조회로 돌린다. 실제 제공자 쓰기를 넘긴 후라면 신규 전달을 보류하고 기존 호출자를 차단한 뒤 마지막 처리 위치를 기록한다. 전환 전후의 시도·원인·멱등키별 요청/응답·결과 버전을 기존 실행 경로로 역이행하거나 재생한다. 진행 중·응답 유실 건은 제공자 증거를 조회해 중복 제출 없이 조정한다. 결제별 예약·확정·원장, 반품별 회수비·보류·결과, 처리 위치와 미처리 건을 대조한다. 차액 0원·누락/중복 0건 및 모든 미확정 건의 보류와 재조회 책임을 확인한 뒤 기존 worker 하나에 호출 권한을 넘긴다. 대사 불가능한 건은 보류·검토 상태에서 전진 복구한다. [데이터 일치와 되돌리기 원칙](../msa-evolution.md#9-되돌리기와-데이터-일치)

P13-D의 산출물은 위 결정 기록이다. AC19 중 로컬 문제 재현·모놀리스 전후 수치·조건부 대안 비교 근거를 제공한다. 실제 서비스의 같은 조건 전후 측정과 AC20 분산 장애 복구는 P14에서 확인할 사항이다. **P14는 착수하지 않는다.** 재검토 자료와 명시적인 사용자 승인이 있을 때 P14-A부터 경계·계약 설계를 검토한다. [수용 기준 AC19·AC20](../requirements.md) · [P14 계획](../implementation-plan.md#16-p14-msa-전환과-비교-검증)

## 검증과 독립 검토

현재 HEAD와 이전 인계의 `35d20f5`는 같은 Git 트리 `fba516183401c717cf2096f01975602c0a4c930d`를 가리킨다. A·B·C 작업 문서의 SHA-256을 각각 독립 검토 기록과 대조했다. C 실행 manifest에 담긴 1,119개 파일이 현재 소스와 일치했고, 비교 원자료의 SHA-256은 `7f57e39eaae8c26ba9e01e8e07b9b7d30054dc20c6b78cab4ac579dae6dcfc2f`였다. 이번 변경은 결정 문서 한 건으로 한정해 링크·금액·측정 구간·소유권·작업 트리를 정적으로 확인하고 기존 격리 실행을 재사용했다.

설계 작성과 독립 검토는 서로 다른 `gpt-6.2-astra` Medium 담당자가 맡았다. 독립 검토의 필수 보완은 1회 1건이었다. 주문이 상품 보류를 쓰고 반품이 이를 조회·대사한다는 계약으로 소유권 표를 수정했다. 권고에 따라 후속 결과 관측이 늦어진 구간도 복구 worker 종료 이후로 한정했다.

최종 문서의 SHA-256, 보완 사항의 재검토 판정과 잔여 건수는 [독립 검토 기록](../../.local-tools/p13-d-independent-8e545234695a491a802643a5836d9d77/review.md)에 남긴다.
