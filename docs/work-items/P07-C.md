# P07-C 서버 견적·배송비·할인 배분 — 구현 작업 계획

> **For agentic workers:** 구현 요청 시 `superpowers:executing-plans`를 사용해 아래 작업을 순서대로 수행한다. 단계 전체 개발 통과 후 지정 검토세션에서 독립 검토한다. 이 문서 작성만으로 구현·다음 단계·커밋을 시작하지 않는다.

**Goal:** 서버가 최신 판매 정보와 혜택으로 결정적인 견적을 만들고 모든 항목·수량·판매자·부모 합계를 일치시킨다.

**Architecture:** 설계의 promotion 모듈이 혜택 데이터와 계산을 소유한다. 기존 identity/seller/catalog 공개 API로 권한과 판매 정보를 확인하고, React는 서버 결과와 입력 상태를 표시한다. 거래 경계·정수 계산·현재 권한 검사를 서버에서 보장한다.

**Tech Stack:** 기존 Java·Spring Boot·Spring JDBC·PostgreSQL·Flyway·JUnit·ArchUnit, React·TypeScript·Vitest·Playwright. 새 프레임워크를 도입하지 않는다.

**Spec:** [요구사항](../requirements.md), [설계](../shop-design.md), [구현 계획](../implementation-plan.md), [P07 공통 계약/검증 절차](P07.md). F08·F07 및 F09 선행 견적, AC03·AC09·AC13, requirements §8, shop-design §8.

상태: 개발 전체 및 독립 전체 검증 완료. 최종 근거는 아래 기록과 P07-C-review.md를 따른다.

## 입력·출력·실패 계약

계획 계약은 `Quotes.calculate(UUID memberOrNull, List<LineRequest> lines, List<CouponSelection> coupons): Quote`다. LineRequest=(skuId, quantity), CouponSelection=(storeId, issuedCouponId). 중복 SKU/매대 쿠폰 선택은400으로 거부한다. client 금액·할인·정책 버전으로 계산하지 않는다. 익명도 공개 견적을 받지만 쿠폰 선택이 있으면 서버가 거부한다. 전체 선택 최대20 SKU, 수량1~99, 현재 공개 판매/가용 수량을 검증한다. 견적은 재고·쿠폰·전화 인증을 소비하지 않는다.

Quote는 policyVersion/evaluatedAt, 상품/SKU/혜택의 id+version, 항목 정가/행사/쿠폰배분/순액, 매대별 기본배송/배송할인/총액, 부모 합계와 선택 이유를 포함한다. P08에 전달할 비교 fingerprint는 정규 순서의 금액 결정 입력/버전으로 만들고 evaluatedAt 자체는 제외한다. 변조 방지 토큰이나 주문 권한으로 취급하지 않는다.

안정적 항목 ID는 중복 없는 skuId의 정규 문자열 순서, 수량 단위는 ordinal 0..quantity-1로 제안한다. 항목별 floor(쿠폰액×행사후금액/대상합계) 후 잔여 원을 ID순으로 1원씩 배분한다. 합계0이면 할인0으로 분기한다. 단위배분도 같은 방식으로 원금·행사/쿠폰액·순액을 보존한다. 중간 곱셈은 BigInteger/checked 연산으로 오버플로를 막고 최종 long 범위를 검사한다. JSON 금액은 십진 문자열로 전달해 JavaScript 안전 정수 초과 손실을 막는 안을 적용하며 프런트 합산/표시도 정수로 처리한다.

예정 POST `/api/quotes`는 CSRF를 유지하고 개인 쿠폰 포함 응답은 no-store다. `/checkout`에는 조회 시점 견적·할인 근거·재확인 버튼을 표시한다. 실제 주문 생성 버튼/결제 완료를 추가하지 않는다. A의 상품 할인 선택과 배송 행사 선택은 C가 동일 규칙으로 호출하며 별도 UI 계산을 만들지 않는다.

## 실행 전 계약 점검 — B 전체 검증 대기 중

C 구현은 B 독립 전체 통과 후 시작한다. 현재 Browse.Offer에는 SKU ID/가격/가용량만 있으므로 견적 전용 QuoteOffer 읽기 API에 상품/매대 UUID와 상품/SKU/매대 version 및 표시명을 제공한다. 기존 탐색/장바구니 DTO를 깨지 않는 추가 계약으로 구현한다.

- Ruling: 서버 내부 Quote 금액은 long 값 타입이며 HTTP 응답에서 금액만 명시적인 십진 문자열로 변환한다. 프런트는 BigInt로 검증·표시하고 Number 합산을 최종 견적으로 사용하지 않는다. 기존 장바구니 준비 내역은 참고 상품 금액이고 신규 서버 견적과 구분한다.
