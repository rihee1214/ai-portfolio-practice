# P09-E 동일 가격 교환·재고 예약·재출고

상태: **계획 문서 독립 검토 반영 / 구현·검증·구현 독립 검토 미착수**, 2026-10-30.
목표: 원품 회수와 교환 재고를 별도로 추적하며 중복 출고 없이 교환 또는 환불로 수렴한다.
요구사항: F11·F12, AC09·10의 교환 부분. [공통 계약](P09.md)과 D 개발·독립 전체 통과가 선행이다.

## 상세 계약과 변경 위치

소비: B 클레임 보류·기한, C 환불 전환, D 회수/검수, A 분할 배송, inventory 공개 예약. 생산: 원 주문항목/교환 SKU/예약/교환 Shipment/반환 이력이 연결된 Exchange.

- 동일 가격 SKU만 허용하며 추가 교환 배송비는 판매자 부담. 가격 차이는 반품·재주문 안내로 끝내고 추가 결제를 자동 생성하지 않는다. 동일 가격의 비교 기준(원 스냅샷과 대상 SKU 기준), 예약 기한/연장 횟수·회수 지연 시 선택은 설계에 미확정이므로 **E1 Astra 판단 게이트**에서 정한다. P08 주문예약15분을 교환에 자동 적용하지 않는다.
- 승인 때 새 SKU 재고 예약. 회수·검수 이후 원품 판매 가능 수량 입고와 교환품 예약확정/출고를 별도 원인으로 기록한다. 교환품을 신규 구매 매출로 중복 계산하지 않는다.
- 품절/예약 실패는 승인 성공으로 표시하지 않는다. 회수지연·검수실패·기한만료는 사유/재고 점유 상태를 보존하고 확정 정책에 따라 반려 또는 C 환불로 전환한다. 전환과 재출고 경합 한쪽만 성공, 취소된 교환예약은1회 해제한다.
- 교환 출고는 원 shipment를 덮어쓰지 않고 원 claim·원 단위·대상 SKU/수량에 연결한다. 원품 입고와 교환 출고 수량을 상쇄해 이력을 지우지 않는다. 후기/정산용 원주문 식별자는 유지한다.

E1은 H05를 다음 항목까지 확정해야 한다. 원 구매의 `inventory_reservation.order_item_id`는 전역 UNIQUE이며 COMMITTED 기록이 남는다. 교환 목적의 예약 식별자·원 `(orderItemId,ordinal)` 연결과 신규 포트/migration 책임을 분리해 설계하고 원 예약의 키/상태를 덮어쓰거나 UNIQUE를 단순 제거하지 않는다. 현재 `Reservations`에는 연장 API가 없으므로 연장/재예약의 생성 주체·새 키/같은 키 조건·멱등성·기한 경계와 기존 P04-E 회귀를 명시한다.

대체 SKU는 원 판매자/매대 귀속을 서버에서 확인한다. 동일 가격만으로 타 매대 재고를 예약하지 않는다. 대상 상품·SKU 공개/활성/보관 상태, 판매 정지/폐점 중 기존 거래 교환 허용 범위는 미정 정책 게이트로 두고 결정 뒤 정확한 allow/deny 표를 검증한다. 일반 inventory 예약은 이 자격 검사를 대신하지 않는다.

교환은 재출고만으로 완료되지 않는다. 교환품 배송 완료→claim 완료→보류 해제→직접/자동 구매확정 재평가→P10/P11 자격 인계까지 계획한다. 구매확정/새 신청의 기준 배송 묶음·기한과 교환 후 추가 클레임 허용 범위를 E1에서 판단하며, 기간을 재시작한다고 임의 확정하지 않는다. 최초 배송7일이 지났다는 이유로 교환품 미배송 상태에서 확정하거나 영구 보류해도 실패다. 추가 반품을 허용할 경우 실제 회수된 대체 SKU를 입고하고 원 SKU를 다시 입고하지 않는다. 허용하지 않을 경우 서버 거부·운영 안내와 미변경 assertion을 남긴다.

예정 변경: 신규 `backend/src/main/java/com/example/marketplace/claim/domain/ExchangeRules.java`, `claim/infrastructure/JdbcExchanges.java`; C Claims/Controller·A fulfillment 공개 계약·inventory Reservations의 필요한 공개 확장과 신규 migration. 재고 모듈 내부 SQL을 claim에서 직접 사용하지 않는다. 교환 상품 조회/선택 최소 화면과 G 조작 UI 계약을 연결한다.

## 독립 검토와 F 인계

검토자는 교환예약 기한의 임의 연장, 원품/대체품 수량 혼용, 환불 전환 뒤 살아 있는 출고 job, 부분입고 재시도 중복을 확인한다. 정책 미확정 또는 필수 검사 미실행이면 완료와 F 진입을 보류한다.

F에 환불 전환의 원 cause/claim/payment 관계와 미확정 금액 점유·교환예약 상태를 전달한다. 실제 택배/추가과금/정산을 구현하지 않는다. 현재 실행·독립 결과와 사용자 확인은 없으며 이후 실제 파일/소스/경로·실패 증거를 기록한다.
