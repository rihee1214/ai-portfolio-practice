# P05-B 장바구니

2026-10-25 착수. base a069bf2154718071bf68d6bab77ac651c6bed32d, codex/p05-b. 범위는 implementation-plan P05-B / F07이다. P05-C 찜·주문서·판매자별 묶음, 주문·결제·재고 예약은 제외한다. 기존 서버·DB·검증 DB·미디어·데모·실패 기록을 보존하고 매 실행 새 DB/미디어를 사용한다.

## 작은 작업과 결정

1. 수량·중복·최대 품목 계약 단위 RED→GREEN.
2. 회원 소유권·CRUD·버전 충돌·멱등 병합·공개 SKU 표시 실제 DB RED→GREEN.
3. 방문자 저장/복구·로그인 병합·계정 전환 상태 단위 RED→GREEN.
4. 상세 담기·/cart 화면·실제 PC/모바일 흐름, 전체 하네스와 기존 검토세션 독립 검토.

- 결정: SKU당 1~99개, 최대100종. 직접 수정은 절대 수량(0은 삭제), 병합은 SKU별 합산99 상한. 상한 조정 안내, 품절/비판매 항목은 자동 삭제하지 않고 안내/삭제 가능. 장바구니는 예약/가격 확정이 아니다.
- 방문자 장바구니 품목은 SKU UUID·수량만 localStorage에 저장한다. 최신 이름·가격·판매 가능·가용량은 catalog 공개 조회로 매번 읽고 로컬 가격/회원/인증 정보는 저장하지 않는다. 손상·저장 실패는 오류로 표시하며 자동 덮어쓰지 않는다.
- 결정: 응답 유실/새로고침/다중 탭에서 중복 병합을 막기 위한 별도 복구 journal에 무작위 requestId와 SKU·수량 snapshot만 저장한다. 이는 품목의 가격·사용자 데이터 저장 예외가 아니라 요청 재시도 식별 메타데이터다. 개인정보·토큰·회원 ID는 넣지 않는다. Web Locks로 탭 간 방문자 변경/병합을 직렬화한다. 미지원 환경에서는 안전하지 않은 변경 대신 오류를 안내한다.
- 회원 cart는 user_id PK/version, cart_item(user_id,sku_id) unique/quantity 제약. merge request UUID는 전역 유일하며 서버에 소유자·정규화 payload를 결합한다. 같은 소유자/내용 재시도는 합산하지 않고 현재 장바구니를 반환한다. 다른 계정/내용 재사용은409이다. capacity 초과는 전체 rollback. 병합 응답 확인 전 방문자 품목을 지우지 않는다. journal 정리 실패도 같은 ID로 복구한다.
- identity의 BUYER 자격 API를 사용한다. 변경은 회원 행→cart 행 잠금 뒤 현재 ACTIVE/BUYER를 재검사한다. 회원 정지·탈퇴와 직렬화하며 다른 회원 cart에 접근하는 파라미터를 받지 않는다. 현재 가격/공개 자격은 catalog API를 사용한다. 미공개/비활성/없는 SKU의 상품명·매대·가격은 반환하지 않는다.
- API: GET /api/cart?owner=, PUT /api/cart/items/{sku}(owner/quantity/version), DELETE /api/cart?owner=&version=, POST /api/cart/merge(owner/requestId/items), POST /api/cart/preview(items). preview만 익명 허용하며 POST는 CSRF 필요. 본인 회원 cart만 조회/변경한다. 모든 응답 no-store. GET/preview는 재고/예약/장바구니 쓰기 없음.
- 글로벌 auth/cart provider가 로그인 완료 시 방문자 journal을 병합한다. 변경/조회는 세대·취소를 함께 사용하고 계정 변경/로그아웃/재확인 중 회원 정보를 즉시 지운다. 회원 cart는 localStorage에 복사하지 않는다. 다른 계정에 묶인 pending journal은 자동 재귀속하지 않고 복구/명시적 방문자 취소 안내를 한다.
