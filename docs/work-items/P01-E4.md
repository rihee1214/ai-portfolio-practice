# P01-E4 DB 필수 설정 시작 전 검증

2026-10-24 / 상태: 구현·자동 검증·독립 검토 완료

## 범위와 결정

기존 계획에 E4 세부 행은 없고 상위 P01-E에 설정 누락 오류 검증이 남아 있다. 이번 E4는 `db` 프로필의 필수 설정 검증으로 한정한다. Actuator 접근 정책·ArchUnit·다음 단계는 진행하지 않는다.

- 실제 적용되는 `spring.datasource.url`, `spring.datasource.username`, `spring.datasource.password`가 누락·빈 문자열·공백·미해결 placeholder이면 일반 singleton 및 DB 연결 생성 전에 시작을 거부한다.
- 오류에는 고정 설정 이름과 DB_URL/DB_USERNAME/DB_PASSWORD 안내만 남긴다. 값이나 원인 예외는 붙이지 않는다.
- 환경 변수뿐 아니라 Spring의 명시적 datasource 설정도 인정한다. 기본/local 등 `db`가 없는 실행에는 필수 DB 설정을 요구하지 않는다.
- DB_SCHEMA 기본값·URL 상세 문법·접속 자격의 유효성·DB 연결 여부는 기존 Flyway/드라이버의 책임이다. 전체 설정/로그의 비밀값 제거를 보장하는 기능은 아니다.
- 기존 health·React·서버·DB 데이터를 변경하지 않는다. 검사는 DB 자동 구성을 제외한 격리 컨텍스트와 기존 DB 없는 Java 검사로 수행한다. 실제 DB에 연결하거나 쓰지 않는다.

## 실행 순서

1. 시작 전 실패·정상 설정·프로필 범위·오류 내 값 미노출 검사를 먼저 작성하고 미구현 실패를 확인한다.
2. db 전용 시작 검증을 최소 구현하고 Java 전체 verify로 health/오류/요청 ID 회귀를 확인한다.
3. 지정 검토 및 반영세션에서 독립 검토를 진행한다.
4. 실제 결과·제한·차단 항목을 기록하고 로컬 커밋으로 마무리한다.

기존 공유 체크아웃과 지정 검토 세션 흐름을 유지한다. 작업 기록을 이 문서에 모으고 별도 실행 도구/작업 트리를 추가하지 않는다.

## 구현과 검증 결과

`DatabaseSettingsConfiguration`은 `db` 프로필에서만 등록한다. static `BeanFactoryPostProcessor`는 일반 singleton을 생성하기 전에 최종 Environment 설정을 확인한다. 누락 항목을 모아 고정된 설정 이름만 안내한다. 값은 바꾸거나 trim하지 않으며 비밀번호 내용의 정상 여부·실제 접속 자격을 판단하지 않는다. `${`가 남은 문자열은 미해결 placeholder로 취급하므로 그 문자열 자체를 포함하는 리터럴 비밀번호도 허용하지 않는다.

| 검증 | 결과 |
| --- | --- |
| [미구현 RED](evidence/P01-E4-red.txt) | 새 검사14개 중11개 예상 실패·3개 통과. 누락 검증 없이 컨텍스트가 시작되어 실패, 컴파일 오류0 |
| [최종 Java verify](evidence/P01-E4-java-verified.txt) | 83개 통과: 기존69 + 설정14, 실패/오류/skip0. Checkstyle·컴파일·패키징 통과 |
| 설정 검사 | 각 필수값의 빈 값/공백/미해결 placeholder, 환경 설정 전체 누락, 환경 주입, 명시적 datasource 우선순위, default/local의 DB 비의존 확인 |
| 시작 순서·값 보호 | 잘못된 설정에서 일반 singleton 생성 표식이 실행되지 않음. 합성 비밀값을 포함한 placeholder 실패의 최종 예외와 캡처된 콘솔에 값 미노출 |
| [패키징 앱](evidence/P01-E4-packaged-missing.txt) | 실제 JAR에 db 프로필·빈 datasource 설정3개·비웹 실행을 전달. exit1과 고정 설정 이름 확인, 연결 이전 실패 |
| 기존 계약 | 전체 Java 검사의 실제 HTTP 및 MockMvc health·요청 ID·API 오류 회귀 통과. UI/프록시 코드는 미변경, 프런트 검사와 브라우저는 이번에 재실행하지 않음 |

설정 검사는 `ApplicationContextRunner`에 실제 앱과 ConfigData 로딩을 연결한다. 시스템 환경/프로퍼티를 제거하고 합성 설정만 사용하며 DataSource/Flyway 자동 구성을 제외해 DB에 접근하지 않는다. 유효 설정 검사 통과는 실제 DB 접속 성공을 뜻하지 않는다. 실제 OS 환경 변수 바인딩 전체 조합과 운영 설정 파일은 재검증하지 않았다.

## 보존과 실행 중 문제

[보존 확인](evidence/P01-E4-preservation.json)에서 기존 dev/test 정규화 덤프 해시는 E3와 동일하다. 컨테이너 ID·healthy·DB 포트15432/15433의 PID57168을 유지했다. 덤프는 읽기 전용이며 restrict/unrestrict 무작위 토큰만 제외해 해시를 계산하고 원문은 저장하지 않았다. DB 쓰기·초기화·재시작은 없다. 기존8080/4174/5174 리스너는 없었으며 임의 기동하지 않았다.

[최초 전체 실행](evidence/P01-E4-java.txt)은 설정14개 통과 뒤 기존 HealthMvcTest의 Mockito 초기화 부근에서 출력 없이 대기했다. JVM 상태 진단도 응답을 얻지 못했다. 이번 실행에서 만든 PID9088/61048/68488만 종료하고 허용된 환경에서 재실행하자 전체83개가 통과했다. 따라서 환경 차이에 따른 현상으로 기록하며 내부 원인은 미확정이다. 기존 JVM71108은 종료하지 않았다. 최초 로그 파일이 잠겨 첫 재시도는 시작되지 않았으며 새 로그 파일로 정상 실행했다. 종료된 호출의 exit0을 검증 통과로 계산하지 않았다. 진단 호출도 취소했고 최종 프로세스 목록에는 기존 JVM만 남았다.

현재 차단 항목은 없다. 기존 Mockito 에이전트 경고와 의도된 health DOWN 경고는 테스트 실패가 아니다. 로그 행 끝 공백은 문서 검사에 맞춰 정리했다.

## 실행·학습·남은 범위

프로젝트 JDK21과 Maven Wrapper로 다음을 실행한다. JAVA_HOME은 `.local-tools/jdk-21.0.12.1+1`, MAVEN_USER_HOME은 `.local-tools/m2`를 사용한다. 전역 설정을 바꾸지 않고 실행 프로세스에만 지정한다.

```powershell
./backend/mvnw.cmd -f backend/pom.xml "-Dmarketplace.build.directory=$PWD/.local-tools/e4-build" verify
```

Spring의 일반 `@Bean` 생성 전에 bean 정의를 검사/보완하는 단계가 `BeanFactoryPostProcessor`다. 이번에는 설정 파일 → Environment → 필수 설정 검사 → 일반 bean/DataSource 생성 순서로 잘못된 설정을 더 빨리 발견한다. 환경 변수 이름만 직접 검사하지 않는 이유는 Spring의 명시적 datasource 설정을 통한 정상 덮어쓰기를 허용하기 위해서다.

작은 실습: DatabaseSettingsTest의 valid 설정에서 DB_PASSWORD를 공백으로 바꾸고 해당 정상 사례만 실행하면 시작 거부로 실패해야 한다. 실습 후 원복한다. 사용자 직접 실습·이해는 미확인이다.

E4는 필수 DB 설정 존재 여부만 다룬다. 실제 DB 재연결/마이그레이션, 임의 설정의 형식 검증, 전체 로그 비밀값 제거, Actuator 정책·ArchUnit, 인증/업무 설정은 이번 범위가 아니다. 다음 단계와 push는 진행하지 않는다.

## 독립 검토와 완료 기록

구현 커밋 `6b70d0f`에 대한 [검토 및 반영세션의 독립 검토](P01-E4-review.md)가 통과했고 필수 수정 결함은 없었다. 별도 출력 경로에서 Java 83개·Checkstyle·컴파일·패키징을 재실행해 통과했다. [검토 요약](evidence/P01-E4-review-summary.json)을 보관한다. RED·패키징 앱의 실패 경로는 개발세션 증거 검토이며 독립 재실행으로 계산하지 않는다.

검토 후에도 기존 DB 해시·컨테이너·포트 상태가 유지됐다. 향후 일반 singleton보다 먼저 DB를 만드는 후처리기를 추가하거나 Environment를 늦게 변경하면 순서를 재검증해야 한다. 현재는 그런 코드가 없으며, 임의 확장 코드까지 검증보다 뒤에 실행됨을 보장하지 않는다. 리터럴 `${` 거부·실제 OS 환경 변수 조합·실제 연결 미검증 등의 한계는 유지한다.

제품 수정 없이 검토 문서와 완료 상태를 최종 로컬 문서 커밋에 포함한다. 현재 차단 항목 없음. P01-E 전체 완료를 뜻하지 않으며 Actuator 정책·ArchUnit 등 남은 단계는 진행하지 않았다. push도 하지 않았다.
