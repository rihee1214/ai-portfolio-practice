# P02-A3 독립 검토 — 재승인 후 재검증 완료

2026-10-24 / 기준 커밋 `968e08e` 이후 작업 트리 / 상태: **R1·R2 보완 및 독립 재검증 통과, 검토 범위 내 필수 수정 잔여 없음**

## 범위

개발세션의 사용자 직접 메시지에서 P02-A3 구현과 이 세션의 검토 지정을 확인했다. React 가입·이메일 확인·로그인·계정 화면, 세션/CSRF 상태 처리, 가입 HTTP 어댑터, 반복 요청 제한, 관련 검사와 [작업 문서](P02-A3.md)를 정적으로 검토했다. 제품 코드는 수정하지 않았다. 다음 단계는 진행하지 않는다.

## 발견사항

### R1 — 새 가입·확인 API의 부정 경로 검사 부족

최초 검토 시 `signupHttpRequiresCsrfAndReturnsNoSecrets`는 유효 CSRF를 보낸 가입201·확인200만 검사했다. 기존 CSRF 누락 검사는 login/logout/unknown 경로만 다뤘다. 새 공개 어댑터의 계약을 검증하려면 다음 증거가 필요하다.

- signup/verify-email에 CSRF 없이 요청하면403이며 회원/토큰 상태가 변경되지 않음.
- 잘못된 가입 입력400, 중복 가입409, 확인 토큰 재사용400.

이는 확인된 제품 보안 결함이 아니라 API 경계의 검증 공백이었다. 최초 패치가 거절된 뒤 사용자 재승인을 받아 `signupAndVerificationHttpRejectCsrfAndBadInputWithoutChanges`가 추가됐다. 독립 새 DB 실행에서 위 상태 코드와 회원 미생성·PENDING_EMAIL 유지·미소비 토큰 유지·회원 1건 유지 검사가 통과했다. **R1 해결 확인.**

### R2 — 로그인 완료 화면 실패, 수정 후 검증 필요

개발 브라우저 로그의 실패는 의도된 오류 검사가 아니라 정상 가입·확인 후 로그인 흐름 실패였다. 최초 구현은 동일 페이지의 별도 BroadcastChannel 인스턴스가 보낸 알림도 수신하여 진행 중 인증 흐름을 invalidate할 수 있었다. source UUID 수정은 자기 알림만 제외하고 다른 탭 알림은 유지한다. 재승인 후 정상 로그인·다중 탭 로그아웃·별도 브라우저 문맥·새로고침·재로그인을 PC/모바일에서 독립 재실행해 모두 통과했다. `/account` 경로 정리도 반영된 코드였다. **R2 해결 확인.**

## 자동 승인 검토 차단 이력 — 현재 해소

개발세션 보고에 따르면 `.local-tools/a3-browser-fixed` 새 격리 DB/브라우저 재검증 실행이 자동 승인 검토에서 두 차례 거절됐다. 보고된 이유는 이전의 “P02-A3 미진행” 지시를 현재 제한으로 판단했고, 이후 개발세션 사용자 직접 승인을 제시했으나 신뢰 근거로 인정하지 않았다는 것이다. 이 문서는 해당 거절 자체를 직접 실행한 결과가 아니라 개발세션 통보임을 구분한다.

이 세션은 당시 통보 뒤 독립 실행으로 우회하지 않고 완료 판정을 보류했다. 이후 사용자가 이 세션에서 직접 재승인했고 개발세션과 이 세션의 재검증이 정상 실행됐다. 차단 기록은 삭제하지 않고 이력으로 남긴다.

## 범위·한계·보존

- 인증 상태는 메모리에 두며 변경 요청은 CSRF를 먼저 요청한다. 로그인/로그아웃 뒤 재발급·me 조회, 세대 번호로 늦은 응답 무시, 확인 중 개인 상태 제거를 코드에서 확인했다.
- 반복 제한은 단일 프로세스 메모리 창이며 성공도 횟수에 포함한다. 재시작·다중 인스턴스·프록시 뒤 공유 IP의 운영 정책을 해결한 것으로 보지 않는다.
- 테스트 메일 접근 경로는 테스트 소스에 있으며 일반 사용자가 이용하는 메일함 UI가 아니다. 수동 시연용 코드 확인 방법과 실제 외부 이메일 미발송을 작업 문서에 명시하도록 요청했다.
- 수정 후 브라우저 흐름은 위 범위에서 확인했다. 인증 화면의 배포 빌드 미리보기, HTTPS, 실제 세션 만료 후 UI, 분산 환경·동시 세션 경쟁, 사용자 직접 실습·이해 확인은 이번 독립 실행으로 검증하지 않았다. 수동 디버거 메일 확인 절차도 미실행이다.
