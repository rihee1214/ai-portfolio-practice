# P09-G 역할별 후속 처리 UI·통합 인수·후속 인계

2026-11-03 검증 절차 갱신: 아래 계획의 개발 전체→별도 동일 소스 독립 전체 실행 지시는 [현행 영향·위험 기준](../development-workflow.md#변경-영향과-위험에-따른-검증-범위)으로 대체한다. G의 여러 변경 통합 마감에는 최종 소스의 무선택 전체 근거를 유지한다. 독립 검토자는 같은 소스의 영향·범위·assertion 및 실행 근거를 확인하고 필요한 범위를 검증하며 전체를 자동 반복하지 않는다. 기존 업무 제약·실제 제공자 필수 검증/외부 차단·인계 조건과 미착수 상태는 유지한다.

상태: **계획 문서 독립 검토 반영 / 구현·검증·구현 독립 검토 미착수**, 2026-10-30.
목표: 구매자·비회원·판매자·운영자가 A~F의 저장된 후속 처리 상태를 화면에서 정확히 확인/처리하게 한다.
요구사항: F09~F12, AC09·10(정산 원장 제외) 및 AC02~04·07·08·13 회귀. [공통 계약](P09.md)과 A~F의 단계별 판정/독립 검토를 읽는다. F 실제 외부차단은 로컬 승인 범위에서만 분리 진행한다.

## 화면·권한·입출력 계약

- 회원 `/account/orders`, 공통 `/orders/{orderNumber}`, 기존 비회원 조회 흐름은 원 항목/단위별 배송·확정·클레임·환불 합계를 구분한다. 두 판매자의 서로 다른 배송·처리 결과를 부모 전체 완료로 뭉치지 않는다.
- 취소/반품/교환 신청은 서버 견적의 원 금액·회수비·추가비용/기한·대상 수량을 보여준 뒤 명시 명령을 보낸다. 서버 권한/가격을 프런트에서 결정하지 않는다. 확인중/운영확인은 완료/실패와 구분하고 자동 새 환불을 보내지 않는다.
- 판매자는 자기 배송/운송장·승인/반려·회수/검수/재출고만 조작한다. 운영자 화면은 공통 권한표와 F1에서 확정한 신규 환불 권한·대사 근거·사유를 요구한다. 기존 승인/보상 대사는 SYSTEM이며 claim 거래지원 권한과 혼동하지 않는다. no-store·최소 개인정보 projection·다른 판매자 정보 비노출을 유지한다.
- 응답 유실은 같은 키/내용 재시도·현재 GET. 인증 변경/로그아웃·GAS reset/version 변경 시 즉시 view/cache 폐기, abort와 generation으로 늦은응답 publish 차단. 오래된 version409는 재조회/재확인을 요구한다.
- PC/mobile 및375/768/1440px에서 표/폼/금액·에러/키보드 초점·로딩을 검증한다. 테스트 수/화면 캡처가 업무 assertion을 대신하지 않는다.

예정 변경: 기존 `frontend/src/pages/{OrderDetailPage,OrdersPage,GuestOrdersPage,SellerShipmentsPage}.tsx`, `frontend/src/fulfillment/ShipmentStore.ts`, `frontend/src/fulfillment/ShipmentViews.tsx`, 신규 `frontend/src/claim/{ClaimStore.ts,ClaimPanel.tsx}`, `frontend/tests/unit/ClaimStore.test.tsx`, `frontend/src/pages/AdminClaimsPage.tsx`, 기존 라우터·공통 API 연결. 백엔드가 제공하지 않는 상태를 프런트 가상 데이터로 만들지 않는다.

## 독립 검토와 전체 종료 기준

독립 검토자는 개발과 같은 소스를 새 증거 경로의 Offline 전체로 검증하고 각 AC를 원 단위 assertion에 연결한다. API/UI 총액만 맞고 DB 재고/쿠폰/배송 수량이 다르면 실패다. 로컬 필수 누락·실패·skip·flaky·보존 실패 또는 실제 제공자 필수 미검증을 전체 완료로 처리하지 않는다. 실기기/사용자 학습 확인은 자동 검사와 구분한다.

최종 기록에는 HEAD/dirty·inputs SHA·개발/독립 하네스 원본·XML/JSON·새 DB/미디어·제약별 실제 결과·수정/실패 이력·검토 담당/실제 모델·외부 차단을 남긴다. 현재는 아무 실행 결과도 없다.

P10에 회원의 확정된 원항목/소유권·환불/클레임 상태를 전달하되 리뷰는 구현하지 않는다. P11에는 원 매출/배송비/환불/회수비·원인ID·클레임 보류·확정시각을 전달한다. P11 정산 조정/지급은 미구현이므로 **AC10 전체 정산 검증 완료를 주장하지 않는다**. 과거 지급 기록 수정 금지·동일 환불 이중차감 금지의 인계 요구를 함께 남긴다.
