# P01 전체 완료 점검 독립 검토

2026-10-24 / 기준 코드: `1ab6584` / 대상: P01-completion-audit.md 및 현재 문서 변경

판정: **기반 구현·단계별 검증 증거의 종합 판단은 타당하다. 문서 교정 2건 중 R1은 검토 중 복원 확인, R2는 반영 대기다.** 새 제품 코드 결함이나 P01 범위의 필수 구현 누락은 발견하지 않았다. 최신 코드의 실제 DB 포함 통합 완료를 선언하지 않은 판정을 유지한다. P02 착수 승인이 아니다.

## 교정 요청

### R1 — 설계 문서 정리에서 유효한 프록시·SPA·CORS 계약이 삭제됨 (P2, 복원 확인)

현재 shop-design.md diff에서 P01-B4 설명 문단 전체가 삭제됐다. 그 문단에는 과거 진행 상태 외에도 다음의 계속 유효한 설계 계약이 있었다.

- 정확한 /actuator/health와 /api만 프록시하고 전체 /actuator를 열지 않음.
- SPA fallback은 화면 URL에만 적용하며 API·관리 경로·정적 자원 오류를 index.html로 바꾸지 않음.
- 별도 origin을 도입하면 허용 출처·credentials·쿠키·프리플라이트를 함께 검증함.

현재 설계의 공개 환경 절에는 같은 origin 역방향 프록시 원칙만 남아 있고 위 세부 계약의 동등한 문구는 확인되지 않는다. 이전 진행 상태를 정리하면서 미래 구현 기준까지 삭제할 이유는 없다. 과거 작업 설명과 분리해 설계의 현재 원칙으로 복원하거나 동등한 현행 계약에 직접 연결해 달라. 제품 코드 변경 요청은 아니다.

위는 최초 검토 시점의 발견이다. 개발세션의 복원 후 shop-design.md를 다시 읽어 위 프록시·SPA·CORS 문단이 복원됐음을 확인했다. R1은 해결됐으며 삭제 당시 이력과 현재 상태를 구분한다.

### R2 — 현재 계획 문단에 DB 연동 미구현이라는 이전 표현이 남음 (P3)

implementation-plan.md의 `3. P01 실행 환경과 프로젝트` 첫 문단은 “현재”로 시작하면서 “DB·인증·업무 API 연동은 미구현이다”로 끝난다. C2/C3/D2의 JDBC·Flyway 및 실제 PostgreSQL 검증 완료와 충돌한다. “DB 기반 연동은 구현·과거 검증 완료, 인증·업무 API는 미구현, 최신 db 프로필 조합 재검증은 남음”으로 구분해 달라.

같은 절의 B1 재검증 문단 마지막 “B4 구현은 진행하지 않았다”는 당시 실행 범위임을 명시하면 현재 상태와 혼동되지 않는다. 작업별 이력 문서는 보존해도 되지만 현행 계획의 현재 설명은 종합 점검과 일치해야 한다.

## 독립 확인한 결과

- 실제 main Java 7개와 platform 중심 구조, V1 경로, P01-A~E6의 계획·작업 기록을 대조했다. 실제 업무 모듈이나 권한 기능이 없다는 감사 문서의 제한은 코드와 일치한다.
- `.local-tools/p01-audit-review-build`에서 DB 없는 전체 Java verify를 독립 재실행했다. **117개 통과, 실패·오류·skip0**, Checkstyle·컴파일·패키징 성공. 로그는 ignored `.local-tools/p01-audit-review-java.txt`, XML은 해당 빌드의 surefire-reports에 있다. 이번 소유 문서는 이 파일 하나이므로 별도 추적 증거 파일은 추가하지 않았다.
- 실행은 기존 로컬 JDK21·Wrapper, MAVEN_USER_HOME=.local-tools/m2와 기본 Maven 의존성 저장소를 사용했다. `mvnw.cmd -o -B -ntp -Dmarketplace.build.directory=<root>/.local-tools/p01-audit-review-build verify`이며 db-it은 실행하지 않았다.
- E6 R1 수정의 `targetPlatform` 검사와 platform.api/platform.web 거부·application→platform 허용 사례를 확인했다. 수정 후 117개 독립 실행이 통과했으므로 초기 E6 검토 당시 남았던 수정 후 독립 재검증은 이번에 보완됐다. 원래 검토의 실패 기록은 삭제할 필요가 없다.
- 개발세션의 이번 감사 증거에서 Java117·Vitest47·Node68·Playwright16 집계와 타입·린트·빌드 출력을 대조했다. Java 외 검사는 이번 검토세션에서 다시 실행하지 않았다. 개발세션 실행과 독립 실행을 합산하거나 모두 독립 검증으로 표현하지 않는다.
- D2 실제 PostgreSQL 8개는 당시 검토 기록과 연결된다. 이번 기본117개에 포함된 DedicatedDatabaseTargetTest14개는 대상 보호 규칙 검사로, 실제 PostgreSQL 통합8개의 대체 증거가 아니다.

## 완료 판정과 남은 범위

감사 문서처럼 “P01 기반 구현 및 단계별 증거 확보, 최신 DB 포함 통합 조합 미검증”으로 구분하는 것이 적절하다. 모든 검증 완료 또는 현재 db 프로필에서 E4/E5까지 함께 정상 동작한다고 표현하면 안 된다. 기존 데이터 보존 조건 아래 이번에 DB 생성/fixture 쓰기 검사를 실행하지 않은 결정은 타당하다. 후속 격리 DB 보완 검증과 P02 시작은 별도 요청으로 유지한다.

공통 JSON은 Servlet ERROR 범위, React 오류 화면은 개발 전용, ArchUnit은 현재 platform 및 합성 업무 fixture 범위라는 한계를 명시했다. 기본 배송 진행 조회가 포함된 첫 구매 완료 기준은 P08 계획에 유지되어 있다. P01을 첫 구매·전체 기능·MSA 완료로 확대하지 않는다.

사용자 직접 실습·이해 미확인, 새 PC/다른 OS 재현·배포·복구·실기기·추가 브라우저 미검증도 적절히 분리했다. 사용자 실습 미응답을 이번 기술 작업의 승인 관문으로 바꾸지 않는다.

## 보존과 변경 범위

이 세션은 소유 RANDOM_PORT 서버를 사용하는 DB 없는 Java 검사만 실행했다. 기존 서버 실행·종료·재시작, DB 연결 검사·쓰기·초기화·컨테이너 조작은 하지 않았다. DB 해시/컨테이너 보존 판단은 개발세션의 P01-audit-preservation.json을 검토한 것이며 이번에 독립 pg_dump는 재실행하지 않았다.

추적 파일 변경은 이 검토 문서 하나다. 다른 문서와 제품 코드는 개발세션 소유로 유지한다. R1 복원은 확인했고 남은 R2 교정은 개발세션에서 반영한 뒤 감사 문서에 연결해 최종 로컬 기록을 마무리할 수 있다. P02·push·커밋은 수행하지 않았다.
