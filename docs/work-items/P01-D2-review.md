# P01-D2 개발 검토

2026-10-23 / 대상: `6206a13..27e0a041b11a95ed5e466fa4e2ef867a86f5025a`

판정: D2 범위 구현·독립 재검증·검토 통과. 추가 코드 수정이 필요한 결함은 발견하지 않았다. 기존 사이트 가동과 사용자 직접 실습 완료는 이 판정에 포함하지 않는다. D3 이후는 진행하지 않았다.

## 검토한 책임과 보호 경계

- Maven db-it 프로필에서만 Failsafe *IT를 integration-test/verify에 연결한다. 기본 Surefire *Test와 구분하고 실행 건수를 따로 기록한다. 기본 검사에 D2 전용 이름 허용 1건이 추가돼 33건이다.
- DedicatedPostgresInitializer는 컨텍스트 refresh 전에 D2 UUID 이름·고정 loopback 테스트 URL·앱 계정을 검증한다. 앱 인증과 권한 확인 후 새 DB만 생성하고, 생성한 DB의 신원을 다시 확인한다. 이름 충돌 시 기존 DB를 재사용하거나 초기화하지 않는다. 별도 Flyway 연결 설정도 거부한다.
- Boot의 db 프로필과 실제 Hikari DataSource/Flyway, 기존 production V1과 테스트 전용 C3 V2를 사용한다. C3 서비스/트랜잭션 설정은 테스트 프로필에서 활성화한다. 업무 테이블이나 API를 구현한 것은 아니다.
- 통합 8개는 실제 PostgreSQL 식별, 이행·재이행, 매핑, 커밋, 중복키 이후 롤백, checked 예외 롤백, CHECK/FK, REQUIRED 롤백을 확인한다. 결과는 별도 JDBC 연결로 조회하고 검사 전체에 자동 롤백을 적용하지 않는다. 서로 다른 fixture ID/참조를 사용한다.
- verify-db.ps1은 새로운 증거/빌드 경로와 UUID DB를 사용하며 프로세스 환경변수를 복원한다. Maven 종료 코드뿐 아니라 보고서의 오류·실패·skip·통합 0건도 거부한다. 로그는 저장 전에 로컬 암호를 치환하지만 전체 XML 등 모든 산출물에 대한 비밀값 제거 보장은 아니라는 문서의 제한을 유지한다.

이 보호는 현재 도구의 오접속 방지다. 코드·포트·관리자 권한을 가진 사용자가 임의 설정을 주입하는 상황 전체를 격리하는 보안 경계로 보지 않는다.

## 독립 실행

이 세션에서 다음 명령을 실행했다.

```powershell
./backend/verify-db.ps1 -EvidenceDirectory .local-tools/d2-review-20261023 -Offline
```

종료 코드 0, Maven verify 성공. [독립 집계](evidence/P01-D2-review-summary.json)는 Surefire 33건·Failsafe 8건, 실패/오류/skip 모두 0이다. 원본 마스킹 로그와 빌드 보고서는 `.local-tools/d2-review-20261023`에 남겼다. 일반 검사 실행 중 D1의 임시 HTTP 서버를 사용했으며 D2 통합 컨텍스트는 웹 서버를 사용하지 않는다.

[검토 DB 생성 기록](evidence/P01-D2-review-target.txt): `d2_it_072249861f96406fa8969eff1f24ec5a`. 이 DB도 삭제하지 않았다. 개발세션의 기존 D2 검증 DB 세 개와 합쳐 **D2 생성 DB 총 네 개**가 남는다. C1/C2/C3의 기존 DB는 별도다.

## 실패 증거와 보존 확인

개발세션의 설정 누락·잘못된 대상·잘못된 암호·이름 충돌·별도 Flyway 연결·Maven 실패 무시 사례를 소스 및 로그와 대조했다. [부정 사례 집계](evidence/P01-D2-negative-summary.json)는 암호 실패 SQLSTATE 28P01, 이름 충돌 42P04와 충돌 DB 전후 해시 일치를 기록한다. 단순 비정상 종료만으로 기대한 거부를 판정하지 않는다. 컨텍스트 준비 오류 8건은 실제 SQL 계약 8개가 실행됐다는 뜻이 아니며 정상 실행과 구분했다. 이 실패 사례들을 검토세션에서 다시 실행하지는 않았다.

독립 실행 후 [보존 확인](evidence/P01-D2-review-preservation.json)에서 기존 marketplace_dev/test를 읽기 전용 pg_dump로 조회했다. 무작위 restrict/unrestrict 토큰을 제외한 해시는 개발세션 시작 기록과 일치한다. 덤프 원문은 저장하지 않았다. DB 컨테이너 6a9f494624c9·68d17431a4b1은 그대로 healthy이며 15432/15433 리스너를 유지한다.

**8080·5174는 D2 시작 기록부터 리스너가 없고 이 검토 시점에도 없다.** 이전 서버 PID가 계속 실행 중이라고 주장하지 않는다. 이 작업에서 서버를 시작·중지·재시작하지 않았으며 중단 원인은 미확인이다. 사이트 health 정상과 D2 통합 검사 성공은 구분한다.

## 한계와 반영

새 PC/OS·Testcontainers·실제 DB 장애 중단·동시성·분산 트랜잭션·운영 권한·백업 복원·사용자 실습은 미검증이다. 프런트 테스트와 브라우저 검사는 이번에 반복하지 않았다. 작업 문서와 현재 상태 문서에 검토 완료 및 추가 DB를 반영했다. 제품 코드 변경 없이 문서와 검토 증거만 추가했으며 검토 작성 시점에는 미커밋으로 인계했으며 개발세션에서 확인 후 별도 로컬 문서 커밋으로 마무리한다.
