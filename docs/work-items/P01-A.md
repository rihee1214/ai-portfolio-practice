## 1. 목적과 조사 범위

[목적·목표](../requirements.md)의 G01·G07·G10과 AC16의 실행 재현성 준비에 연결된다. 익숙한 Java로 업무 규칙을 구현하고 React의 화면·상태·API 연동을 학습할 수 있도록 서버와 프런트 도구의 역할을 구분한다. 이번 문서 개정으로 F01~F18 또는 AC01~AC20을 통과 처리하지 않는다.

기준 문서는 [전체 기술 설계](../shop-design.md), [ADR-001](../decisions/ADR-001-java-spring-react.md), [구현 계획](../implementation-plan.md), [개발 작업 흐름](../development-workflow.md)이다. 상세 기술 선택 이유·장단점·대안은 ADR을 따르고, 이 문서에는 준비 상태와 다음 검증을 기록한다.

2026-10-21에 이 문서를 현재 기술 구성으로 개정한 뒤, 별도 P01-A2에서 환경·버전을 읽기 전용으로 재조사했다. 이 문서에는 그 결과와 진행 상태를 반영했다. 도구 설치, 시스템/PATH 변경, Git 초기화, 앱·설정·SQL 생성, 컨테이너 시작은 수행하지 않았다.

## 5. 호환성과 실행 경계

- P01-A2에서 Vite 8.3.4·React 플러그인 6.1.2·Router 8.5.0·Vitest 5.0.5의 Node 조건을 대조했다. 당시 기본 Node 20.12.1 대신 B2에서 프로젝트 Node 24.22.0·npm 11.19.1을 준비했다. 실행에는 `frontend/npm.ps1`을 사용한다. Vitest 도입은 P01-D3에 남아 있다.
- Java 설치 기록만으로 Maven 다운로드·Boot 빌드·JDBC 연결이 성공했다고 판단하지 않는다. Maven과 JDK의 경로·버전, Boot 관리 의존성, Flyway의 PostgreSQL 지원을 함께 확인한다.
- React는 화면을 렌더링하고 Spring MVC는 `/api/**`를 처리한다. 개발에서는 Vite가 API를 프록시하고 공개 환경에서는 같은 출처의 정적 화면·Java API로 연결한다. API 오류를 React 화면으로 바꾸는 fallback을 만들지 않는다.
- 로그인은 서버 세션과 CSRF를 유지한다. React의 화면 제한은 서버의 권한·소유권 검사를 대신하지 않는다. 세션 확인·토큰 발급/갱신·401/403 JSON은 P02에서 검증한다.
- DB 접근은 Spring JDBC, 스키마 변경은 Flyway가 맡는다. Spring Data JDBC나 JPA의 자동 저장소·스키마 생성을 전제로 하지 않는다.
- Docker 적용 대상은 PostgreSQL 서버다. JDK·Maven·Node의 Windows 배포본·프로젝트 경로와 JDBC·Flyway의 Maven 의존성은 그대로 필요하다. PostgreSQL 이미지·컨테이너·데이터 볼륨은 서로 구분해 기록한다.
- Java 기본 검사, 실제 PostgreSQL 통합 검사, React 단위 검사, 실제 API에 연결한 브라우저 검사를 구분한다. API mock으로 전체 구매 흐름의 성공을 선언하지 않는다.
- Node.js는 화면 개발 도구에 필요하다. 배포된 업무 API는 Java에서 실행하고 React 빌드 결과는 정적 파일로 제공한다. Vite 개발 서버를 운영 서버로 사용하지 않는다.

## 7. 다음 작업 인수인계

**현재 다음 구현은 P01-B4 하나다.** B1~B3 기록과 실제 코드를 확인하고 Vite의 `/actuator/health` 전용 프록시·공통 fetch·화면 연결을 진행한다. B1은 Actuator health로 교체됐으며 [B4 계획](P01-B4.md)에 503·통신 실패·관리 경로 제한 기준을 정리했다. JDK·Maven·Node의 준비와 검증은 이미 B1·B2에서 수행했으므로 A2의 과거 다운로드 실패를 현재 미설치로 해석하지 않는다.

DB는 P01-C1에서 ADR-002에 따라 Docker로 준비한다. Docker 엔진 접근 실패의 과거 기록은 남기되, 새 실행 환경에서의 접근·이미지 pull·DB 접속 결과를 각각 확인한다. 현재 B1 상태 API와 B3 화면은 DB를 요구하지 않는다.

이후 구현은 [구현 계획](../implementation-plan.md)의 작은 작업 하나씩 진행한다.

| 작업 | 범위 | 완료 증거 |
| --- | --- | --- |
| P01-B1 (완료) | `backend/` 최소 Boot REST API·Maven Wrapper | 선택 JDK·Maven으로 컴파일·패키징·실제 JSON 응답. [기록](P01-B1.md) |
| P01-B2 (완료) | `frontend/` React·TypeScript·Vite와 필요한 Node 환경 | 첫 화면·타입 검사·lint·정적 빌드, 실제 버전·잠금 파일. [기록](P01-B2.md) |
| P01-B3 (완료) | React Router·공통 레이아웃·일반 CSS | 직접 URL·새로고침·404·모바일·키보드 확인. [기록](P01-B3.md) |
| P01-B4 (계획 정리, 구현 미착수) | health 전용·업무 API 프록시, 공통 fetch·화면 연결 | 200·UP / 503·DOWN·통신 오류·취소 처리, 관리 경로 제한·오류의 HTML fallback 방지 |

| P01-C1 (미착수) | Docker Compose PostgreSQL·DB/계정 분리·데이터 볼륨 | 공식 이미지·실제 digest·접속·재시작·볼륨 유지 재생성 검증. PC 직접 설치 없음 |

기존 README/docs를 프로젝트 생성기로 덮어쓰지 않는다. 기본 API나 화면이 동작해도 DB·인증·구매·전체 P01까지 완료했다고 표시하지 않는다.

## 8. 개정과 보완 조사 반영 결과

이전 기술 구성의 설치 목표·패키지 조합·후속 구현 지시를 제거하고 Java·Spring Boot + React 기준으로 본문을 교체했다. 과거의 로컬 버전·접근 거부·DNS 오류는 관찰 날짜를 붙여 보존했다. P01-A를 설명하는 관련 문서의 안내도 현재 본문과 일치시켰다.

P01-A2에서 실제 읽기 전용 조사 결과를 추가했고 이 문서의 상태·남은 항목·인수인계를 갱신했다. A/A2 조사 작업에서는 앱 코드·빌드 설정·SQL·테스트를 생성하지 않았으며 설치·빌드·DB·인증·브라우저 실행도 하지 않았다.

2026-10-21 Docker 방침 반영 검토에서는 현재 상태·도입 경계·인수인계를 B1~B3 결과와 맞췄다. JDK·Maven·Node 경로와 실행 버전을 재확인했으며 상세 범위·제약은 P01-A2 10절에 기록했다. 앱 빌드·테스트·DB 구성은 이번 문서 검토에서 재실행하지 않았다.
