# P07-D 쿠폰 예약·확정·해제·복구 계약 — 구현 작업 계획

> **For agentic workers:** 구현 요청 시 `superpowers:executing-plans`를 사용해 아래 작업을 순서대로 수행한다. 단계 전체 개발 통과 후 지정 검토세션에서 독립 검토한다. 이 문서 작성만으로 구현·다음 단계·커밋을 시작하지 않는다.

**Goal:** 동시 사용과 재시도에도 쿠폰이 한 번만 예약/사용/복구되도록 내부 거래 계약을 완성한다.

**Architecture:** 설계의 promotion 모듈이 혜택 데이터와 계산을 소유한다. 기존 identity/seller/catalog 공개 API로 권한과 판매 정보를 확인하고, React는 서버 결과와 입력 상태를 표시한다. 거래 경계·정수 계산·현재 권한 검사를 서버에서 보장한다.

**Tech Stack:** 기존 Java·Spring Boot·Spring JDBC·PostgreSQL·Flyway·JUnit·ArchUnit, React·TypeScript·Vitest·Playwright. 새 프레임워크를 도입하지 않는다.

**Spec:** [요구사항](../requirements.md), [설계](../shop-design.md), [구현 계획](../implementation-plan.md), [P07 공통 계약/검증 절차](P07.md). F08, AC07·AC08·AC10·AC13의 쿠폰 계약 부분, requirements §8·9, shop-design §9·환불 계약.

상태: 개발 전체 및 독립 전체 검증 완료(2026-10-27). R-PD01~05 해결, 필수 잔여 차단 없음. 최종 근거는 아래 기록과 P07-D-review.md를 따른다.

## 입력·출력·실패 계약

계획 내부 계약은 `CouponReservations.reserve(List<Request>): List<Reservation>`, `commit(UUID checkoutId, List<UUID> ids)`, `release(UUID checkoutId, List<UUID> ids)`, `expire(UUID checkoutId, List<UUID> ids)`, `restore(RestoreRequest): Restoration`다. commit/release/expire도 List<Reservation>을 반환한다. Request=(reservationId, checkoutId, sellerOrderRef, memberId, storeId, issuedCouponId, Quotes.Quote quoteSnapshot, expiresAt); RestoreRequest=(causeId, sellerOrderRef, reservationId, refundCompletion)이다. RefundCompletion은 신뢰된 호출자가 생성하는 전체/부분·확정 여부 값 타입이며 외부 HTTP 입력으로 노출하지 않는다.

요청의 회원/쿠폰/매대·유효기간·최신 자격은 서버에서 다시 확인한다. C의 fingerprint만으로 권한을 인정하지 않는다. reserve는 Request의 C 서버 견적 스냅샷을 기반으로, 현재 소유권·사용 조건·할인액·최소금액·쿠폰 version을 재검증한다. 클라이언트가 제출한 금액을 이 값으로 대입하지 않는다. 정확한 DTO는 C의 Quotes.Quote와 공유하여 별도 할인 계산을 복제하지 않는다. 예약은 B의 발급 쿠폰을 잠그고 활성 예약을 하나로 제한한다. 여러 쿠폰을 잡으면 couponId 순으로 잠근다. 같은 요청 ID+같은 정규 입력은 기존 결과, 같은 ID+다른 입력은409다. 서로 다른 checkout의 같은 쿠폰은 한쪽만 성공한다. 하위 주문 참조는 P07에서 fixture UUID이며 제품 주문을 만들지 않는다.

예약 상태는 RESERVED→COMMITTED 또는 RELEASED/EXPIRED, COMMITTED→RESTORED다. 늦은 commit은 해제된 예약을 되살리지 못한다. 이미 처리한 동일 명령은 같은 결과로 수렴하고 상충 명령은 거부한다. commit은 잠금 후 expiresAt 정각 이상이면 거부하며, 만료 뒤 확인된 승인에 대한 정합성 처리/보상은 P08의 결제 조정자 책임으로 남긴다. 승인 불명확 상태에서 expire를 호출해도 안전하다는 의미로 해석하지 않는다. 복구된 쿠폰의 재사용은 새 예약 ID를 요구하며 과거 예약의 늦은 release/restore가 새 예약에 영향을 주면 안 된다. 복구는 **사용 회차/예약별 전체 취소·반품 완료에 1회**다. 원인ID는 중복 방지와 감사에 보존한다.

결제 전 해제 후 AVAILABLE 판단은 원 사용 만료를 따른다. 결제 후 부분 환불은 복구하지 않는다. 전체 완료라도 만료 쿠폰은 복구 이력만 남고 재사용 불가다. 만료는 시각만 보고 실행하지 않으며 P08의 결제 결과 조정자가 승인/불명확 상태를 해소한 뒤 내부 expire를 호출한다. P07에는 만료 worker·공개 확정/복구 endpoint를 만들지 않는다.

같은 DataSource/REQUIRED 거래에 참여하므로 호출자 rollback이 예약·이력까지 되돌려야 한다. 테스트 전용 컨트롤러는 fixture profile에서만 활성화하며 CSRF/인가를 유지한다. 실제 운영자는 이 fixture로 상태를 바꾸지 않는다.
