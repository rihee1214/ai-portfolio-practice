# P01-E1 개발 검토

2026-10-23 / 대상: `63fba6f..08800c0a19464cfb5d41cdef5f5387c48848842b`

판정: 첫 작업인 요청 ID 생성·전달 범위의 독립 검토 통과. 필수 수정 결함은 발견하지 않았다. P01-E 전체 완료를 뜻하지 않는다. 이 세션에서는 제품/테스트 코드를 바꾸지 않고 검토 증거와 작업 상태만 반영했다.

## 직접 검증

기존 로컬 JDK와 Maven 캐시로 DB 프로필 없는 `verify`를 독립 빌드 경로 `.local-tools/e1-review-build`에서 실행했다. [독립 검토 요약](evidence/P01-E1-review-summary.json): **44개 통과**, 실패·오류·skip 0. Checkstyle·컴파일·JAR 패키징도 성공했다. 기존 33개와 새 필터 5개·실제 HTTP 6개를 포함한다. 개발세션의 RED 실패와 패키지 검사 증거도 검토했으며 RED 자체는 다시 실행하지 않았다.

| 검토 항목 | 결과 |
| --- | --- |
| 생성과 신뢰 | 외부 X-Request-ID를 사용하지 않고 서버 UUID v4를 생성한다. 응답 헤더·요청 속성·MDC·로그의 ID 일치를 검사한다. UUID는 인증·권한·멱등성 키가 아니다. |
| 오류·비동기 | 실제 HTTP 500의 ERROR 디스패치와 Callable의 ASYNC 디스패치에 관찰 필터를 두어 동일 속성/MDC를 확인한다. 단순히 초기 응답 헤더만 확인하는 검사가 아니다. |
| 정리 | 정상·예외 종료 시 requestId 제거 또는 바깥 문맥 복원을 확인한다. 같은 스레드의 연속 요청과 다른 MDC 키 보존을 검사한다. |
| 기존 계약 | health 본문과 기존 정상/장애·404/405 검사가 유지된다. 업무 오류 JSON이나 React 표시를 앞당기지 않았다. |
| 범위 | 필터 등록·필터 구현·로그 패턴으로 한정했다. 테스트용 probe는 src/test에 있으며 업무 API를 추가하지 않았다. |

시험 중 의도한 `intentional-e1` 예외와 404/405/500 응답은 실패 경로의 기대 결과다. 테스트 실패 0과 구분한다. 예외 메시지가 응답 본문에 노출되지 않는 단언도 통과했다.

## 보존 확인

검토 후 기존 marketplace_dev/test를 읽기 전용 pg_dump로 확인했다. 무작위 restrict/unrestrict 토큰을 제외한 정규화 해시가 개발세션의 전후 기록과 동일하다. 덤프 원문은 기록하지 않았다. 두 DB 컨테이너 ID와 healthy 상태, 15432/15433의 PID 57168이 유지된다. DB 쓰기·생성·초기화·재시작은 하지 않았다.

8080/4174/5174 앱 서버는 작업 시작 기록과 검토 종료 시 모두 미실행이다. 이번 작업에서 종료하거나 재실행하지 않았으며 기존 화면 연결 성공으로 계산하지 않는다. 검사는 임시 RANDOM_PORT 테스트 서버만 사용했다.

## 한계와 완료 구분

- MDC 보장은 서블릿 디스패치 실행 범위다. Callable 작업 본문 스레드·@Async·스케줄러로 자동 전파하는 기능은 구현하거나 검증하지 않았다.
- 필터 이후 코드가 임의로 헤더를 덮어쓰거나 재디스패치 없이 응답을 reset하는 모든 상황, 필터에 도달하지 않은 프록시 오류는 보장하지 않는다.
- 소수 요청에서 ID가 다른 것을 확인했으며 전역 유일성 증명이나 부하·동시성 시험은 아니다.
- DB 통합 프로필·브라우저·프런트 검사는 이번에 재실행하지 않았다. 사용자 직접 실습과 이해는 미확인이다.
