# P04-C 상품·매대 이미지

2026-10-25 / 기준877bf55 / 구현·검증·독립 검토 완료. P04-D 이후·커밋·푸시 미진행.

## 범위와 세부 계약

설계/계획 P04-C의 JPEG·PNG·WebP 실제 디코딩·재인코딩, 업로드/교체/삭제, 상품·매대 연결, 소유권·비공개 접근 제한, 고아 파일 정리를 구현한다. 재고·구매·후기 이미지·객체 저장소는 제외한다.

1. 파일당5MiB, 폭/높이 각각4096 이하·총1600만 픽셀 이하. 허용 확장자 jpg/jpeg/png/webp와 실제 형식을 대조한다. MIME은 신뢰하지 않는다. 손상 파일·SVG/HTML·애니메이션은 거부한다. 새 BufferedImage에 픽셀을 복사해 메타데이터를 버린 PNG로 저장한다. 출력도5MiB 이하이며 초과는 거부한다. EXIF 방향 자동 보정/리사이징/크롭은 제공하지 않는다.
2. JDK JPEG/PNG + TwelveMonkeys imageio-webp 3.15.0 선정. WebP 출력 코덱 대신 PNG로 일관되게 재인코딩한다. 실제 lossy/lossless(alpha 포함) WebP fixture 검사를 통과했다. 출처: [공식 프로젝트](https://github.com/haraldk/TwelveMonkeys), [3.15.0](https://github.com/haraldk/TwelveMonkeys/releases/tag/twelvemonkeys-3.15.0). 순수 Java ImageIO 확장으로 배포별 네이티브 라이브러리 설치를 피한다.
3. 상품은5개 고정 슬롯(0~4), 매대 대표는1개(0). 슬롯별 version을 사용하고 삭제 뒤에도 빈 슬롯의 버전을 유지한다. 읽은 version과 다르면409, 타인 대상404. 대체 텍스트1~120자. 한 요청은 검증·파일 저장·대상 연결까지 처리한다. 임의 assetId/storageKey를 연결하는 API는 없다.
4. media 모듈이 MediaAsset와 연결 슬롯을 소유한다. catalog/seller의 공개 API로 소유권/거래 내 쓰기 잠금을 확인하고 타 모듈 테이블을 수정하지 않는다. 회원→매대→상품→슬롯 순서. 보관 상품/정지·폐점 매대 쓰기는 거부한다. 기존 imageKey/imageAlt는 과거 메타데이터로 보존하되 파일 접근 경로로 사용하지 않는다.
5. 저장소는 정적 폴더 밖의 명시적 MEDIA_ROOT. 서버 생성 UUID.png만 사용한다. DB 식별 마커와 프로세스 잠금으로 다른 DB/동시 인스턴스의 루트 공유를 거부한다. 검증마다 신규 DB뿐 아니라 신규 미디어 루트도 사용한다. 경로·심볼릭 링크 경계를 확인한다.
6. DB rollback 시 신규 파일 제거, 교체/삭제된 asset는 같은 거래에서 retired 기록 후24시간 뒤 정리한다. 파일 저장 직후 프로세스 중단으로 남은 DB 미등록 UUID.png도24시간 뒤 정리한다. 루트 범위와 DB 참조를 확인하며 현재 연결 파일을 지우지 않는다. 실패는 다음 정리에서 재시도한다. 기존 서버/DB/검증 파일에는 접근하지 않는다.
7. binary GET은 매번 소유자 또는 공개 대상 자격을 DB에서 확인하고 no-store/nosniff를 보낸다. 공개 조건은 상품·카테고리·매대·판매자 및 운영 숨김과 연결 상태를 단일 SQL로 판정한다. 교체/삭제 후 이전 URL은404. 저장 경로는 응답하지 않는다. 이미 내려받은 이미지 회수는 불가하다.
8. React 상품/매대 화면에서 미리보기·대체 텍스트·업로드/교체/삭제·오류/재조회 제공. 공개 매대에 실제 이미지 표시. 상품 공개 탐색 화면은 P05 범위를 유지한다. 인증/선택 변경 후 늦은 응답은 버린다. 자동 쓰기 재시도 없음.

- 기존 검토세션 독립 검토/새 DB 검증, 보존 비교와 결과·차단 기록. P04-D는 진행하지 않는다.

## 구현·API 계약

- V16은 media_namespace, media_asset, media_slot을 추가한다. 삭제 슬롯은 version을 가진 빈 행으로 유지한다. 기존 상품/매대 메타데이터와 기존 마이그레이션은 보존한다.
- `GET /api/media/{products|stores}/{targetUUID}`는 소유자 슬롯 배열(상품5·매대1)을 반환한다. `PUT .../{slot}` multipart `file`, `alt`, `version`과 CSRF로 생성/교체, `DELETE .../{slot}?version=N`과 CSRF로 삭제한다. 응답은 slot/assetId/alt/version/width/height이며 저장 경로는 없다.
- `GET /api/media/public/{products|stores}/{slug}`는 현재 공개 자산 목록, `GET /api/media/{assetUUID}/content`는 권한을 확인한 PNG다. 소유자도 활성 회원·SELLER 자격이 필요하다. 바이트 응답은 no-store/nosniff. 입력400, 인증401, CSRF403, 대상/비공개404, 버전/쓰기상태409, codec 동시2건 초과429를 사용한다.
- MediaPanel/MediaStore는 상품5슬롯·매대1슬롯 미리보기와 업로드·교체·삭제 확인을 제공한다. PublicMedia는 공개 매대에 실제 PNG를 표시한다. 인증 변경/선택 변경 시 취소하고 오래된 응답을 버린다.

## 작은 작업과 실패 이력

- codec 실제 RED는 미구현으로4개 검사 중2실패·2오류. 초기 wildcard import 스타일 실패를 먼저 수정했다. JDK/TwelveMonkeys 구현 후4개 통과. 후속으로 유효 CRC의 픽셀 초과, APNG, 손상 JPEG, 재인코딩 출력5MiB 초과를 보강했다.
- 최초 DB 이미지 RED는 업로드 예상200/실제404. 구현 후 settings-only 컨텍스트의 MEDIA_ROOT 누락2실패, 이어 초기 운영자 동시실행 실패를 확인했다. DB 설정 검사 및 이미지와 무관한 InitialAdminCommand에서 media 구성을 비활성화해 기본134·DB76 통과했다.
- 이미지 관리 화면 부재를 검사한 뒤 연결했다. 후속 기본136·DB79와 프런트 타입/린트/단위90/빌드 통과. DB에는 타인·CSRF·공개 필터·교체/삭제 버전·동시쓰기·DB실패 rollback·현재 참조 보존·부분 정리 실패 재시도 검사를 포함했다.
- 검토 R1: 인증401/403 후 기존 이미지 목록이 남는 두 실제 실패를 재현했다. stop+rejectSession으로 목록/회원 상태를 폐기해 해결했다. 첫 테스트 파일 확장자가 설정과 달라 수집되지 않은 실행은 RED 증거로 세지 않았다.
- 검토 R2: 파일 모니터를 잡은 채 DB 행 잠금 또는 풀 연결을 기다리는 순서를 보완했다. 외부 REQUIRED 거래, 실제 회원/상품 잠금 대기 후 정지/보관 재검증, 진행 중 파일 보호를 추가했다. 연결풀1의 실제 대기 상태를 관측하여 content/orphan 잠금 역전의 수정 전 실패와 수정 후 통과를 분리 검증한다.
- 중간 p04-c-full은 기본137·DB81·브라우저22 통과. 이후 R2 보완과 매대 이미지 실제 표시 추가가 있으므로 이 중간 결과만으로 최종 완료를 판정하지 않는다.

## 제한·보존·후속 범위

24시간 유예는 테스트에서 시각을 조정해 검증한다. 실제24시간 대기, 프로세스 강제종료, 실제 모바일 기기, 모든 이미지 코덱 입력의 안전성 증명 및 사용자의 직접 학습은 미확인이다. 재현 가능한 손상/위장/경계 입력을 자동 검사한 범위로 한정한다. 이미지 방향 자동 보정/리사이징/크롭·애니메이션·객체 저장소·후기 이미지는 제공하지 않는다. 기존 다운로드 사본의 회수는 불가능하다. P04-D 및 이후 기능은 미착수다.


### 손상 PNG 추가 검사

JDK 디코더가 잘못된 PNG IHDR CRC를 받아들이는 동작을 실제1실패로 재현했다(`p04-c-crc-red.txt`). PNG 전체 chunk의 CRC32를 명시적으로 대조하도록 보완한 뒤 codec5개가 통과했다(`p04-c-crc-green.txt`). 모든 이미지 손상 탐지를 디코더에만 맡기지 않는다. 앞선 p04-c-final은 R2 두 회귀를 포함해 기본137·DB83·브라우저22 통과했으며, CRC 보완을 포함한 p04-c-final2를 별도로 실행한다.


## 최종 개발 검증

CRC 보완을 포함한 `p04-c-final2`에서 기본137·PostgreSQL83 실패/오류/skip0, 실제 DB 브라우저22 통과했다. 프런트 타입/린트/단위90/빌드도 통과했다. [DB 집계](evidence/P04-C-db-summary.json), [신규 대상](evidence/P04-C-db-target.txt), [서버 검사](evidence/P04-C-db.txt), [브라우저](evidence/P04-C-browser.txt), [프런트](evidence/P04-C-frontend.txt)를 보존한다.

[인증 RED](evidence/P04-C-auth-red.txt), [읽기 풀 잠금 RED](evidence/P04-C-pool-red.txt), [고아 정리 풀 잠금 RED](evidence/P04-C-orphan-red.txt), [PNG CRC RED](evidence/P04-C-crc-red.txt)와 [codec GREEN](evidence/P04-C-crc-green.txt)을 기록했다. 최종 DB83에는 제한 연결 풀 대기 중 파일 잠금 진입 가능·외부 REQUIRED 거래·회원 정지/상품 보관 잠금 대기 후 재검증 회귀가 포함된다.

PC/모바일 브라우저는 상품 이미지 업로드→실제 naturalWidth 확인→교체→이전 URL404→삭제, 매대 대표 업로드→익명 공개 화면 실제 표시→매대 비공개 뒤 이미지 URL404를 확인했다. [상품 모바일](evidence/P04-C-images-mobile.png)·[상품 PC](evidence/P04-C-images-desktop.png), [매대 모바일](evidence/P04-C-store-mobile.png)·[매대 PC](evidence/P04-C-store-desktop.png)를 보존했다. 캡처는 직접 열어 폼/줄바꿈/공개 매대 표시를 확인했다. 자동 fixture는4×3 픽셀이라 캡처에서 작은 색 점으로 표시되며 실제 사진의 시각적 품질 검사로 주장하지 않는다.

[검토 입력 해시](evidence/P04-C-review-input-sha256.json)로 최종 제품/검사 소스를 고정했다. 검토세션에 개발 실행 종료와24176 포트 반환을 알리고 별도 신규 DB의 독립 전체 실행을 요청했다. 독립 판정 전까지 최종 완료는 보류한다.


## 보존 확인

개발 최종 실행 뒤 [작업 전](evidence/P04-C-before.json)과 [작업 후](evidence/P04-C-after.json)의 정규화 읽기 전용 덤프 해시가 개발/테스트 DB 각각 동일했다. 기존 검증 DB를 포함한 원래 DB 목록 누락 없음, 기존 컨테이너 ID 동일, 리스너 주소·포트·PID 동일을 [보존 로그](evidence/P04-C-preservation.txt)로 확인했다. 과거 검증 DB 전체 행을 다시 덤프 비교한 것은 아니다. 모든 검증은 새 DB와 새 media 루트만 사용했고 생성된 실패/성공 DB와 파일도 유지했다. 기존 서버 재시작·기존 DB 업그레이드·기존 이미지 삭제는 수행하지 않았다.


## 최종 판정과 막힌 항목

기존 [검토세션의 독립 검토](P04-C-review.md)가 별도 신규 DB와 media 루트에서 기본137·DB83·브라우저22, 프런트 타입/린트/단위90/빌드를 직접 실행해 통과했다. R1 인증 상태·R2 DB 연결/파일 잠금·R3 PNG CRC 문제 모두 해결을 확인했다. 제품/검사34개 해시가 검토 전후 같고, 독립 실행 전의 기존 미디어69개 파일도 동일했다. [독립 보존 증거](evidence/P04-C-review-preservation.txt)를 확인했다.

**P04-C 확정 범위 완료. 필수 잔여/차단 항목 없음.** 위 진행 중·대기·완료 보류 문구는 중간 이력이다. 실제24시간 대기·강제종료 복구·실제 기기·상용 부하·Windows 링크 교체 공격 전체와 사용자의 직접 학습은 미확인으로 남긴다. 이를 자동 검증 완료로 표시하지 않는다.

독립 검토 당시 로컬 `codex/p04-c` 브랜치의 미커밋 변경으로 보존했다. 후속 사용자 요청에 따른 로컬 커밋 마감은 아래 기록을 따른다. 푸시·기존 서버 반영·P04-D 및 이후는 진행하지 않았다.

커밋 대상 소스·문서 공백 검사는 통과했다. 원문 검사 로그의 Maven 출력 끝 공백은 그대로 보존했으며, 로그를 제외한 staged diff를 검사했다. 이 출력 공백은 제품/검사 코드 변경이 아니다.
