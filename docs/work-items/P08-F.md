# P08-F 회원·비회원 주문·결제 이력 조회 — 구현 작업 계획

> **For agentic workers:** 구현 요청 시 `superpowers:executing-plans`로 작은 작업을 순서대로 수행한다. 개발 전체 통과 후 지정 검토세션에서 독립 검토한다. 이번 문서 작성은 구현/커밋 승인이 아니다.

**Goal:** 실제 주문과 결제 이력을 새 브라우저에서도 본인 권한으로 조회한다.

**Architecture:** order와 payment는 각각 자기 읽기 projection을 제공하고 guest 공개 계약은 조회 세션 권한을 판정한다. React는 서버 결과를 조합하며 판매자 projection을 구매자와 분리한다.

**Tech Stack:** Java/Spring Boot·Spring JDBC·PostgreSQL·JUnit/ArchUnit·React/TypeScript·Vitest/Playwright.

**Spec:** [설계](../shop-design.md) §4·7~11·13~16, [요구사항](../requirements.md) F05/F09/F10/F11·AC01~04/07/08/13, [구현 계획](../implementation-plan.md) §10, [P08 전체 계약](P08.md).

상태: 계획 작성 / 구현·검증 미착수. 선행: **D 완료; E를 순차 시도하되 외부 차단이면 DEMO 범위로 진행**.

## Interfaces와 세부 계약

GET `/api/account/orders`, `/api/orders/{orderNumber}`, `/api/guest/orders` 및 권한 있는 결제 이력 경로의 응답을 정의한다. 모든 식별자 조회는 현재 서버 회원/GuestAccessSession과 연결된 주문만 허용하며 주문번호 추측으로 존재 여부·결제 정보를 누출하지 않는다. 결제 조회는 order의 공개 소유권 판정을 사용한다. 목록은 제안 크기20·최대50, 생성시각+ID 안정 정렬/커서로 고정한다.

부모 금액·하위 주문 항목·원래 스냅샷·결제 시도/확인중/보상 상태를 별도 표시한다. 주문 완료와 배송 완료를 혼합하지 않는다. 상품/행사가 비공개돼도 과거 이름/가격을 현재 catalog로 덮지 않는다. 판매자는 자기 SellerOrder와 배송 필요 수령 정보만 보며 다른 매대 상품·전체 결제 이력·GuestBuyer 자격·복구정보를 받지 않는다. 회원 탈퇴 시 스냅샷은 유지하되 다른 신규 계정에 귀속시키지 않는다.

비회원 새 브라우저 로그인은 P06의 주문번호+전화+비밀번호를 그대로 사용한다. NEW/EXISTING 연결·로그아웃/비밀번호 재설정/최대수명·유휴만료가 실제 주문 조회에도 적용된다. no-store, 계정전환 시 이전응답 폐기, 오류/로딩 중 과거 타인 데이터를 숨긴다.
