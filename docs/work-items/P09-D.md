## 상세 계약과 변경 위치

소비: A 배송완료 원단위/시각, B 신청 보류/확정 경합, C 환불/회수비/전체완료 계약. 생산: ReturnReceipt·검수 결과·반품 완료 사실과 E에서 재사용할 회수/검수 절차.

- 배송완료7일 미만·미확정·미점유 대상만 신청한다. 같은 항목의 다른 수량은 구분하되 취소/반품/교환 중인 동일 수량은 중복 신청할 수 없다.
- REQUESTED→APPROVED 또는 REJECTED, 승인 뒤 회수→검수→환불 처리→COMPLETED. 회수/검수 사실 없이 완료 금지. 반려는 이유/actor/시각을 보존하고 점유 해제 후 B 자동확정을 재평가한다.
- 구매자는 본인 신청, 판매자는 자기 하위주문 승인/반려/회수/검수, 운영자는 거래지원 권한·사유가 있는 지원 명령만 허용한다. 비회원은 현재 별도 조회 세션으로 소유권/CSRF를 확인한다.
- 수량별 반환·판매가능·불량·분실을 구분한다. 판매 가능 수량만 causeId별 StockMovement1회; 환불 성공만으로 재입고하지 않는다. 재입고 성공/환불 UNKNOWN 등 부분 진행도 각각 이력으로 남겨 재개한다.
- 변심 회수비는 구매 당시 저장한 상품별 정책(기본3,000원·0원 허용)을 사용한다. 같은 원 배송 묶음에서는 반품 대상 상품의 누적 최대 금액을 적용하고, 후속 반품은 이미 확정된 부과액과의 차액만 추가한다. 서로 다른 원 배송 묶음은 합산하며 판매자 책임 단위는 부과 대상에서 제외한다. 정책이 없는 기존 주문은 C의 새 견적 비용 표시·명시 동의 계약을 사용한다. 현재 상품 정책·가격·무료배송 조건으로 과거 주문을 재계산하지 않는다. 하위주문 전체 금전+필수 반품 완료 후에만 쿠폰 복구한다.

후속 기간/회수비는 H03의 저장 정책 버전을 사용한다. 원단위/배송묶음과 반품 회수·검수 결과는 C의 전체완료 조정에 전달한다. 재고입고는 검수 판매가능 수량의 효과이고 쿠폰복구는 전체 처리의 효과이므로 서로 다른 시점/원인으로 검증한다. 분할 신청의 회수비 차액·추가비용 미정산 상태는 C1의 확정 계약을 따른다. 원 배송비는 2026-11-01 사용자 결정 **“판매자 책임으로 전체 반품할 때만 환불, 변심 반품은 환불하지 않음”**을 적용한다. 최초 계획의 미정 상태는 이 결정 전의 역사이며 C의 미발송 전체 취소 배송비 규칙을 발송 후 반품에 자동 적용하지 않는다. 혼합 책임·누적 전체의 서버 증거와 SHIPPING 연결은 지정 D1 기술계약으로 구체화한다.

C 진행 중 사용자 확정 정책을 위 계획에 반영했다. 상세 금융 경계는 [C 설계 계약 §11~12](P09-C-design-review.md)를 따른다. 누적 부과액에는 공제와 미수납이 모두 포함되며, 이전 미수납을 다음 환불에서 자동 상계하지 않는다. C 공통 포트의 금융 적용은 반품 완료·검수·재고 입고·쿠폰 복구·주문 종결을 뜻하지 않는다. D는 저장된 RETURN 결과와 실제 회수·검수 근거를 연결해야 한다. 이 문구 보완은 인계 계획의 정합성 수정이며 D 구현·실행 검증 착수가 아니다.

예정 변경: C의 `claim/api/Claims.java`, `claim/infrastructure/JdbcClaims.java`, `claim/web/ClaimController.java`; 신규 `claim/domain/ReturnRules.java`, `claim/infrastructure/JdbcReturnReceipts.java` 및 migration (`backend/src/main/java/com/example/marketplace/` 기준). C 환불/inventory 공개 API를 사용하며 구현 직접 참조는 금지. 최소 신청 화면은 G의 전체 UI로 이어진다.

## 독립 검토와 E 인계

검토자는 환불액과 재입고량을 하나의 성공 플래그로 묶지 않았는지, 전체 반품 완료의 서버 근거, 분실/불량 처리와 반려 후 확정 경합을 확인한다. 수량·금액·재고·쿠폰·이력 각각의 assertion과 새 독립 하네스가 필요하다.

**최초 계획 시점의 인계 기록:** E에 원품 회수/검수·판매가능 입고 원인ID, 미완료/추가비용 상태와 공통 환불 전환 포트를 전달한다. 현재 실제 변경·검증·독립 결과·사용자 확인은 없다. 실행 시 동결 소스/증거 경로/실패 이력을 덧붙이며 과거 결과를 소급하지 않는다.

### 이 고정 검토의 경계와 후속 미검증

지정 검토 대상은 catalog·기존 C 인계를 바꾸는 것이 아니라 현재 request/accepted-proof·명령·회수/검수·신뢰 입고와 DB graph다. R-D01은 이미 지정 ADDRESSED다. 이번 물리 고정본의 별도 판정은 아직 대기다. 자연 시간7일 뒤의 실제 운영·사람의 물품 확인·실제 Toss는 검증하지 않았다. 기존 접수의 후기한 포트는 승인 경로에서 직접 제어 Clock으로 검사됐고, 회수/검수/향후 최종 동의 후기한 조합은 나머지 통합 계약에 연결할 후속 범위다.
