# P04-D SKU 재고 잔액·조정 이력·버전

2026-10-25 / 기준33d5427 / 구현·검증·독립 검토 완료. P04-E·푸시 미진행. 후속 로컬 커밋 마감은 아래 기록 참조.

## 범위·결정

계획 P04-D와 설계9절의 SKU 보유(onHand), 예약(reserved), 가용(onHand-reserved), version, 사유/원인 이력을 구현한다. 예약 생성·확정·해제·만료와 주문/구매 연동은 P04-E 이후로 제외한다.

- inventory 모듈이 balance와 movement를 소유한다. 기존 SKU는 V17에서0으로 보충하고 신규 SKU는 조회 시 미생성 잔액을0/version0으로 표시하며 최초 조정 때 생성한다. catalog→inventory 의존/쓰기와 순환 의존을 피한다.
- 수량0~999999999 정수, reserved≤onHand, version 안전정수 범위. 보유량 절대값 조정이며 같은 수량은409. 사유1~200자, actor·원인 MANUAL_ADJUST·requestId·변경 전후 수량·reserved·버전·시각을 같은 거래에 기록한다.
- UUID requestId로 같은 actor/대상/본문 재전송은 최초 결과 반환, 같은 키의 다른 내용은409. 자동 쓰기 재시도 없음. version 충돌409, 타인/대상 불일치404, 형식400. 잔액과 이력은 원자적이며 이력 삭제 API 없음.
- 판매자는 자기 매대 SKU만, 운영자는 CONTENT 권한으로 조회/조정한다. 판매자·매대 쓰기 자격과 보관 상품 금지를 운영자에게도 동일 적용한다. 비활성 SKU 및 초안/중지 상품은 재고 정리가 가능하다. 잠금은 회원→매대→상품→잔액 순서, 대기 후 권한·상태·version 재검증.
- 판매자 상품 아래 재고 목록에서 SKU를 선택하면 재고 폼/이력. 운영자 카테고리 화면에 대상 상품 UUID 조회로 동일 재고 패널 제공. 공개 재고/구매 가능 판정은 추가하지 않는다.
- 조회는20개 페이지, 최대page10000. 인증/상품·SKU 선택 변경 시 이전 응답 폐기, CSRF·no-store 적용.

## 구체화된 처리 순서

requestId는 전역 UUID 고유키다. actor·SKU·정규화 사유·보유량·입력 version 모두 같아야 동일 요청이며, 다른 내용/대상/actor는409다. 현재 접근권한→대상 쓰기 상태/잠금→기존 요청 확인→version 확인→잔액/이력 원자 저장 순서다. 따라서 성공 요청의 재전송은 낡은 version보다 우선하지만 현재 권한회수·정지·보관보다 우선하지 않는다. 성공 재전송은 최초 결과 snapshot을 반환하고 화면은 최신 목록을 다시 읽는다.

운영자 actor와 대상판매자를 구분한다. actor CONTENT를 확인한 뒤 대상판매자→매대→상품 잠금을 취하고 CONTENT를 다시 확인한다. actor 회원행 잠금은 추가하지 않아 서로 다른 운영자/판매자 조합의 회원 잠금 역전을 피한다. 권한회수의 실제 상품 잠금 대기 검사를 수행한다. 이력은 시각이 아닌 SKU version 내림차순으로 정렬한다.

UI는 같은 수량·사유·버전의 미확정 의도에 requestId를 유지한다. 응답 유실 뒤 사용자가 같은 내용을 재전송하면 같은 키를 사용한다. 입력 내용/버전 변경은 새 키이고 최신 조회 후 새 조정을 시작한다. 자동 쓰기 재시도는 없다.

## HTTP와 화면

판매자 경로는 `/api/seller/products/{productUUID}/inventory`, 운영자 경로는 `/api/admin/content/products/{productUUID}/inventory`다. GET은20개 SKU 잔액 페이지, PUT `/{skuUUID}`는 `{onHand,version,reason,requestId}` JSON과 CSRF를 받으며 GET `/{skuUUID}/history?page=N`은 version 내림차순 이력 페이지다. 모든 응답은 no-store. 재고 버전은 상품/SKU 가격 버전과 독립이다.

현재 운영자는 카테고리 화면의 상품 UUID 입력으로 재고를 조회한다. 판매자 화면과 동일한 재고 모듈/폼을 사용하며 운영자 전용 임의 DB 수정은 없다. 권한이나 쓰기 상태가 거부되면 서버 오류를 표시한다. 보관 상품은 판매자 재고 폼을 비활성화한다. 공개 재고 조회나 재고에 따른 구매 가능 판정은 제공하지 않는다.

boundaries 새DB 기본137·DB88 통과: 음수/범위·엄격 숫자 타입·CSRF·타인/운영 권한·reserved4 하한·동일키 동시1이력/다른키동일버전1승자·이력 실패 rollback/동일키 재시도·나중 성공 뒤 최초 요청 재전송·이력25건 페이지·V16기존SKU→V17 및 재실행·운영자 CONTENT회수 실제 잠금대기 검증. 프런트 타입/린트/단위94/빌드 통과. 후속 전역키 충돌/판매자 상태 잠금대기/브라우저 검증을 추가했다.
