# P01-D2 PostgreSQL 통합 검사

2026-10-23 / 상태: 구현·검증 완료, 독립 검토 대기

## 범위와 계획

기준 커밋6206a13, 변경 없는 작업 트리에서 시작한다. 실행 계획·TDD 스킬을 적용한다. 기존 서버·DB 컨테이너를 재시작하거나 초기화하지 않는다. 기존 Compose 테스트 포트15433에 신규 d2_it_<UUID> DB만 만든다. 기존 보호 장치의 URL/계정/DB 이름 검증과 실제 연결 권한 확인을 유지한다.

1. [보존 기준](evidence/P01-D2-before.json) 기록.
2. 기본 Surefire *Test와 db-it 프로필의 Failsafe *IT 실행 분리. 준비 누락은 skip 대신 실패.
3. 초기화 전에 대상 검증·인증·신규 DB 생성·실제 신원 확인. Spring Boot db 프로필과 기존 V1+테스트 V2, 가상 데이터 사용.
4. 실제 DataSource·NamedParameterJdbcTemplate·트랜잭션의 조회/매핑·커밋·중간 실패/checked/REQUIRED 롤백·제약·Flyway 재이행을 독립 연결로 확인.
5. 미준비·잘못된 대상·인증 실패와 정상 실행을 구분해 기록. 종료 보존 비교와 개념/실습 문서 작성 후 검토 가능한 로컬 커밋으로 인계.

검토 및 반영세션이 구현 완료 이후 독립 검토한다. D3 이후·프런트 단순화·원격 push는 진행하지 않는다. 사용자 직접 실습은 미확인으로 유지한다.

## 구현과 검증 결과

- pom의 db-it 프로필에 Failsafe3.5.6 integration-test/verify와 *IT·failIfNoTests를 추가했다. 기본 Surefire *Test와 분리했다. 테스트 의존성·실행기는 기존 Boot BOM 관리 버전을 유지한다.
- DedicatedPostgresInitializer가 refresh 전에 대상·앱 인증/권한·새 DB 생성·실제 신원을 확인한다. 별도 Flyway URL/user/password도 거부한다. Boot db 프로필과 C3 fixture를 실제로 로딩한다. 운영V1/C3V2와 production 코드·설정은 변경하지 않았다.
- [최종 정상 실행](evidence/P01-D2-verified-maven.txt), [집계](evidence/P01-D2-verified-summary.json): Checkstyle·컴파일·패키징·기본33개 및 통합8개 모두 통과, 실패/오류/skip0. 실제 PostgreSQL18, Boot DataSource, V1/V2 재이행0건, 조회·매핑·커밋·제약·checked/REQUIRED 롤백을 확인했다. 별도 JDBC 연결로 결과를 읽으며 테스트 전체 자동 롤백에 기대지 않는다.
- [기본 verify](evidence/P01-D2-default-verify.txt): DB 설정 없이33개만 통과하며 새 출력 경로에 failsafe-reports가 생기지 않았다. 기본33개 중 D2 이름 허용 검사1개가 추가됐고 D1의 기존32개는 유지했다.
- [패키지 검사](evidence/P01-D2-package.txt): 테스트 코드·SQL·JUnit/Mockito/Spring Test가 배포 JAR에 포함되지 않는다.
- 실행 안내·개념·코드 흐름·직접 실습은 [PostgreSQL 통합 검사](../postgresql-integration-tests.md)를 따른다. frontend 변경은 없으며 D2에서 npm/브라우저 검사를 반복하지 않았다.

[부정 사례 집계와 이름 충돌 해시](evidence/P01-D2-negative-summary.json)를 별도 보관한다. 준비 실패의8 ERROR는 각각의 SQL 계약이 실행됐다는 뜻이 아니다. 최종 정상 집계는 `verified-*`이며 앞선 `final-*`은 Flyway 우회 보호 추가 후, 실행 도구의 보고서 오류 검사 보완 전 성공 이력이다. 직접 negative Failsafe 실행은 해당 임시 build의 XML을 덮어쓸 수 있어 정상 실행 당시 추출한 summary/log를 따로 보관했다.

첫 verify-db.ps1 실행에는 PowerShell의 줄바꿈된 -or 조건 구문 오류가 있었다. Maven/DB 실행 전에 발생했고 조건 연산자를 앞줄 끝으로 옮겨 수정했다. 이후 정상·실패무시 거부·최종 정상 경로까지 실행했다. D1에서 기록한 Mockito/JDK21 동적 agent 경고와 장애 health 임계값 WARN은 계속 발생하지만 검사 실패로 집계되지 않았다.

## 잔여 데이터와 보존

신규 DB 세 개를 삭제하지 않고 보존했다. 모두 marketplace_test 소유, marketplace Flyway 이력과 c3_fixture 가상 데이터만 포함한다. 각 DB는 계좌11행·성공 이체2행·성공V1/V2 2행이다.

- 최초 정상: d2_it_ae59ed177e6c4b14bdc84dadc87307ef ([기록](evidence/P01-D2-first-target.txt)).
- Flyway 연결 보호 보완 후: d2_it_8e4f6269c64a416e9a23690ee5fd7366 ([기록](evidence/P01-D2-final-target.txt)).
- 실행 도구 최종 확인: d2_it_eef26ee364774f77b8cccb7f8e86e850 ([기록](evidence/P01-D2-verified-target.txt)).

기존 marketplace_dev/test의 정규화 덤프 SHA256은 [시작](evidence/P01-D2-before.json)과 [종료](evidence/P01-D2-after.json)가 동일하다. 무작위 restrict/unrestrict 토큰만 제외했고 덤프 원문은 저장하지 않았다. 기존 db-dev6a9f494624c9/db-test68d17431a4b1과 Docker포트 PID57168·healthy를 유지했다. 컨테이너/볼륨/기존 DB 중지·재시작·삭제·초기화는 하지 않았다.

**기존 API/프런트 상태의 제한:** 시작 기록(22:18 KST)부터8080/5174 리스너는 없었다. 종료 확인에서도 이전 PID68748/63940과 리스너가 없으며 health 연결은 거부됐다. D1 당시 상태를 현재 상태로 가정할 수 없다. 이 작업에서 서버를 시작하거나 종료하지 않았고 중단 시점/원인은 미확인이다. 임의로 재시작하지 않았다. DB 통합 검증 성공을 기존 사이트 가동 성공으로 표시하지 않는다.

## 인수인계

D2 검사 실행 자체의 차단 항목은 없다. 기존8080/5174 health 확인은 서버 부재로 미검증이다. 새 PC/OS, Testcontainers, 동시성·분산 트랜잭션, 운영 권한/백업 복원, 사용자 직접 실습은 미검증이다. 신규 DB 잔여물과 설정·코드 경로는 위 문서에 설명했다. 독립 검토 전이므로 검토 완료를 주장하지 않는다. D3 이후와 원격 push는 진행하지 않는다.
