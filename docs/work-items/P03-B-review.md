## 정적 확인

- 소유자는 인증 principal에서 얻으며 수정 SQL에 id와 owner 조건을 함께 사용한다. 매대 생성은 회원당 고유 제약, slug는 전체 고유 제약을 둔다. 비공개 매대도 회원당 한 개 제한에 포함된다.
- 서비스는 SELLER 접근 권한을 확인하고 트랜잭션 안에서 ACTIVE BUYER 회원 잠금 및 SELLER 보유를 재확인한다. 회원→매대 순으로 잠그며 수정 시 읽은 version과 slug를 확인한 뒤 version을 증가시킨다. 다른 소유자 매대는 404, 중복·오래된 version은 409다.
- 공개 GET 경로만 익명 접근을 허용하며 공개 여부와 ACTIVE SELLER 조건을 확인한다. 공개 DTO에는 owner UUID와 version이 없다. 응답은 no-store다.
- 이미지 키·대체 텍스트만 저장하며 외부 URL이나 파일 업로드는 제공하지 않는다고 화면에서 안내한다. 공개 주소도 공개 정보임을 안내한다.
- 관리 화면은 저장 전 CSRF를 얻고 POST/PUT을 자동 재전송하지 않는다. 인증 변화 시 상태를 비우고 세대 번호로 늦은 응답을 무시한다. 공개 화면도 경로 변경 시 이전 응답을 무시한다.

## R1 — 입력 경계 검증 보완 요청

최초 DB 검사는 잘못된 slug 일부와 외부 이미지 키를 검사하지만 문서에 정한 길이의 최대 허용·초과 및 이미지 키/대체 텍스트 한쪽 누락을 확인하지 않았다. 최대 허용 입력, 초과값, 필수 공백값 거부와 거부 후 저장 상태 불변을 실제 DB에서 검증하도록 요청했다. 제품 결함을 실행 재현한 것이 아니라 검사 공백이다.

## R2 — 공개 페이지 모바일 검증 범위 확인

최초 브라우저 검사는 판매자 페이지에만 가로 넘침 검사를 수행하고 공개 방문자 문맥을 `browser.newContext()`로 생성한다. 모바일 설정 적용을 명확히 하고 공개 페이지의 가로 넘침도 확인하도록 요청했다. 실제 모바일 기기의 검증과 에뮬레이션은 구분한다.

## 보완 확인

- **R1 완료:** 최대 길이 입력(이름은 emoji 80 code point 포함)의 저장 성공, 각 항목 최대 길이 초과·필수 공백·이미지 키/대체 텍스트 단독 입력의 400 거부 및 기존 저장값·version 불변 검사를 추가했다. 독립 실제 DB 검사에서 통과했다. 모든 가능한 입력 조합을 검증했다는 뜻은 아니다.
- **R2 완료:** 공개 방문자 문맥에 판매자 페이지와 같은 viewport를 명시하고 공개 화면 가로 넘침 및 캡처를 추가했다. `.store-card`의 긴 문자열 줄바꿈도 적용했다. PC·모바일 폭에서 생성→비공개 404→공개 조회→다시 비공개 404와 새로고침을 독립 통과했다. 방문자 문맥은 viewport를 맞춘 것으로 실제 기기나 모바일의 모든 설정을 검증한 것은 아니다. 최대 길이 문자열 자체의 브라우저 표시는 별도로 검사하지 않았다.
