# P01-D1 JUnit Jupiter·Spring Boot Test·MockMvc

2026-10-23 / 상태: 구현·검증 완료, 지정 세션 검토 대기

## 범위·실행 계획

실행 계획·TDD 스킬에 따라 현재 계약을 검사로 옮긴다. 기본 API는 Actuator health이고 업무 API·보안 필터·공통 오류 형식은 아직 없다. P01-E의 requestId/code/message를 앞당기지 않고 현재 health와 404/405 기본 오류 계약을 검증한다.

1. 기존 프로세스/컨테이너·DB 해시 기록. 기존 작업 공간을 유지하고 .local-tools/d1-build에 빌드 출력 격리.
2. Boot BOM의 test starter와 webmvc-test starter, Surefire *Test 실행 및 0건 실패 정책 도입.
3. 순수 Jupiter(기존 DB 대상 검증), Boot MOCK+MockMvc(health·HTTP 상태·관리 경로), Boot RANDOM_PORT(실제 서블릿 404/405 JSON)를 분리.
4. DB 자동 구성 제외·SQL init/Flyway 비활성으로 D1 컨텍스트의 DB 연결 차단. 서버는 loopback 임의 포트만 사용하고 종료한다.
5. 검사 결과·실행 수·한계를 기록하고 지정 검토 세션에 전달. D2의 DB 통합/Failsafe, D3, E는 미착수 유지.

MockMvc는 Servlet 컨테이너의 /error 재전달을 그대로 실행하지 않으므로 빈 MockMvc 오류 body를 실제 JSON 계약으로 오인하지 않는다. @WebMvcTest는 향후 업무 Controller의 좁은 slice에 사용할 수 있지만 현재 Actuator는 Boot 자동 구성과 함께 확인한다. 테스트용 가짜 업무 API는 추가하지 않는다.

## 실패와 수정

1. [최초 실행](evidence/P01-D1-first-run.txt)은 순수13개 통과·Boot19개 컨텍스트 오류였다. C3의 일반 @Configuration이 앱 자동 검색에 포함돼 DataSource를 요구했다. @Profile("c3-fixture")를 추가하고 C3 main 컨텍스트만 명시적으로 켜도록 변경했다. DB 빈을 억지로 제공하거나 검사 전체를 skip하지 않았다. [수정 후32개](evidence/P01-D1-green.txt)와 C3 회귀를 확인했다.
2. [첫 노출 실험](evidence/P01-D1-health-regression-red.txt)은 show-details만 always로 변경해도 show-components=never가 유지돼11개가 통과했다. 파일명의 red가 실패를 의미하지 않는다. 실제 노출 조건인 두 설정 변경으로 회귀 탐지를 검증했고 위의 별도 노출 실패 로그와 구분했다.
3. 장애 health 검사의 diskspace WARN은 임계값을 의도적으로 높여 발생시킨 것이며 실제 디스크를 채우거나 DB를 중단하지 않았다.

## 인수인계와 한계

[Java 검사 안내](../java-testing.md)에 도구 역할·명령·실행 수·MockMvc와 실제 오류 전달의 차이·학습 실습을 정리했다. 실행 차단 항목은 현재 없다. 최초 테스트 의존성 확보는 승인된 Maven 네트워크 접근을 사용했다. 로컬 TCP/다운로드가 막힌 환경에서는 실행 권한이나 캐시 준비가 필요하다.

DB 자동 구성 자체의 정상 연결은 D1 검사 범위가 아니다. 업무 오류·인증/CSRF/세션·500 업무 예외·브라우저·전체 구매 흐름·새 PC/OS·사용자 직접 실습은 미검증이다. 지정 세션 검토 후 상태를 갱신하며 D2 이후·원격 push는 진행하지 않는다. 증거 텍스트는 Git을 위해 줄 끝 공백/마지막 빈 줄만 정리하고 Surefire XML은 비밀값 노출 가능성이 있는 전체 시스템 속성 대신 실행 수만 추출했다.

테스트 로그에는 Boot 테스트의 Mockito listener가 inline mock maker를 초기화하면서 JDK21 동적 agent 경고가 남는다. 현재 검사 실패는 아니며 이 작업에서는 Mockito mock을 작성하지 않았다. 향후 JDK에서의 자동 attach 제한 대응은 미검증이고, 경고를 숨기는 JVM 옵션은 추가하지 않았다.
