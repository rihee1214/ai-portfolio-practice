## 업무 묶음·전체 연결

[B 인계](P10-B.md#후속-전달-계약)에서 본인 주문·판매자별 하위 주문의 귀속, 권한 상실 뒤 단일 담당 인수·감사 이력, 자격 상실 접수의 동일 응답을 소비한다.

[D 전달 계약](P10-D.md#e-전달-계약)에서 사건별 숨김/복원 조치 ID·종결 버전·대상 세대와 사유를 소비한다. 현재 담당·권한을 확인하고, 과거 세대의 감사 이력과 현재 가능한 조치를 구분한다. 비공개 상품의 기존 거래는 원 주문과 판매자 하위 주문의 증빙·권한으로 조회한다.

## 최종 완료와 검토

E1/E2의 새 쟁점만 기존 세션에 중간 검토 요청하고 유효한 A~D 증거는 재사용한다. E3 최종은 통합된 동일 소스의 무선택 `./verify.ps1 -Offline -EvidenceDirectory .local-tools/<새-P10-실행경로>` 근거가 필수다. 꺾쇠 경로는 설명용이며 실제 고유 경로·서버 식별·명령을 실행 때 기록한다. 독립 세션은 변경/선택 적합성·각 제약의 assertion·원 XML/브라우저/결과/보존을 대조하고 추가 실행 필요 범위를 판단한다. 두 번째 전체 실행을 자동 의무화하지 않는다. 공유 변경 또는 실패 수정 영향이 전체 조건이면 다시 전체 근거를 확보한다.

- [x] A~E 서버·UI·권한·금액 보존·복구·회귀·필수 정책 모두 완료
- [x] 최종 소스/hash·미커밋 포함 목록·전체 결과·실패 이력/실측 시간·보존 연결
- [x] 기존 검토세션 최종 판정·수정 영향 재검증·필수 잔여0
- [x] P11 인계: 콘텐츠/문의/조치 사건의 안정 식별·actor/대상/상태/시각/공개 권한·중복 원인, 알림/대시보드 소비 범위와 미구현 항목
- [x] F07/G08 BLOCKED와 P09 전체 미완료, 실제 Toss/실기기/사용자 직접 확인 미검증을 별도 유지

P11 알림 전송·정산·대시보드·사이트 설정은 구현하지 않는다. 알림 발생 계약을 전달해도 전송 성공으로 표시하지 않는다. 정산 금액은 P09 원 금융 계약이 기준이며 P10 신고/지원 상태가 금융 원장/지급 근거를 대신하지 않는다. 기존 증거/서버/DB/미디어를 보존하며 커밋·푸시·배포는 별도 지시 전 금지한다.

## E1 거래지원 착수

기존 검토세션 `01a1a658-3fa7-7a70-aa14-96236ecf25eb`의 설계 판단(턴 `01a1c085-700a-7272-81c9-c13e4fa6a928`)에 따라 B의 확정 계약을 재사용한다. 판매만 정지된 활성 판매자는 자기 하위 주문에 답변할 수 있다. 계정 정지로 인증 자격을 잃으면 기존 세션의 본문·첨부 읽기를 거부하고 비노출 접수만 제공한다. 담당 SUPPORT의 답변은 고객에게 보이는 메시지다. E1 거래지원에는 판매자를 대신한 발송·검수, 강제 금융 처분, 정지 이용자의 인증 답변 수신을 추가하지 않는다.

E1은 담당 주문 문의 상세에 이미 승인된 원 주문번호·판매자 하위 주문 ID를 표시하고 재배정하면 본문·초안과 함께 폐기한다. 식별자는 다른 업무 권한을 부여하지 않는다. 착수 검토 시점의 계정 정지·복원 명령은 요청 키나 예상 버전을 받지 않았으므로 응답 유실 시 자동 재전송을 하지 않고 상태와 이력을 재조회해야 한다. E3 마감에는 통합된 최종 소스의 무선택 전체 근거가 필요하다.

### E1 회원 관리

사용자 확정 정책은 회원 ID·계정 상태 조회 및 정확한 이메일 검색 허용, 검색 결과에 이메일 미표시다. [회원 관리 화면](../../frontend/src/pages/ManagedAccountsPage.tsx)은 현재 ADMIN+ACCOUNTS 계정에 한해 `/admin/users`에서 목록·개별 상태·최근 조치 이력을 확인한다. [조회](../../backend/src/main/java/com/example/marketplace/identity/infrastructure/ManagedAccounts.java)는 가입 때의 정규화 규칙과 SQL 등가 비교를 사용한다. 검색어는 CSRF 검증을 거치는 POST 본문으로만 전달한다. 결과는 이메일·연락처를 반환하지 않는다. 계정 상세 화면은 정지/복원 사유·현재 버전으로 기존 명령을 호출한다. 결과 유실 시 상태·감사 상세 GET만 보내며 재조치는 새 사용자 입력과 최신 버전이 필요하다. 기존 버전 생략 호출은 유지한다.

초기 프런트 lint에서 렌더 중 ref 접근이 발견돼 버튼 비활성화 표시를 상태로 분리했다. [accounts-dev1](../../.local-tools/p10-e-accounts-dev1-20261109/result.json)은 identity,support 선택 중 기존 권한 확인 주소의 200이 400으로 바뀐 회귀에서 실패했고 보존은 통과했다. 기존 세션 턴 `01a1c094-e4ad-7aa0-928f-84a2d911ff28`의 필수 보완 3건에 대해 상세 경로를 `/api/admin/accounts/members/{id}`로 분리하고, 현재 HTTP 세션 ID·인증 버전을 대상 잠금 전후 확인해 만료된 조치는 트랜잭션을 되돌리도록 했다. 상세 401/403은 목록·검색값·초안까지 폐기하고 이전 목록 응답도 무효화한다. 상세 404는 해당 회원에만 적용한다.
