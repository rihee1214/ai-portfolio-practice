> **For agentic workers:** 구현 요청 시 `superpowers:executing-plans`로 작은 작업을 순서대로 수행한다. 개발 전체 통과 후 지정 검토세션에서 독립 검토한다. 이번 문서 작성은 구현/커밋 승인이 아니다.

**Goal:** 모의 결제와 동일한 조정 계약에 실제 테스트 제공자를 연결한다.

**Tech Stack:** Java/Spring Boot·Spring JDBC·PostgreSQL·JUnit/ArchUnit·React/TypeScript·Vitest/Playwright.

**Spec:** [설계](../shop-design.md) §4·7~11·13~16, [요구사항](../requirements.md) F05/F09/F10/F11·AC01~04/07/08/13, [구현 계획](../implementation-plan.md) §10, [P08 전체 계약](P08.md).

## Interfaces와 세부 계약

D의 승인/조회/보상 port를 구현한다. 테스트 키·허용 결제 수단·현재 SDK/API·webhook 인증/재전송 계약은 착수 시 토스페이먼츠 공식 문서에서 확인하고 URL/확인일/선택 버전을 기록한다. 이 계획은 미확인 제공자 세부 필드·서명 방식을 확정하지 않는다.

클라이언트 공개 키와 서버 비밀 키를 분리하고 DEMO/SANDBOX는 서버에서 결정한다. 요청 orderId/amount/paymentKey를 저장 주문·현재 소유권·기존 시도와 대조한다. 외부 요청/재조회는 DB 거래 밖이다. redirect URL 입력만으로 PAID 처리하지 않는다. 금액불일치·알수없는결과·네트워크단절은 D의 실패/UNKNOWN 규칙에 연결한다. webhook은 검증 후 이벤트 dedupe와 서버 재조회·상태전이 검증을 수행한다. 임의의 provider 문자열로 CSRF 예외를 넓히지 않는다.

일반 루트 Offline 하네스에는 HTTP stub의 어댑터/보안 계약 검사를 연결한다. 실제 SANDBOX 테스트는 별도 실행 결과로 증명하고 네트워크 접근 불가를 skip 성공으로 바꾸지 않는다. 비밀 값/원문결제키는 로그·추적·문서에 저장하지 않고 제공자 거래참조는 필요한 최소 범위로 마스킹한다.
