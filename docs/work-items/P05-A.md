## 계약과 결정

- 기존 /api/products 계약은 유지하고 읽기 전용 GET /api/browse/products 및 /api/browse/products/{slug}를 추가한다. catalog 읽기 projection은 기존 공개 조건을 재사용하고 SKU/재고 잔액을 한 SQL snapshot으로 읽는다. 재고 테이블을 쓰거나 inventory→catalog의 반대 Java 의존/순환을 만들지 않는다.
- 공개 조건: ACTIVE 상품, 운영 숨김 아님, 활성 카테고리, OPEN·공개 매대, ACTIVE·SELLER 소유자. 목록/상세 모두 적용. 품절과 판매 준비(활성 SKU 없음)는 공개하되 구분 표시한다.
- q: 제목 부분 일치, trim/NFC, 최대80문자, 제어문자 거부, SQL 와일드카드 문자는 문자 그대로 검색. category UUID, store slug, minPrice/maxPrice 0..999999999, inStock true/false, page0..10000. 가격은 활성 옵션의 최저가이며 품절 옵션도 포함한다. 필터는 이 표시 가격을 기준으로 한다.
- sort=newest/price_asc/price_desc/name, 기본 newest. 정렬값은 허용목록, 동률은 상품UUID로 고정. 가격 없는 상품은 뒤. 페이지20개, hasMore; 목록/페이지 사이 변경에 대한 고정 snapshot은 보장하지 않는다.
- 상세는 활성 옵션의 가격·가용량(onHand-reserved), 매대 링크·설명·기존 이미지 제공 경로를 사용한다. 조회는 재고를 예약하지 않으며 구매 가능 확정이 아니다.
- 화면 URL이 검색 조건의 기준이다. 제출/필터 적용은 페이지0으로, 페이지 이동은 나머지 조건을 유지한다. 새로고침/뒤로 가기 복원. 이전 요청 취소와 세대 식별을 함께 사용해 늦은 응답·이전 상세가 새 상태를 덮지 않게 한다. 로딩/오류 중 이전 조건 결과를 표시하지 않는다.
- 홈의 하드코딩 샘플 상품은 실제 조회로 교체한다. 기존 매대 이름 연습 컴포넌트와 해당 입력/초기화/비저장 검사는 분리해 유지한다. 공개 매대는 본인 store 필터가 고정된 상품 목록으로 연결한다.
