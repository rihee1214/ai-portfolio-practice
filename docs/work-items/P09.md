E 이후 각 단계는 업무 결과 묶음의 최소 연결과 필수 경계 완성 → 제약 연결 확인 → 개발 전체 → 동일 소스 독립 전체 검토·검증 → 필요한 수정·재검증 → 인계 순서다. A가 원단위 식별·배송 사실 전달 경계를 먼저 확정하고, B가 그 경계 위에 수량 점유/보류 공개 계약을 제공한다. C에서 실제 취소 신청과 A 출고를 B 보류에 연결한다. A만으로 아직 없는 클레임 차단을 검증했다고 하지 않는다. C/D/E는 동일 payment 환불 포트의 명시적 DEMO 어댑터로 종단 검증하며 F의 실제 제공자 연결을 완료했다고 하지 않는다. G 전에도 단계별 API·DB·필요한 최소 UI 회귀 검증을 수행한다.

**향후 착수 조건:** 구현 요청을 별도로 받아야 한다. P08 전체 완료가 정식 선행 조건이다. 외부 차단이 지속되는 경우 사용자 요청이 P09 로컬·모의 선행 진행까지 허용하는지 확인하고, 승인된 범위·남은 실제 PG 차단을 기록한다. P08 내부의 E→F 예외를 P09에 자동 확대하지 않는다. 동일하게 F 실제 제공자 차단 중 G 로컬 통합 진행은 승인된 범위에서만 하며, 필수 로컬 실패를 우회하지 않는다.

## 확정 설계와 미확정 상세 정책

- Java·Spring JDBC·Flyway·PostgreSQL, React·TypeScript·Vite 및 기존 모듈 소유권을 유지한다. claim은 절차, order는 원 주문/확정 수량, fulfillment는 배송, payment는 금전 시도, inventory는 재고, promotion은 쿠폰을 소유한다. 타 모듈 테이블 직접 쓰기는 금지한다.
- 반품/교환 신청은 **대상 수량의 배송 완료부터 7일 미만**, 직접 확정은 배송 완료 수량만, 자동 확정은 **7일 이상**. 진행 중 클레임 수량은 보류, 확정 후 자동 신청은 종료하고 운영 문의로 안내한다. 분할 묶음마다 시간을 따로 계산한다.
- 미발송 하위주문 전체 취소는 원 청구 배송비도 반환한다. 부분 환불은 원 단위 실결제액, 남은 가격/무료 배송 기준 소급 변경 없음. 변심 회수비는 구매 당시 저장한 상품별 금액(기본3,000원·0원 허용)을 사용한다. 같은 원 배송의 반품 대상 누적최대와 후속 차액만 부과하고 서로 다른 원 배송은 합산한다. 판매자 책임 단위는 제외한다. 음수 환불을 만들지 않고 부족 회수비는 추가 비용 처리 상태로 남긴다. 정책 없는 기존 주문은 새 견적의 명시 동의를 받으며 현재 상품 정책을 소급 적용하지 않는다. [C 설계 §11~12](P09-C-design-review.md)에 사용자 확정 정책과 금융 경계를 기록했다.
- 반품 재고는 회수·검수 후 판매 가능한 수량만1회 입고한다. 동일 가격 SKU 교환만 지원하고 추가 배송비는 판매자 부담이다. 차액 교환은 반품·재주문 안내다.
- 최초 계획에서는 다음을 **기존 설계에 없는 상세 결정**으로 담당 단계의 설계 판단 게이트에 두었다: A 예외 상태 복귀와 운송장 형식/수정 가능 구간, B 수량 식별/클레임 보류 공개 계약과 잠금, C 회수비 분할 공제·추가 비용 상태 및 환불 완료 조정 경계, E 동일 가격 비교 기준·교환 예약 기한/연장/회수 지연 전환, F 재시도 횟수/기한/제공자 실제 계약. A/B는 각 완료 기록을 따르며 C1은 [C 설계 계약](P09-C-design-review.md)에서 확정되어 구현·검증 중이다. 미확정 후속 항목의 수치를 구현자가 임의 확정하지 않는다. Astra가 기존 설계 내 보완인지 판단하고 중요한 정책·경계 변경은 사용자 승인 후 문서화한다.

금액 fixture는 C 착수 전에 먼저 고정한다. 예: 원 단위 net `[10001,10000,10000]`, 배송비3,000원인 미발송 하위주문은 부분1개 환불10,001원, 나머지 전체 취소23,000원, 총33,001원. 변심 반품 net10,001원은 회수비3,000원 공제 시7,001원, 판매자 책임은10,001원. net2,000원 변심 반품은 환불0원·부족 회수비1,000원 상태이며 임의 추가 청구는 하지 않는다. 실제 주문 생성 경로가 만든 같은 스냅샷과 대조하고, 회수비 반복/분할 공제 정책은 C 설계 게이트에서 확정한다. 쿠폰 복구는 여러 부분 처리가 최종적으로 해당 하위주문 전체 완료가 되는 경우도 포함해 검증한다.

금액 전송은 P07/P08의 Java long/DB BIGINT checked 계산, HTTP 10진 문자열·프런트 BigInt 계약을 유지한다. 상품 net 합계와 배송비를 혼동하지 않는다: `단위 net 합=항목 net 합`, `하위 총액=항목 net 합+shippingBase-shippingDiscount`, `부모 총액=하위 총액 합`. 환불 성공액/예약액·회수비 공제·추가비용 잔액은 원 금액과 별도 열로 보존한다.

신규 Java 단위 검사는 `backend/src/test/java/com/example/marketplace/<모듈>/domain/*Test.java`, DB 검사는 기존 `dbtest/PostgresJdbcIT.java`, 프런트 단위는 **`frontend/tests/unit/**/*.test.tsx`**, 브라우저는 **`frontend/auth-e2e/*.spec.ts`**에 둔다. 현재 Vitest는 `.test.ts`를 수집하지 않는다. 구현 시 필수 목록 등록뿐 아니라 실제 수집 보고서의 정확한 파일·test 이름·파라미터가 모두 실행됐는지 확인한다. 미래 테스트 이름과 이번 문서 점검 결과를 혼합하지 않는다.

구현은 Sol High, 설계 분석·판단과 독립 검증은 Astra Medium을 기본으로 하며 기존 부모/세션·담당 구조를 유지한다. 현재 세션 모델 자동 전환이나 새 검토 수행을 주장하지 않는다. 실행 환경에서 지정할 수 없으면 역할·실제 모델·제약을 기록하고 기존 절차로 인계한다. 구현자의 자체 검토를 독립 검토로 표시하지 않는다.

1. 각 문서의 제약 ID에 실제 클래스/메서드·파라미터·fixture·기대 assertion을 연결한다. 아래 신규 검사 이름은 **예정**이며 미구현·미실행이다. 먼저 요구사항 실패를 재현하고 환경/setup 실패와 분리한다.
2. JUnit으로 상태/시간/금액, ArchUnit으로 실제 소스와 금지 의존 fixture, 새 격리 PostgreSQL로 FK·잠금·원자성·멱등성·중단 복구를 검사한다. Vitest로 화면 상태, Playwright로 실제 화면→API→DB를 검사한다. 모의 API 테스트를 실제 DB 증거로 합산하지 않는다.
3. 기존 `verification/required-tests.json`, `required-browser.json`, `required-frontend.json` 항목을 보존하고 새 필수 검사를 등록한다. 기존 Node 검사도 보존한다. 집중 검사는 빠른 피드백이며 완료 근거를 대신하지 않는다.
4. 개발과 독립 검토는 각각 새 경로에서 `./verify.ps1 -Offline -EvidenceDirectory .local-tools/p09-<단계>-<dev또는review>-<고유값>`를 실행한다. 선택 옵션·검사 축소·skip·시간 제한 확대 금지. 독립 검토는 동일 동결 소스로 별도 전체 실행한다.
5. 종료0, `result.json`의 status/preservation passed, 필수 이름 coverage·각 assertion·skip/flaky0, 입력 SHA 및 전후 소스 동일을 확인한다. 실패 시 원인·수정·새 실행을 연결하고 이전 결과를 덮어쓰지 않는다.
6. 기존 서버·DB·검증 DB·미디어·실패 증거를 보존한다. 새 DB·새 미디어·새 증거만 사용한다. 보존 검사가 과거 검증 DB 모든 행의 전수 동일성을 증명한다고 하지 않는다.
7. 제약별 결과·하네스 경로·HEAD/dirty·inputs SHA·검사 XML/JSON·새 DB/미디어·실패/차단·독립 검토자/실제 모델을 기록한다. 누락/실패/skip/미검증이면 해당 단계 완료·다음 진입을 보류한다. 캐시/의존성 누락도 NOT RUN 사유다.

독립 검토는 총 검사 수보다 다음 다섯 위험의 assertion을 우선 확인한다: 분할 수량 경계(A/B), 같은 원 단위의 취소/반품/교환 경합(B~E), 다중 판매자의 부모 결제 한도(C/F), 외부 성공 후 내부 실패(F), 인증 변경/잠금 대기/늦은 화면 응답(A~G). 각 단계 표에 담당 검사를 배치했다.
