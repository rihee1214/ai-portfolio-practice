# P09 배송과 거래 후속 처리 — 순차 작업 흐름

상태: **P09-A·B 로컬·모의 범위 완료 / C~G 미착수**. B는 기존 배송 완료부터7일 적용을 사용자 승인받아 구현했고, 동일 소스 개발2·지정 검토세션 독립 전체에서 Java488·브라우저118·프런트234·Node75·필수52묶음·보존을 각각 통과했다. [B 최종 작업·인계](P09-B.md)와 [독립 검토](P09-B-review.md)를 따른다. 전체 브라우저 예산240→260초 및 실제252.477/252.205초·과거 실패 보존을 명시한다. 실제 Toss·사용자 직접 확인 미검증, 커밋·배포·푸시·C 실행 없음.

후속 요청으로 Astra Medium의 문서 독립 검토·재검토를 수행했다. 지적·보완·실행 결과는 [계획 검토 기록](P09-plan-review.md)을 따른다. 아래 최초 작성 당시 미검증/실패 기록은 보존한다. 문서 검토와 미래 구현의 독립 검증은 별개이며 H01~06의 설계 게이트가 구현 전에 남는다.

후속 검토의 새 Offline 실행 `.local-tools/p09-independent-plan-harness-20261030-02`는 Java451·브라우저106·프런트216·Node75와 필수50묶음·보존 검사를 통과했다. 현재 P08 기반 소스의 회귀 결과이며 P09 예정 기능의 검증 통과가 아니다. 앞선 에뮬레이터 실패는 원인 미확정 이력으로 유지한다.
기준 소스: `e80fbc05b69ba93977039732bc1cb5f3da26dd0a` (작성 시작 시 작업 트리 깨끗함).
최초 요청은 단계별 작업 문서 작성만 허용했다. 후속 사용자 요청으로 P09-A 로컬·모의 구현을 착수했다. [A1 설계 검토](P09-A-design-review.md)를 적용하고 지정된 검토세션에서 독립 검토한다. 이 문장은 A 착수 당시 범위 기록이다. 이후 사용자 요청으로 B 구현과 기존 배송 완료 시각부터7일 정책이 승인되었다. 현재 실제 PG 차단을 유지하며 C~G·커밋·배포·푸시는 진행하지 않는다.

**향후 착수 조건:** 구현 요청을 별도로 받아야 한다. P08 전체 완료가 정식 선행 조건이다. 외부 차단이 지속되는 경우 사용자 요청이 P09 로컬·모의 선행 진행까지 허용하는지 확인하고, 승인된 범위·남은 실제 PG 차단을 기록한다. P08 내부의 E→F 예외를 P09에 자동 확대하지 않는다. 동일하게 F 실제 제공자 차단 중 G 로컬 통합 진행은 승인된 범위에서만 하며, 필수 로컬 실패를 우회하지 않는다.

## 확정 설계와 미확정 상세 정책

- Java·Spring JDBC·Flyway·PostgreSQL, React·TypeScript·Vite 및 기존 모듈 소유권을 유지한다. claim은 절차, order는 원 주문/확정 수량, fulfillment는 배송, payment는 금전 시도, inventory는 재고, promotion은 쿠폰을 소유한다. 타 모듈 테이블 직접 쓰기는 금지한다.
- 반품/교환 신청은 **대상 수량의 배송 완료부터 7일 미만**, 직접 확정은 배송 완료 수량만, 자동 확정은 **7일 이상**. 진행 중 클레임 수량은 보류, 확정 후 자동 신청은 종료하고 운영 문의로 안내한다. 분할 묶음마다 시간을 따로 계산한다.
- 미발송 하위주문 전체 취소는 원 청구 배송비도 반환한다. 부분 환불은 원 단위 실결제액, 남은 가격/무료 배송 기준 소급 변경 없음. 변심 회수비3,000원·판매자 책임0원. 음수 환불을 만들지 않고 부족 회수비는 추가 비용 처리 상태로 남긴다.
- 반품 재고는 회수·검수 후 판매 가능한 수량만1회 입고한다. 동일 가격 SKU 교환만 지원하고 추가 배송비는 판매자 부담이다. 차액 교환은 반품·재주문 안내다.
- 다음은 **기존 설계에 없는 상세 결정**이며 담당 단계의 설계 판단 게이트다: A 예외 상태 복귀와 운송장 형식/수정 가능 구간, B 수량 식별/클레임 보류 공개 계약과 잠금, C 회수비 분할 공제·추가 비용 상태 및 환불 완료 조정 경계, E 동일 가격 비교 기준·교환 예약 기한/연장/회수 지연 전환, F 재시도 횟수/기한/제공자 실제 계약. 구현자가 수치를 임의 확정하지 않는다. Astra가 기존 설계 내 보완인지 판단하고 중요한 정책·경계 변경은 사용자 승인 후 문서화한다.

금액 fixture는 C 착수 전에 먼저 고정한다. 예: 원 단위 net `[10001,10000,10000]`, 배송비3,000원인 미발송 하위주문은 부분1개 환불10,001원, 나머지 전체 취소23,000원, 총33,001원. 변심 반품 net10,001원은 회수비3,000원 공제 시7,001원, 판매자 책임은10,001원. net2,000원 변심 반품은 환불0원·부족 회수비1,000원 상태이며 임의 추가 청구는 하지 않는다. 실제 주문 생성 경로가 만든 같은 스냅샷과 대조하고, 회수비 반복/분할 공제 정책은 C 설계 게이트에서 확정한다. 쿠폰 복구는 여러 부분 처리가 최종적으로 해당 하위주문 전체 완료가 되는 경우도 포함해 검증한다.
