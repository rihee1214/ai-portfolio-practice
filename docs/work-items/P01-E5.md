# P01-E5 Actuator 관측·접근 정책

2026-10-24 / 상태: 구현·자동 검증 완료 / 독립 검토 대기

## 범위 결정

E5 세부 행이 없어 상위 P01-E의 남은 Actuator 관측/접근 정책을 구체화한다. 현재 인증·관리망은 미구현이므로 health 외 관리 endpoint는 기본 access=none, health만 read-only로 허용한다. HTTP 노출은 기존 health만 유지하고 JMX endpoint 노출은 전부 제외한다. 이는 Spring 설정 기본값이며 운영자가 다른 설정으로 덮어쓰는 것을 막는 인증 장치는 아니다.

기존 `/actuator/health`의 UP200/DOWN503·status 단독 응답·POST405·요청 ID를 유지한다. discovery·상세 정보·component·probes 비공개를 확인한다. liveness/readiness 그룹은 Kubernetes나 별도 probe 소비자가 없고 DB 장애를 liveness에 연결하면 불필요한 재시작을 유발할 수 있어 추가하지 않는다. 현 health는 앱의 모든 업무/DB 기능 정상 여부를 보증하지 않는다.

지표 수집 저장소·관리 UI·관리망·Spring Security·새 health 그룹·ArchUnit은 범위 밖이다. 특히 관리망/운영자 인증을 구현했다고 주장하지 않는다. React·health 처리 코드·DB 설정은 바꾸지 않는다.

## 계획과 검증

1. 실제 RANDOM_PORT HTTP와 JMX 활성 컨텍스트에서 비공개 계약을 검사한다. 테스트에서 web include=*를 넓혀도 access 기본 거부가 작동하는지 확인한다.
2. 미구현 실패 확인 후 최소 설정만 추가하고 DB 없는 전체 Java verify·기존 프록시 Node 검사를 실행한다.
3. 지정 검토 및 반영세션 독립 검토와 결과·제한 기록, 최종 로컬 커밋. 다음 단계/push는 금지한다.

기존 공유 체크아웃을 유지하며 이 문서에 범위·결정·결과를 기록한다. 기존 서버와 DB에 쓰기·초기화·재시작을 하지 않는다.

공식 근거: [Actuator endpoint 접근·노출](https://docs.spring.io/spring-boot/4.2/reference/actuator/endpoints.html), [JMX 노출 제외](https://docs.spring.io/spring-boot/reference/actuator/jmx.html). 온라인 문서 버전과 별도로 실제 프로젝트 Boot4.1.1에서 동작 검증한다.

## 구현과 결과

제품 변경은 application.properties에 기본 access=none, health access=read-only, JMX exposure exclude=* 세 설정을 추가한 것이다. HTTP health 노출·discovery/details/components/probes 설정은 기존 값을 유지했다. access는 endpoint 자체의 사용 가능 여부, exposure는 HTTP/JMX 경로에 노출할지 여부다. health 외 기능을 다시 열려면 별도의 인증·관리망 설계를 먼저 해야 한다.

| 검사 | 결과 |
| --- | --- |
| [미구현 RED](evidence/P01-E5-red.txt) | 새16개 중9개 예상 실패·7개 통과. web include=*에서 관리 endpoint 노출 및 health JMX 등록을 탐지 |
| [최종 Java verify](evidence/P01-E5-java-verified.txt) | 기존83+신규16=99개 통과, 실패/오류/skip0. Checkstyle·컴파일·패키징 성공 |
| 실제 HTTP | 별도 loopback RANDOM_PORT에서 관리 경로·상세 health·liveness/readiness404, health GET200/status만·HEAD200/빈 body·POST405/Allow 확인. 기존 회귀에서 DOWN503·요청 ID·API 오류 유지 |
| JMX | spring.jmx.enabled=true인 격리 컨텍스트에서도 전용 domain의 Actuator MBean0개. 원격 JMX 포트를 열지 않음 |
| [Node 회귀](evidence/P01-E5-node.txt) | 기존68개 통과, health/API 프록시·기타 관리 경로 차단·응답 처리 회귀. 실제 Java 연결을 사용하는 브라우저 검사는 아님 |

검사에서만 HTTP exposure를 *로 넓혔으며 제품 설정은 health만이다. heapdump는 최초 RED 초안의 HTTP 경로 목록에 포함되었지만 최종 검사는 해당 bean이 생성되지 않는지 확인한다. 회귀 시 큰 dump를 생성할 수 있는 요청을 실행하지 않도록 바꿨다. 임의 shutdown/쓰기 endpoint 호출은 없다.

## 발견·수정과 한계

[최초 전체 실행](evidence/P01-E5-java.txt)에서 신규16개는 통과했으나 기존 E4 설정14개가 실패했다. ApplicationContextRunner는 SpringApplication의 ApplicationConversionService를 자동 적용하지 않아 소문자 enum 설정 none을 해석하지 못했다. E4 테스트 초기화에 Boot 변환기를 명시해 실제 앱의 변환 규칙과 맞췄고 전체99개가 통과했다. 제품 설정을 테스트에 맞춰 바꾸거나 검사를 비활성화하지 않았다. Mockito 에이전트·의도된 health DOWN 경고는 실패가 아니다.

관리 endpoint 기본값을 거부하는 설정이며 외부 환경에서 access/노출 값을 덮어쓰는 것을 방지하지 않는다. 보안 인증·인가 구현은 아니며 프로덕션 방화벽/리버스 프록시/JMX 원격 접속은 미검증이다. JVM의 표준 platform MBean이나 임의 사용자 MBean 전체를 없애는 기능도 아니다.

새 health 그룹은 추가하지 않았다. 현재 공개 status는 일반 연결 상태 확인 용도이며 DB 없는 실행의 UP을 주문/DB 기능의 정상 보장으로 사용하지 않는다. DB 프로필 실제 접속·지표 저장·대시보드·브라우저/실기기 재검증은 범위 밖이다. 사용자 직접 실습·이해는 미확인이다.

## 보존·실행·학습

[보존 확인](evidence/P01-E5-preservation.json)에서 dev/test 정규화 pg_dump 해시는 E4와 동일하다. 원문은 저장하지 않고 restrict/unrestrict 무작위 토큰을 제외해 계산했다. 컨테이너 ID·healthy·DB 포트 PID57168도 유지했다. 기존8080/4174/5174 리스너는 없으며 임의 기동/종료하지 않았다. 테스트는 자신이 만든 서버만 사용한다. DB 쓰기·초기화·재시작 없음. 현재 차단 항목 없음.

프로젝트 JDK21을 JAVA_HOME, .local-tools/m2를 MAVEN_USER_HOME으로 실행 프로세스에만 지정하고 아래 명령을 실행한다.

```powershell
./backend/mvnw.cmd -f backend/pom.xml "-Dmarketplace.build.directory=$PWD/.local-tools/e5-build" verify
./frontend/npm.ps1 test
```

흐름은 HTTP 요청 → Actuator 노출·접근 설정 → health status → 기존 요청 ID 응답이다. 이번에는 React 코드나 업무 API 필터를 수정하지 않았다. 작은 실습은 ActuatorPolicyHttpTest의 경로 목록에 `/actuator/scheduledtasks`를 추가하여404 검증을 실행하는 것이다. 실제 관리 endpoint를 열거나 DB를 변경하지 않아도 공개 범위를 이해할 수 있다.

ArchUnit 등 다음 단계와 push는 진행하지 않는다. E5 완료는 P01-E 전체 완료를 뜻하지 않는다.
