## 설계와 범위

목표: 조회 세션+현재 비밀번호로 변경/복구 코드 재발급, 주문번호+등록전화+복구 코드+새 전화 재인증을 통한 비밀번호 재설정. 전화 인증 하나만으로 과거 주문에 접근하지 않는다. 코드 분실 시 자동 우회 복구 없이 가상 지원 절차 안내만 제공한다. P06-E 묶음 연결, 실제 주문/결제, 실제SMS, 커밋/배포/푸시는 제외한다.

기존 guest 모듈/identity.api.PasswordHashes/phone.api.PhoneVerifications와 React·Spring JDBC를 유지한다. 복구 인증은 구매 인증과 다른 테이블/API/서버 purpose RECOVERY에 바인딩한다. 주문 생성은 기존 테스트 fixture에 한정해 최초 코드 발급을 검증하고 내부 최초 발급 계약을 P08 호출자에게 제공한다.

구현 결정: 복구 코드는 SecureRandom32바이트 URL-safe43자, DB SHA256만 저장, 최초발급/변경/재설정/명시적 재발급 응답에서만1회 표시. 코드 자체는 사용/교체 전까지 유지하며 자동 만료를 두지 않는다. 세션+현재 비밀번호를 다시 확인해야 재발급한다. 복구 코드 재발급은 진행 중 재설정 권한도 무효화한다.

인증 시도3분, 재발송 번호별60초·15분3회, 주문/출처별15분5/20회 시작 제한(실패 포함). OTP 교환은 최대5실패, 제공자 호출은 거래 밖. 인증 후32바이트 무작위 재설정 권한5분을 발급하고 DB해시/브라우저/구매자/비밀번호버전/복구코드해시에 연결한다. 재설정은 해시 연산 전후 권한을 검사하고1회 소비, 비밀번호·version증가·코드회전·전체조회세션폐기를 한 거래로 커밋한다. 동일 코드의 여러 인증시도는 허용하되 최초 재설정만 성공하고 나머지는 버전/코드 검사로 거부한다.

민감 입력/새 코드/권한은 메모리에만 유지, 원문 로그/URL/storage 금지, no-store·CSRF. 조회 세션은 재설정 권한으로 자동 발급하지 않으며 새 비밀번호 로그인 필요. 응답유실 후 재설정권한 재사용은 거부하고 새 비밀번호로그인 후 코드재발급으로 복구한다. 비밀번호를 모르면 자동 우회하지 않는다.
