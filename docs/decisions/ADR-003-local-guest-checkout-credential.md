# ADR-003 로컬 구매 세션 자격과 실패 복구

2026-10-25, P06-B. 로컬 단일 프로세스에만 적용한다.

## 배경과 선택

기존 HttpOnly/SameSite Spring Session 쿠키가 브라우저를 식별한다. 최초 구현은 구매 자격 난수를 HttpSession 속성에 저장했지만, DB 생성과 세션 속성 저장 사이에 다른 요청이 끼면 늦은 응답이 폐기된 자격을 저장할 수 있다는 독립 검토 R-B02가 있었다.

프로세스별 SecureRandom 256비트 키와 HMAC-SHA256(sessionId)로 서버 전용 자격을 유도한다. 자격은 클라이언트나 세션 속성에 내보내지 않고 DB에 SHA-256 해시만 저장한다. 서비스도 현재 키에서 유도한 자격과 일치하는지 확인한다. 같은 쿠키의 요청은 같은 자격을 사용한다. DB browser advisory lock과 checkout row lock 안에서 생성/reset 및 시도 연결을 바꾸므로 HTTP 응답 순서가 자격 선택에 영향을 주지 않는다.

reset은 같은 checkout 행의 current_attempt와 인증 상태를 초기화한다. 과거 attempt 행과 consumed_at은 유지한다. 실제 주문 소유권·주문과 소비의 원자성은 P08-C에서 별도 설계/검증한다. 이 reset을 주문 소유권 이전 수단으로 사용할 수 없다.

## 대안과 영향

HttpSession 속성 저장은 요청 사이 원자성을 보장하지 않아 채택하지 않았다. 별도 쿠키도 응답 도착 순서 문제가 남고 추가 자격 보관이 필요하다. 프로세스 키 영속화/공유는 현재의 로컬 제공자 메모리 상태와 맞지 않으며 이번 범위에 도입하지 않는다.

재시작·다른 인스턴스·세션 ID 변경에서 구매 인증을 재개하지 않는다. 새로운 인증이 필요하다. 실제 운영/다중 인스턴스 인증 보장이 아니며 실제 SMS를 사용하지 않는다. 기본 설정에서는 제공자가 비활성이고 명시적인 local-test/127.0.0.1 설정만 허용한다.

## 외부 호출과 복구

발급·코드 교환·증명 확인은 짧은 DB 상태 전이 사이에 호출한다. 외부 호출 중 DB 트랜잭션을 유지하지 않는다. 마지막 저장 전에 현재 시도·번호·용도·만료를 다시 검사한다. 외부 성공 후 DB 실패나 교환 응답 유실은 자동 재전송 대신 새 시도로 복구한다. 확인 저장 후 응답만 유실되면 현재 상태 조회로 복구하며 증명 재사용은 거절한다. 업무 만료는 요청 시점부터 3분이다.

## 검증

검사와 실행 결과는 [P06-B 작업 기록](../work-items/P06-B.md) 및 [독립 검토](../work-items/P06-B-review.md)에 연결한다. 동일 쿠키 동시 생성, SENT/VERIFIED 새로고침, 키 교체 거부/복구, DB 실패와 rollback, 늦은 제공자 결과, 실제 확인 응답 유실을 각각 자동 검사한다. 문서 작성 자체를 검증 통과로 보지 않는다.
