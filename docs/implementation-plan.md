# 단계별 구현·검증 계획

설계 v4 Java·Spring Boot + React / 2026-10-23 / P01-B1 Actuator 교체·B2·B3 검증 완료, B4 R4 수정·회귀 검증 완료, B5 완료

[요구사항](requirements.md)과 [전체 기술 설계](shop-design.md)의 현재 기준은 v4다. F01~F18과 AC01~AC20은 유지하고 React 학습 목표 G10을 추가했다. P01~P14의 기능 순서는 유지하며 Java·Spring Boot API와 React 화면에 맞춰 결과물·검증 도구를 변경했다. P01-A 문서 개정 완료를 현재 구성의 환경 검증 완료로 해석하지 않는다.

## 1. 작업 단위와 진행 규칙

한 요청은 `P08-C`처럼 작은 작업 하나를 기본으로 한다. 각 작업에서 기존 문서·코드 확인 → 세부 계약 작성 → 구현 → 검증 → 결과·진행 상태 기록 순서로 진행한다.

같은 표의 작업은 위에서 아래로 수행한다. 다른 의존 관계가 있으면 행에 명시한다. 선행 작업이 없어도 테스트 데이터로 독립 검증할 수 있는 부분은 진행 가능하지만, 실제 연동 전에는 전체 기능 완료로 표시하지 않는다.

각 작업의 완료에는 변경 파일, 필요한 DB 변경, 실행 방법, 검증 명령·결과, 남은 제한, 다음 작업 기록이 포함된다. API와 DB만 만든 경우 화면까지 완료했다고 표시하지 않는다. 더 작게 나눌 필요가 있으면 작업 ID 아래 하위 작업을 기록한다.

현재 [P01-B1](work-items/P01-B1.md)의 최소 API·Wrapper·빌드·HTTP 검증을 완료했다. [P01-B2](work-items/P01-B2.md)의 첫 화면과 [P01-B3](work-items/P01-B3.md)의 라우팅·공통 레이아웃·역할별 화면 틀도 검증했다. P01-B4는 health 연동과 기존 검토 수정을 반영했지만, [추가 UI·timeout 검증](work-items/P01-B4-review.md)에서 발견한 부분 응답 종료 결함 R4를 수정하고 개발·preview에서 재검증했다. P01-B5는 설정·빌드·Git을 검증하고 지정 세션 검토 반영·로컬 이력 기록을 완료했다. B1~B5가 있는 P01-B처럼 상위 작업은 하위 작업이 모두 검증되어야 완료다. P02-A도 A1~A3로 나누며 작업 중 새 개념·변경 파일이 많아지면 더 작게 나눈다. 자동 검사와 사용자 직접 확인 결과는 별도로 남긴다.

화면이 포함된 기능은 React 화면 → HTTP 계약 → Java 애플리케이션 서비스 → SQL → 화면 결과까지 연결한다. API만 검증한 상태와 실제 브라우저에서 연결한 상태를 구분한다. 로딩·빈 결과·오류·권한 거부·중복 클릭 중 해당 기능에 필요한 상태도 함께 설계한다.

## 3. P01 실행 환경과 프로젝트

현재: [P01-B1](work-items/P01-B1.md)의 프로젝트 전용 JDK·Maven 준비, 최소 API 구현·패키징·HTTP 검증을 완료했다. 기술 선택은 ADR-001, 조사 이력은 P01-A2를 따른다. P01-B2의 React 첫 화면과 P01-B3의 경로·역할별 화면 틀을 검증했다. P01-B4 health 연동의 R4 결함을 수정하고 자동 검사 68개와 개발·preview HTTP·UI 회귀를 확인했다. DB·인증·업무 API 연동은 미구현이다.

2026-10-21 사용자가 개발·테스트용 PostgreSQL을 Docker Compose로 구성하기로 확정했다. PC에 DB 서버를 직접 설치하지 않으며, 환경 재현·애플리케이션과 DB의 독립 실행·3계층의 통신 경계 학습을 목적으로 한다. [ADR-002](decisions/ADR-002-docker-postgresql.md)의 구성 원칙과 한계를 따른다. Docker 접근 문제는 P01-C1에서 먼저 확인하고 직접 설치로 자동 대체하지 않는다. 이번 변경은 문서상 결정이며 P01-C1은 미착수다.

Java 21·Spring Boot 4.1·Maven 3.9·PostgreSQL 18, React 19·TypeScript·Vite·React Router·Node 24 LTS를 설계 목표로 삼는다. 목표 패치·주요 지원 조건·조사 당시 다운로드 실패는 P01-A2에 기록했다. B1·B2·B3에서 도입한 의존성과 실행 결과는 각 작업 기록을 따르며, DB·인증 등을 포함한 전체 조합은 미검증이다. Node.js·npm은 React 개발·검증·빌드에 필요하며 업무 API는 Java에서 실행한다. 과거 Next.js·Prisma 설치 목표를 현재 구성에 적용하지 않는다.

2026-10-21 Actuator 교체 전 P01-B1 재검증은 기존 API·Wrapper를 유지한 채 공식 체크섬, clean verify, 재시작을 포함한 HTTP 8건을 확인했다. 이후 Actuator 교체 검증은 HTTP 27건이다. 제한된 실행 환경의 DNS·로컬 통신 실패와 허용된 실행 환경의 성공을 [B1 기록](work-items/P01-B1.md)에 구분했다. B4 구현은 진행하지 않았다.

각 작업에는 기존 Java·Spring·SQL 경험과 연결한 새 개념, 핵심 파일의 흐름, 직접 해 볼 작은 수정과 예상 결과를 제공한다. [학습을 포함한 진행 방식](development-workflow.md)을 적용하며 Boot·웹·인증까지 이미 능숙하다고 가정하지 않는다.

P01-A~B의 다운로드·저장 위치는 [P01-A2 10절](work-items/P01-A2.md#10-docker-방침-반영과-현재-준비-기준)을 따른다. JDK·Maven·Node는 기존 호스트 도구 경로를 유지하고 PostgreSQL만 이미지 저장소·태그·digest와 데이터 볼륨으로 구분한다. B4의 상태 API 연동에는 DB 준비가 선행 조건이 아니다.

2026-10-21 기본 health 도입을 E에서 B1으로 앞당겼다. `/api/status`는 제거됐고 B4는 `/actuator/health`의 status를 해석한다. 프런트는 `Accept: application/json`을 보내며, 한국어 안내를 직접 구성한다. health 전용 응답과 이후 업무 API의 오류 계약을 구분한다. B4의 개발 프록시는 전체 `/actuator`를 열지 않으며, 공개 배포의 관리 경로 정책은 P12에서 정한다.

공개 요청이 있을 때 준비된 배포안을 사용한다. 이 계획 작성 자체가 유료 자원 생성이나 실제 판매 전환의 실행 요청은 아니다. 공개가 아직 안 됐다면 로컬 데모 완료와 공개 완료를 구분한다.

완료 지점은 F01~F18의 기능과 AC01~AC18의 증거다. PG 검증 등 미확인 항목이 남아 있으면 “전체 검증 완료”로 표시하지 않는다.

## 17. 단계별 공통 검사와 상태

아래는 Windows에서 사용할 실행 계약이다. 현재 Wrapper와 npm의 개발·타입·린트·빌드·미리보기 명령은 존재하며 B1~B4에서 실행했다. B4의 `npm test`는 Node 기반 응답·취소·프록시 검사를 실행한다. DB 통합 프로필·JUnit·React DOM 단위/E2E 체계는 아직 없다. 도입 시 실제 동작을 확인하고 README에 기록한다. 기본 Java 검사나 React 모의 API 검사를 실제 DB·브라우저 연동 검사로 계산하지 않는다.

| 실행 위치 | 검사 | 사용 시점 |
| --- | --- | --- |
| `backend/` | `.\mvnw.cmd verify` | Java 컴파일·단위/웹 검사·도입된 코드 규칙/ArchUnit·패키징 |
| `backend/` | `.\mvnw.cmd test` | 금액·상태·권한 등 빠른 JUnit 검사 |
| `backend/` | `.\mvnw.cmd -Pdb-it verify` | Failsafe의 DB 통합 검사. PostgreSQL·Flyway·트랜잭션·작업 처리 변경 |
| `backend/` | `.\verify-api.ps1` | 빌드된 JAR의 health 200·UP / 503·DOWN / 복구·status 단일 필드·기존 경로 제거·관리 경로 비노출, HTTP 27건 |
| `frontend/` | `npm ci` | lockfile 기준 설치 재현. 설치만으로 검증 완료가 되지 않음 |
| `frontend/` | `npm run lint`, `npm run typecheck`, `npm run build` | React·TypeScript 코드 규칙·타입·정적 빌드 |
| `frontend/` | `npm run test:unit` | Vitest·React Testing Library를 대기 없이 1회 실행. 입력·상태·오류 처리 |
| `frontend/` | `npm run test:e2e` | Playwright Test·TypeScript. 실제 React·Java·필요한 테스트 DB·브라우저 준비 |
| 해당 검사 위치 | 계약 검사 | Java 모듈·제공자/서비스, React와 API의 입출력·실패 계약 |
| 실험 문서의 위치 | 부하·장애 시나리오 | P13~P14, 성능·복구 관련 변경 |

단위 검사는 구현을 그대로 복사하지 않고 경계값과 불변식을 확인한다. 테스트가 성공했다면 변경·실패·새 우려가 없는 범위의 반복 검사는 추가하지 않는다.

P01-D에서 Java의 `*Test`·`*IT`와 Surefire/Failsafe 실행 범위, React의 단위 검사와 브라우저 검사 범위를 각각 확정한다. 테스트 0건이나 DB·브라우저 준비 실패를 통과로 보고하지 않는다. P12에서 필요한 검사를 모두 실행하며 실행 위치·명령·검사 건수·성공/실패·환경을 기록한다.

작업 상태는 `미착수 → 설계 중 → 구현 중 → 검증 중 → 완료`로 관리한다. 외부 조건을 기다리는 작업은 `대기: 사유`를 적고 실제 완료 단계로 넘기지 않는다. 각 작은 작업의 상태는 착수 시 생성하는 작업 기록에 남기며, 위 단계 표는 그 기록의 집계다.

## 18. P01-B1 요청 예시 (완료된 작업의 참고용)
