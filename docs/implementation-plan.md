## 1. 작업 단위와 진행 규칙

한 요청의 범위는 사용자가 지정한 단계·기능을 따른다. 내부 작업은 업무 결과·assertion·전달 계약으로 묶고, 진행·검토·최종 완료 순서는 [개발 흐름](development-workflow.md)을 따른다.

같은 표의 작업은 위에서 아래로 수행한다. 다른 의존 관계가 있으면 행에 명시한다. 선행 작업이 없어도 테스트 데이터로 독립 검증할 수 있는 부분은 진행 가능하지만, 실제 연동 전에는 전체 기능 완료로 표시하지 않는다.

각 작업의 완료에는 변경 파일, 필요한 DB 변경, 실행 방법, 검증 명령·결과, 남은 제한, 다음 작업 기록이 포함된다. API와 DB만 만든 경우 화면까지 완료했다고 표시하지 않는다. 독립적인 실패·완료 조건 때문에 나눌 필요가 있으면 같은 작업 문서에 업무 묶음과 의존 관계를 기록한다.

현재 [P01-B1](work-items/P01-B1.md)의 최소 API·Wrapper·빌드·HTTP 검증을 완료했다. [P01-B2](work-items/P01-B2.md)의 첫 화면과 [P01-B3](work-items/P01-B3.md)의 라우팅·공통 레이아웃·역할별 화면 틀도 검증했다. P01-B4는 health 연동과 기존 검토 수정을 반영했지만, [추가 UI·timeout 검증](work-items/P01-B4-review.md)에서 발견한 부분 응답 종료 결함 R4를 수정하고 개발·preview에서 재검증했다. P01-B5는 설정·빌드·Git을 검증하고 지정 세션 검토 반영·로컬 이력 기록을 완료했다. B1~B5가 있는 P01-B처럼 상위 작업은 하위 작업이 모두 검증되어야 완료다. P02-A의 A1~A3 분할은 당시 이력이다. 후속 작업은 개념·파일 개수가 아니라 업무 결과와 독립적인 실패·완료 조건을 기준으로 묶는다. 자동 검사와 사용자 직접 확인 결과는 별도로 남긴다.

화면이 포함된 기능은 React 화면 → HTTP 계약 → Java 애플리케이션 서비스 → SQL → 화면 결과까지 연결한다. API만 검증한 상태와 실제 브라우저에서 연결한 상태를 구분한다. 로딩·빈 결과·오류·권한 거부·중복 클릭 중 해당 기능에 필요한 상태도 함께 설계한다.

Java 21·Spring Boot 4.1·Maven 3.9·PostgreSQL 18, React 19·TypeScript·Vite·React Router·Node 24 LTS를 설계 목표로 삼는다. 목표 패치·주요 지원 조건·조사 당시 다운로드 실패는 P01-A2에 기록했다. 2026-10-21 Actuator 교체 전 P01-B1 재검증은 기존 API·Wrapper를 유지한 채 공식 체크섬, clean verify, 재시작을 포함한 HTTP 8건을 확인했다. 이후 Actuator 교체 검증은 HTTP 27건이다. 제한된 실행 환경의 DNS·로컬 통신 실패와 허용된 실행 환경의 성공을 [B1 기록](work-items/P01-B1.md)에 구분했다. 당시 B1 재검증에서는 B4 구현을 진행하지 않았다.

## 17. 단계별 공통 검사와 상태

아래는 Windows에서 사용할 실행 계약이다. 현재 Wrapper와 npm의 개발·타입·린트·빌드·미리보기 명령은 존재하며 B1~B4에서 실행했다. B4의 `npm test`는 Node 기반 응답·취소·프록시 검사를 실행한다. D1에서 JUnit·Boot Test·MockMvc를 도입했다. D2에서 db-it/Failsafe 통합 검사를 도입했다. React DOM 단위 검사는 D3, 실제 브라우저 검사는 D4에서 도입했다. 기본 Java 검사나 React 모의 API 검사를 실제 DB·브라우저 연동 검사로 계산하지 않는다.

| 실행 위치 | 검사 | 사용 시점 |
| --- | --- | --- |
| `backend/` | `.\mvnw.cmd verify` | Java 컴파일·단위/웹 검사·도입된 코드 규칙/ArchUnit·패키징 |
| `backend/` | `.\mvnw.cmd test` | 현재 DB 없는 순수·MockMvc·임시 HTTP·설정·ArchUnit 포함129개. 순수 검사만 실행하려면 -Dtest로 선택 |
| `backend/` | `.\mvnw.cmd -Pdb-it verify` | Failsafe의 DB 통합 검사. PostgreSQL·Flyway·트랜잭션·작업 처리 변경 |
| `backend/` | `.\verify-api.ps1` | 빌드된 JAR의 health 200·UP / 503·DOWN / 복구·status 단일 필드·기존 경로 제거·관리 경로 비노출, HTTP 27건 |

단위 검사는 구현을 그대로 복사하지 않고 경계값과 불변식을 확인한다. 테스트가 성공했다면 변경·실패·새 우려가 없는 범위의 반복 검사는 추가하지 않는다.

P01-D에서 Java의 `*Test`·`*IT`와 Surefire/Failsafe 실행 범위, React의 단위 검사와 브라우저 검사 범위를 각각 확정한다. 테스트 0건이나 DB·브라우저 준비 실패를 통과로 보고하지 않는다. P12에서 필요한 검사를 모두 실행하며 실행 위치·명령·검사 건수·성공/실패·환경을 기록한다.

작업 상태는 `미착수 → 설계 중 → 구현 중 → 검증 중 → 완료`로 관리한다. 외부 조건을 기다리는 작업은 `대기: 사유`를 적고 실제 완료 단계로 넘기지 않는다. 각 단계의 업무 결과 묶음·전체 완료표 상태는 착수 시 기존 작업 기록에 통합하고 없을 때만 생성한다. 위 단계 표는 그 기록의 집계이며 내부 구성요소마다 별도 인계·검토를 요구하지 않는다.
