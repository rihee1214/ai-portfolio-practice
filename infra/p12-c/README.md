# P12-C local package

`compose.yaml` is a reviewed package candidate, not a deployment command. It has no published API, worker or database port. Prepare a new project, synthetic database, writable media directory for UID 10001, TLS certificate, individual reviewer htpasswd file, and rendered configuration before use. `PACKAGE_APP_IMAGE` must be one immutable image ID/digest for both Java roles. Build it once with the supplied Dockerfile and the verified JAR named `marketplace.jar`.

Start the API alone first so Flyway completes, then start the worker with the same artifact. Public mode is explicitly `public-demo`; production is refused by the application. Actual publication, migration orchestration, backup, restore and rollback remain P12-D work. Never run `down -v` against existing projects.

The harness uses a new PostgreSQL database and media path, production JAR child processes, and an owned loopback TLS NGINX container using this exact configuration. It retains stopped containers, logs, artifacts and failure evidence. Its self-signed two-day localhost certificate and random invitation password are test resources; they are not public hosting credentials. NGINX receives no database or media mount. Application cookies and CSRF remain independent of the invitation gate. API alone owns the exclusive media lock, writes and scheduled cleanup; worker has media disabled and no media mount. Both roles retain common scheduling and the worker's dashboard schedule. The database bootstrap administrator password is separate from the unprivileged application role created by `../postgres/init-app.sh`.

The compatibility check copies the preserved P12-B full1 bundle into its new evidence directory and serves that copy through a second TLS proxy to the current API. Its recorded historical development build mode is retained; this is previous-client compatibility evidence, not a new public production build. Clean environments without the preserved bundle lack this compatibility input and must report that check as unverified.

Template replacements are `__HOST__` (approved exact hostname), `__UPSTREAM__` (internal API authority), and `__PORT__` (external HTTPS port). Render those only from trusted operator inputs. The proxy strips inbound forwarding and authorization headers, never retries upstream writes, preserves API status/body/cookies, and never exposes the media volume directly.
